# 实现流水线（Implementation Pipeline）

> 与设计树对应：**设计树**澄清「做什么/为什么」——顶层是一组具体 **OKR**（O=可验证全局目标，第二层 KR=演绎/归纳支撑，所有 KR 达成 ⟹ O 达成；每层递归满足 MECE + OKR 充分性），grilling **动态逐层下钻**（每层「调研消解→批量追问→充分性自检→达标 descend」），叶子层落到四维度（代码实现/文件结构/工具调用/环境配置）。**实现流水线**定义「怎么做/怎么验收」。两者联动：**O 对应 job 级目标；KR 链逐层下传——叶子层 KR 映射为 task 的 # 关键结果**，四维度映射 # 写域（文件结构）/# 测试方法（自测指引）；实现流水线的分层 DAG 是设计树 OKR 推导的执行投影（每层门禁验证该层 KR 的联合达成）。本 skill 定义实现流水线的结构契约，plan / easy / doing 共用。

---

## 结构契约

实现流水线 = **分层 DAG + 层门禁**：

```
层 N（递进依赖：层内全部通过门禁才能进层 N+1）
 ├─ task A（写域独立）──┐
 ├─ task B（写域独立）──┼─ 并行执行（层内写域互斥）
 └─ task C（写域独立）──┘
 门禁：gate{N}.py（human 设计的确定性程序，exit 0 = 层验收通过）
```

三要素：

1. **分层 DAG（并行优先）**：只有**真实依赖**（数据/接口契约前置）才分层；**并行优先**——无真实依赖的 task 必须放同一层，同层内尽量多拆写域独立 task 最大化 DAG 并行度（警惕假依赖：顺手依赖/时序偏好，能写域隔离就不要串行）。Kahn 分层：无 pending 依赖的 task 进第 1 层，其余按依赖收敛；层内是**写域独立**的可并行 task
2. **写域（# 写域）**：每个 task 声明允许创建/修改的路径清单——目录以 `/` 结尾（前缀语义），精确文件写全名。**同层多 task 必须全员声明写域且两两不相交**（相等 / 目录前缀包含 = 冲突）；互相独立的 task 若必然改同一文件，补一条依赖使其分层
3. **层门禁（检查逻辑 + 确定性代码双产物）**：每层产出 `gate{N}.md`（**检查逻辑说明**：逐条断言的检查对象/判定标准/依赖前提——human 确认的对象）+ `gate{N}.py`（确定性实现，exit 0 = 层验收通过；携带该层模块的**集成测试** + 业务级验收，唯一的持久化测试资产）。**human 确认的是检查逻辑**（断言合理/覆盖层验收/可达成），逻辑定稿后写代码——不是让人审代码。**自洽性**：断言间不得矛盾、不得有永远红门禁（依赖不存在的产物/超层范围/条件恒假）——「该层 task 全部完成且符合关键结果」必然使门禁转绿。task 级不生成专门测试脚本（worker 按 # 测试方法 自测，过程性验证）

## 产物落盘

```
plan/
  task{N}.md          ← 含 # 写域 节
  gates/gate{N}.md    ← 层门禁检查逻辑（human 确认的对象）
  gates/gate{N}.py    ← 层门禁确定性实现（逻辑定稿后写）
  pipeline.md         ← 流水线定义（每层：task 列表 + 写域 + 门禁路径 + 验收标准摘要）
```

## doing 阶段执行（每层 4 步）

1. **门禁判别力验证**：跑 `gate{N}.py` 应为**红**（exit != 0）——本层模块集成测试此刻必然失败，这是门禁有判别力的证明（TDD 思想用于门禁本身；一开始就绿 = 门禁无效或层已完成，停下来查）
2. **并行 impl-worker**：`runs.all` 派发（写域 = task 声明，互斥；不碰 git；按 task 的 # 测试方法 **自测**——过程性验证，自测代码可写在写域内随交付或跑通即弃，不落盘共享测试目录）
3. **层门禁提交**：parent 调 `level_complete`（gate_cmd 必填，跑 gate{N}.py 模块集成测试）→ 绿 → hook 单次 commit + tasks.json 批量 success
4. **debug 压缩传递**：该层 debug 摘要压缩为共享上下文注入下层 worker（前层教训，避免重复踩坑）；最后一层完成后归档 debug-summary.md

## gate 编写注意（实测踩坑）

- gate{N}.py 定位仓库根/源码目录时，**从 `plan/gates/` 到仓库根是 5 层上溯**（gates→plan→job_N→jobs→.rick→根）——job_35 验收两次踩中（4 层误写导致 No module named / 测试未落盘误报）。稳妥写法：从 gate 文件位置用 `os.path.abspath(os.path.join(os.path.dirname(__file__), "..", "..", "..", "..", ".."))` 并在门禁开头自检（`assert os.path.isdir(...)`）
- 门禁判别力验证（步骤 ①）就是为了在编码前抓住这类 gate 自身 bug

## 关键原则

- **门禁是层验收唯一标准**，agent 不得修改 gate{N}.py 及其集成测试；**测试资产只有一层**（模块集成测试，human 确认），task 自测是过程行为
- **worker 不碰 git**——提交权集中在层检查点（level_complete，确定性）
- **loop 与流水线正交**：worker 按匹配的项目 loop（学习到的工作方法）执行；parent 是结对导航员（读行为轨迹全局监督纠偏，不在执行层）
- 执行前 parent 先调 `pipeline_gate` 工具做结构校验（分层 + 写域互斥 + gate 存在性，确定性 hook）——⛔ 才派发
