# skill:research（尽调树+信源加权方法论）

当需要尽调事实、澄清事实模糊性到极限时使用。research 是 SENSE 方法论中 S1/E1/E2/N/S-R 的事实调研工具化体现。

---

## 触发场景

- sense_loop 派发 S1/E1/E2/N/S-R 步骤的事实调研部分时
- think 选出最高风险假设后,若为事实性,由 research 调研
- 任何需要"澄清事实模糊性"的调研场景

---

## 核心数据结构:尽调树

尽调树 = 根节点(主题)+ 若干层 MECE 划分。每个节点要么是叶节点(已尽调),要么有子节点(已下钻)。

### MECE 划分原则

每层子节点必须:
- **完备**:覆盖父节点全部关注面(不遗漏)
- **互斥**:子节点之间不重叠(不重复)
- **可验证**:每个子节点是可被信源验证的事实陈述

划分维度由模型自行判断(结构/流程/产物等),不限定规则。

### 下钻触发

节点置信度 < 高 **且** subagent 报告含"疑问点" → 按 MECE 把疑问点划为子节点加入树。无疑问点但置信度低 → R7 上报,不再下钻。

### 示例(帮助理解意图,非穷举规则)

主题:human-loop 命令实现

```
根:human-loop 命令实现
├─ 入口与参数处理(结构维度)
│  ├─ 命令注册 ✅0.9
│  ├─ 参数解析 ✅0.8
│  └─ 配置加载(下钻,疑问:加载顺序?)
│     ├─ 默认配置 ✅0.9
│     ├─ 用户配置覆盖 ✅0.85
│     └─ 环境变量(R7,无法验证)
├─ prompt 生成(流程维度)✅0.9
└─ 产物落盘(产物维度)✅0.8
```

同父节点的子节点可用不同维度划分,由模型基于语义自行选择。

### 节点状态

| 状态 | 含义 | 置信度 |
|---|---|---|
| 待调研 | 初始/已派发 | N/A |
| 已澄清 | 事实明确 | ≥ 0.8 |
| 部分澄清 | 置信度中 | 0.5-0.8 |
| 无法澄清 | 置信度低,无疑问点 | < 0.5(R7) |
| 已下钻 | 拆分为子节点 | 看子节点 |

### 树规模约束

深度 ≤ 5 | 每层子节点 ≤ 7 | 总节点 ≤ 30(超过则强制 R7 上报剩余)

---

## 信源加权

置信度 = Σ(信源验证结果 × 信源权重),验证结果 ∈ {0, 1}

| 信源 | 默认权重 | 验证方式 |
|---|---|---|
| 代码原文 | 0.4 | Read/Grep 直接读取 |
| 运行时行为 | 0.3 | Bash 跑命令/测试/日志 |
| 文档 | 0.2 | WebFetch/Read 官方文档/规范 |
| 反事实 | 0.1 | 修改代码看影响后还原 |

阈值:高 ≥ 0.8(终止)| 中 0.5-0.8(续研)| 低 < 0.5(R7 上报)

权重可在 `.rick/config.json` 的 `human_loop.research_source_weights` 覆盖,和应 = 1.0。

---

## 关键原则

- 不直接执行调研动作,派发 subagent 实现上下文隔离
- subagent 报告必须落盘(供 learning 复盘)
- 置信度计算只在主 research(避免 subagent 私调权重)
- 修改代码必须 `git restore` 还原
- 不替 human 决策 R7 上报项
- 不替 think 评估价值性假设

---

## 与其他 subagent 的协作

- **think**:think 选出最高风险假设后,若为事实性,research 接手调研
- **sense_loop**:research 输出尽调树简报,由 sense_loop 呈现 human 决策
- **subagent**(research 内部派发):执行单节点的具体调研动作,返回信源验证结果+疑问点

---

## 使用模式

```
[Step 0] 绘制根节点 → MECE 划分第一层 → 创建主报告
[Step 1] 配置信源权重 + 加权公式
[Step 2] LOOP:选叶节点 → 派 subagent → 计算置信度 → 下钻判定 → 更新树
[Step 3] 整合 subagent 报告 → 输出尽调树简报 + R7 上报项
```
