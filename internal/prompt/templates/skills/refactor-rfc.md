# skill:refactor-rfc（死代码与重构调查 RFC）

以软件工程架构简洁性为第一目标，深度扫描源码，将发现的死代码、重复逻辑、冗余抽象等问题整理为一份 RFC 报告。**只调查，不修改源码。**

---

## 触发场景

在 dream 阶段周期性运行：随着功能迭代，源码积累了不再被使用的代码路径、重复实现的逻辑或过度设计的抽象，需要定期识别并记录，为后续重构提供依据。

---

## 执行 SOP

### 1. 全量源码扫描

使用 Read / Grep / Glob 扫描 `internal/`、`cmd/`、`pkg/` 全部 `.go` 文件，重点识别：

**死代码**
- 函数/方法被定义但未被任何其他代码调用（Grep 函数名，确认无调用方）
- 导出的类型/常量/变量只在定义处出现
- 被注释掉但未删除的大段代码块

**重复逻辑**
- 两处或以上完成相同功能的函数（参数、逻辑高度相似）
- 同一错误处理模式散布在多个文件
- 相似的数据转换逻辑未抽象为公共函数

**冗余抽象**
- 只有一个实现的 interface（接口无扩展价值）
- 只被一处调用的 helper 函数（内联成本极低）
- 只包装一行代码的 wrapper 函数

**过度耦合**
- 模块间循环依赖
- 一个文件同时承担多个不相关职责
- 配置、逻辑、IO 未分层

### 2. 优先级排序

以"删除成本低、架构收益高"为排序原则：

| 优先级 | 判断依据 |
|--------|----------|
| P0 | 死代码：删除无任何风险，测试仍通过 |
| P1 | 重复逻辑：合并后减少维护点 |
| P2 | 冗余抽象：简化后提升可读性 |
| P3 | 过度耦合：解耦后降低变更影响面 |

### 3. 确定 RFC 序号

扫描 `.rick/draft/RFC/RFC-refactor-*.md`，提取所有已有数字序号，取最大值 +1；若无则从 1 开始。

### 4. 创建 RFC 文件

在 `.rick/draft/RFC/RFC-refactor-{n}.md` 写入以下结构：

```markdown
# RFC-refactor-{n}: 代码简洁性重构建议

## 背景

{1-2 句说明本次扫描范围和目标}

## 发现的问题

### 死代码
| 文件 | 函数/类型 | 说明 |
|------|-----------|------|

### 重复逻辑
| 文件A | 文件B | 重复内容 |
|-------|-------|----------|

### 冗余抽象
| 文件 | 标识符 | 冗余原因 |
|------|--------|----------|

### 过度耦合
| 模块 | 问题描述 |
|------|----------|

## 优先级建议（Top 5）

1. **P0** `file:line` — {简述改动内容及理由}
2. ...

## 影响评估

{每项改动的预估影响范围，说明是否有测试覆盖}
```

## 约束

⚠️ **允许**：Read、Grep、Glob 查阅任意源码；写入 `.rick/draft/RFC/RFC-refactor-{n}.md`（仅此一个文件）
⚠️ **禁止**：修改任何源代码或其他 `.rick/` 文件
