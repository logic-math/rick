# skill:super-debugging（超级调试框架）

## 铁律

```
没有根因调查，不得提出任何修复方案。
症状修复是失败。随机修改是制造新 bug。
```

**声明触发**：遇到任何非预期行为，必须先声明：
> "I will use skill:super-debugging."

声明后，严格按照以下五个阶段顺序执行，**不得跳过任何阶段**。

---

## Phase 1 — S：还原问题（Subject）

用 SENSE 的 S 阶段将问题结构化：

```
现状是___（实际观察到的行为）
期望是___（应该发生的行为）
差距是___（两者之间的具体偏差）
```

同时收集所有可用证据，**不猜**：

1. **完整读取错误信息** — 不跳过报错和警告，读完整个堆栈
2. **稳定复现** — 能稳定触发吗？偶发就继续收集数据，不猜
3. **检查最近变更** — `git diff`、最近提交、新依赖、配置变更
4. **多组件系统：先埋点收集证据**
   - 在每个组件边界记录入参和出参
   - 先跑一次收集数据 → 定位哪一层失败 → 再深入那一层

**阶段产出**：精确的问题描述
> "当用 Y 调用 X 时，期望得到 Z，但实际得到 W"

---

## Phase 2 — E：视角分析（pErspective）

用 SENSE 的 E 阶段形成可验证的根因假设：

1. **逆向追踪数据流** — 坏值从哪来？谁传入了坏值？沿调用链向上追，直到源头
2. **找类似的可用代码** — 在同一代码库中找到正常运行的类似实现，完整阅读，一行不跳
3. **列出所有差异** — 正常代码与出错代码之间的**所有**差异，不管多小
4. **提出 2-3 个候选根因** — 每个假设必须可证伪，按可能性排序

用融贯性检验每个候选假设：
- **自洽**：内部逻辑一致，无矛盾
- **他洽**：与已观察到的所有现象一致
- **续洽**：能预测：如果是这个根因，修复后现象应该消失

**阶段产出**：
> "我最可能的假设是 [X]，理由是 [证据]。验证方法：[最小改动]"

---

## Phase 3 — N：验证假设（judgmeNt）

每次只验证**一个**假设，做**最小改动**：

1. 明确说出假设：**"我认为 X 是根因，因为 Y"**
2. 添加有针对性的日志或写最小复现用例验证
3. 判断结果：
   - ✅ 假设成立 → 进入 Phase 4
   - ❌ 假设不成立 → **不叠加修复**，回到 Phase 2 用新信息形成新假设

**阶段产出**：附证据的确认根因
> "bug 是 [X]，证明是 [观察到的现象]"

---

## Phase 4 — 修复实现

1. **先写失败测试**（结合 skill:tdd），再写修复代码
2. 实现**单一修复** — 只解决已确认的根因，不顺手重构
3. 验证：
   - 复现用例通过？
   - 其他现有测试仍然通过？
4. 清理调试阶段添加的日志和临时代码

**提交信息格式**：
> "fix: [什么出了问题] — [如何修复的]"

---

## Phase 5 — 3 次失败 → 停止，找人类协作者

**触发条件**（满足任一）：
- 同一问题修复已失败 ≥ 3 次
- 每次修复都在不同地方暴露新问题
- 修复需要"大规模重构"才能落地

**此时的正确行为：停止一切修复尝试。**

向人类协作者提出：
- 当前的问题描述（现状/期望/差距）
- 已尝试的方案和失败原因
- 两个问题供人类决策：
  1. 这个设计模式本身是否合理？
  2. 继续修复症状，还是重构架构？

---

## 反模式（遇到立即停止）

| 反模式 | 正确做法 |
|--------|----------|
| 没形成假设就随机修改代码 | Phase 1 先还原问题，Phase 2 再假设 |
| 叠加修复：第一个没用直接加第二个 | 一次一个假设，验证失败则回 Phase 2 |
| 修复症状（捕获异常/加 if）而不是根因 | 追踪到根因再修复 |
| "先试一下看有没有用" | 先声明假设，再验证 |
| "再试一次"（已失败 2 次以上） | 已失败 3 次 → Phase 5，找人类 |
| 跳过测试，手动验证就行 | 必须先写失败测试（TDD） |

---

## 支撑技术

**逆向追踪**：从症状出发沿调用链向上追踪，直到找到坏值起源。

**多层防御**（找到根因后，在数据流经过的每一层都加验证）：
- Layer 1 入口点：拒绝无效输入
- Layer 2 业务逻辑：确保数据对当前操作有意义
- Layer 3 环境守卫：防止危险操作在特定上下文执行

**条件等待替代 sleep**（防止 flaky test）：
```go
// ❌ 猜时间
time.Sleep(300 * time.Millisecond)

// ✅ 等条件
waitFor(func() bool { return getResult() != nil }, "result to appear")
```
