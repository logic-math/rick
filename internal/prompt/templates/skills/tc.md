# skill:tc（测试用例设计）

编写测试用例时使用，确保测试覆盖完整且无歧义。

## 测试用例四要素

每个测试用例必须包含以下四个要素：

### 1. 前置条件
测试运行前系统所处的状态：
- 数据库/缓存中必须存在哪些数据？
- 必须设置哪些环境变量或配置项？
- 哪些前置操作必须已完成？
- 示例："用户账户存在，状态=active，余额=100"

### 2. 输入参数
传入被测系统的确切输入：
- 所有函数参数必须有具体值（不能用"某个值"）
- 边界情况：空字符串、nil、0、负数、最大整数
- 应触发错误处理的非法输入
- 示例：`userID=42, amount=-5, currency="CNY"`

### 3. 操作序列
按顺序执行的步骤：
1. 建立前置条件
2. 用输入参数调用函数/接口
3. 观察返回结果
4. 验证副作用（数据库状态变化、发出的事件等）

### 4. 预期输出
可观测的确切结果：
- 返回值（含具体类型和值）
- 存储中的状态变化
- 抛出的错误或异常（含消息/错误码）
- 发出的事件或日志
- 示例："返回 error{code: INSUFFICIENT_FUNDS}，余额不变"

## 常见反模式
- 前置条件模糊："某个用户存在" → 应指定所有字段具体值
- 预期输出模糊："应该正常工作"或"返回某些内容" → 应给出确切值
- 缺少副作用验证：写操作后必须检查数据库状态
