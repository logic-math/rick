# values.md — 待裁决价值清单（loop_11）

## 待裁决 — OneTrans-V2 论文 — 2026-10-12

- [V1] 原文/出处：论文主张「保留 cascade（cascade-preserving）而非端到端生成（OneRec 路线）」，理由是「移除候选特征会显著降低推荐质量」（论文 §1 / Figure 1，等级 A）。
  为什么是价值判断：断言了「应当保留级联、不应替换为端到端生成」这一架构取向/取舍，是设计偏好，无法由事实唯一推出（OneRec/端到端路线同样有生产成功案例）。
  human 裁决：是的接受，我认可论文所说，移除候选确实会当值推荐质量下降

- [V2] 原文/出处：业务目标经「业务偏移 β·φ(z)」做「软偏好而非规则」的调控，而非硬性强制决策值（论文 §4.2.1 / Table 5，等级 A）。
  为什么是价值判断：断言「软调节优于硬强制」是一种目标权衡/治理偏好，无法由事实必然推出（Table 5 显示硬强制在 CTR/AOV 单项上也有正收益）。
  human 裁决：接受，目前看软调解是收益的，且逻辑上更有扩展性

- [V3] 原文/出处：「多模态 embedding 应如何进入排序模型不是固定设计，而是容量的函数；某一规模下的既有实践未必在下一规模仍最优」（论文 §7.8，等级 A）。
  为什么是价值判断：含「应当/未必」式的规范性结论，主张设计随规模演进的取舍，属方法论取向而非事实。
  human 裁决：我认可，这一说法，符合具体问题具体分析的哲学观。但是什么是容量函数，我不太了解，后续可以解释清楚

- [V4] 原文/出处：「我们相信 OneTrans-V2 为从『每阶段一个模型』向『统一单模型推荐架构』的更广泛转型提供了生产级基础」（论文 §8 Conclusion，等级 A）。
  为什么是价值判断：对未来技术方向的愿景/信念声明，非可验证事实。
  human 裁决：接受值得

- [V5] 原文/出处：论文以「人均 GMV」为主要业务收益口径（+9.74%），同时报告 CTR/订单量/AOV 间存在反向权衡（论文 §6.3 / Table 5、6，等级 A）。
  为什么是价值判断：隐含「GMV 优先于点击率/订单量/AOV」的目标排序，业务指标优先级是价值选择，落地美团时应以何指标为主需 human 判断。
  human 裁决：接受

- [V6] 原文/出处：论文主张「业务目标对应决策空间的一个区域，而非独立召回通道；决策是模型预测的结果，而非用户显式选择」——即把召回目标内化为模型内部预测的决策分布、由线上偏移调控，而非外部路由规则或每目标一个独立通道（论文 §4.2.1，等级 A）。
  为什么是价值判断：断言「业务目标应当内化为模型内决策预测 + 线上偏移，而非外部规则/独立通道」是一种架构治理取向，与「独立通道 / 规则路由」路线构成取舍，无法由事实唯一推出（独立通道在工业界同样是成熟做法）。
  human 裁决：接受

## 待裁决 — OneTrans-V2 复现/部署/端到端全流程（模块九）— 2026-10-12

- [V7] 原文/出处：论文明确「虽然 OneTrans-V2 是作为一个 Transformer 联合训练的，serving 仍遵循原 召回→粗排→精排 级联，每个阶段只执行自己的候选侧计算」，即把「统一」限定在参数与训练层、共享上下文，而不延伸到服务拓扑（论文 §5.1，等级 A）。
  为什么是价值判断：断言「统一模型不必统一服务阶段」是架构/部署取向的取舍，与「单次前向出全量结果」的端到端路线（OneRec 式）构成互斥选择，无法由事实唯一推出。
  human 裁决：接受

- [V8] 原文/出处：论文把系统级优化（kernel 融合、FP8、两段式 top-k、FlashAttention 风格 mask kernel）与建模收益并列，作为其 3.2× QPS 与 2.16×/27.6× 加速的来源（论文 §5.2 / §7.9，等级 A）。
  为什么是价值判断：把「编译器/系统级优化」视为与建模收益同等、值得同等工程投入的收益来源，是资源分配取向而非事实（同样的工程人力也可投在特征或数据上）。
  human 裁决：接受

- [V9] 原文/出处：为换吞吐做精度取舍——serving 默认 FP16（推荐侧浮点特征需保值域与精度），并把占 TransBlock 约 2/3 FLOPs 的 SwiGLU GEMM 下推到 FP8（论文 §5.2，等级 A）。
  为什么是价值判断：「精度 vs 吞吐」的取舍与可接受误差阈值属业务风险偏好，论文只自述 backbone 更耐受，未评估对浮点特征丰富场景的影响，无法由事实推出「应当这么做」。
  human 裁决：接受

- [V10] 原文/出处：论文将可复现边界划在「机制可复现」——完整给出 §4.1–4.4 与 §5 的机制与公式，但层数/宽度/专家数/序列长度/beam 宽一概不给，规模只用 L/S/XS 与 GFLOPs 表述（论文 §5、§6.1，等级 A）。
  为什么是价值判断：「什么叫可复现、公开到什么粒度」是发表与开源的治理标准（工业闭源惯例），主张「给机制即算可复现、规模可自选」是标准设定而非事实，直接决定我们在美团该照抄还是自行定标。
  human 裁决：接受
