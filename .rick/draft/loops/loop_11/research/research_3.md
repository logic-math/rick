# research_3 — OneTrans-V2 复现 / 部署 / 端到端全流程（模块九）— 2026-10-12

元信息：时间基准 2026-10-12（CST）。本轮自主直读论文全文（curl arxiv.org/html/2609.28589v1）§4.1–4.4、§5.1–5.2、§6.1、§7.6/7.8/7.9 = A 级主源。外部源（TIGER / HSTU / OneRec / MTGR 各自一手论文）仅用于「行业通用」层。每条显式标注 **[论文已给]** / **[行业通用]** / **[只能推断]**。

## 事实性结论

**层① 论文已给（可复现到架构级）**

1. **token 序列组织**：行为 token 𝒮 在最前、因果自注意力、全序列共享一套 Q/K/V+FFN 参数；每个 exposure/阶段的 stage token 追加其后、用各自专属 Q/K/V+FFN（混合参数化）；召回紧接 𝒮 的追加序列依次为 CTX（NS_r 压成的 context token）→ DT^p（并行决策）→ DT^d（依赖决策）→ SID_0..2。mask：stage token 只能看「请求时间戳锚点 a_e 之前的行为前缀」+自身+同阶段同 exposure 更早 token；跨阶段/跨 exposure 互屏蔽；**行为 token 永不看 stage token**（故 user context 一次编码、三阶段共读）。来源 §4.1 + Fig.2(c) + Eq.1（A，[论文已给]）

2. **两阶段 token 预算差异**：粗排把 NS_p ⊂ NS_f 压成**单个候选 token**（每候选预算最紧）；精排保留 NS_f 的**多 token**（弃之会掉排序保真度）。来源 §4.2.2（A，[论文已给]）

3. **backbone 规模线索**：正文只给符号——块数 N、宽度 d、专家数、序列长度均为符号。**给到的数**：L=662 GFLOPs/请求、S=239、原三模型级联合计 275；**S = small（轻量版，239≈L 的 36%）**、L = large（默认）、另有 XS = extra small（比 L 训练便宜 46×）；SID 三层每层码本 8192；决策前缀 4 维占 **2 个 token 位**。训练：BF16、per-GPU batch 2048、16 GPU、λ_r=0.1/其余 λ=1、τ=0.5、EMA 0.9999、稀疏侧 AdaGrad lr=0.1、稠密侧 AdamW(β1=0, β2=0.99999, ε=1e-5, wd=0.01)。来源 §6.1 + §7.8（A，[论文已给]）

4. **DCGR 推断 = beam search + 三步解码**：① 枚举决策的**全部合法组合**，在缓存 ℋ=(𝒮,CTX) 上**一次前向**打出 log P(z|ℋ)；② 每个前缀分加 βφ(z)；③ **一条 beam search（宽 k）同时扩展前缀与 SID 码**，按 Eq.4 联合打分，返回 top-K 给粗排（前缀单独分高但引不出好物品者会被压过）。来源 §4.2.1 Eq.4 + Fig.3 + §5.2（A，[论文已给]）

5. **前缀折叠成单打分步的条件**：各决策维词表小（z_oc 3 值、z_ad 2 值、z_disc 与 z_aov 各「几个」），乘积「小到足以一次前向打完」，故把多个顺序步折叠为**单个打分步**，业务偏移就作用在此步。来源 §5.2（A，[论文已给]）

6. **Retrieval Decoding Optimization 第二项**：把「全部 beam–token 对的全局 top-k」换成**两段式 top-k**（先留每 beam 最好的 k 个扩展，再选全局 top-k）——结果集与原 top-k **完全一致**，每步候选池从「beam 宽 × 词表」降到「每 beam k」。来源 §5.2（A，[论文已给]）

7. **SID→物品取回语义**：多物品可共享同一 SID，**凡映射到被检索 SID 的物品全部返回**（⇒ 必有 SID→物品 映射结构；论文未写其实现，也未提 ANN/向量索引）。来源 §4.2.1（A，[论文已给]）

8. **SNT 的训练数据切分**：mini-batch 按**用户窗口**组织（一窗口 = 一用户一段时间内全部曝光）；序列每窗口只编码一次；每 exposure 保留 request 身份、时间戳、task 身份、阶段特征与标签，但**不带序列副本**；每 exposure 锚定 a_e 只读其前缀（causal view），同 request 共享锚点；序列 append-only ⇒ 旧前缀编码与锚点持续有效；窗口**按天切**（不跨评估日）。收益：训练 4.4×、序列特征存储 −95%、非序列特征存储减半；按周/月切可更高但留作未来工作。来源 §4.4 + §7.9（A，[论文已给]）

9. **请求相对 RoPE**：exposure 的 query 旋转 t_e、行为的 key 旋转 t_i，注意力项只依赖 (t_i − t_e)；同 exposure 内相对旋转抵消；**行为自注意力不变**；key 旋转只依赖自身时间戳 ⇒ **旋转后的 key 算一次可被所有请求与阶段复用**；多个固定时间周期覆盖长短期。来源 §4.4 Eq.11（A，[论文已给]）

10. **§5.1 部署管线（论文确有此节，前两轮事实版图遗漏）**：在线请求 → 𝒮_u 先过共享因果 Transformer 产出**可复用 user-context cache C_u** → 同一 C_u 供召回/粗排/精排消费（长序列每**请求**编码一次而非每阶段一次）；召回 = C_u + NS_r 做 DCGR 解码（偏移加前缀分 + beam search）；粗排/精排是对同一 C_u 的**非自回归候选打分**（各用 NS_p / NS_f）；候选集仍逐级收缩。来源 §5.1（A，[论文已给]）

11. **三阶段不在同一次前向内完成**：论文明确「虽然联合训练为一个 Transformer，**serving 仍遵循原 召回→粗排→精排 级联**，每阶段只执行自己的候选侧计算」。来源 §5.1（A，[论文已给]）

12. **KV cache 与 GQA**：共享行为序列的 KV cache 算一次后被三阶段 stage token 读，**召回时在 beam 间广播**；其大小同时决定每步 cross-attention 的显存与访存 ⇒ GQA 按组数等比缩小它且**质量基本不变**（§7.6）；只需 KV 头数与 head dim 在 stage token 与行为序列间一致，query 头数可不同。来源 §4.3 + §7.6（A，[论文已给]）

13. **kernel 融合**：stage token × 共享序列的注意力用 FlashAttention 风格 kernel，**自带 stage visibility mask、一次调用覆盖某用户全部候选**、不 padding 不物化注意力矩阵；QKVG 融成无 bias GEMM 且输出原地消费；QKNorm 用偏移寻址 RMSNorm kernel；SwiGLU 的 gate+up 合并为一个 GEMM；隐藏向量 16B 对齐以发射 128-bit 向量化 load。来源 §5.2（A，[论文已给]）

14. **精度取舍**：serving 默认 **FP16**（推荐侧浮点特征需保值域与精度），backbone 因 RMSNorm 激活有界而更耐受，把占 TransBlock 约 **2/3 FLOPs 的 SwiGLU GEMM 下推 FP8**；并有一个训练做不到的融合：gate-up+down+scaled residual 合成单 kernel（serving 无反向、不需中间激活）。来源 §5.2（A，[论文已给]）

15. **服务端加速数字**：两段式 top-k → 吞吐 **19.7×**、单请求 beam 搜索延迟 **2.3×**（改前该步占召回推理时间 **94%**）；前缀单步打分 → 延迟再降约 **30%**、累计解码加速 **27.6×**；精排相对已部署精排：无优化 0.58× → kernel fusion 1.66× → FP8 **2.16×**；三阶段共享 C_u 再叠 **1.53×**；合计端到端 **3.2× QPS**。批处理只描述为「装进在线延迟预算的最大 batch」，**无数值**。来源 §7.9（A，[论文已给]）

16. **端到端环节对照（刷新页面 → 产出推荐数据）**：论文**写了**的只有：请求到达后序列编码一次得 C_u、C_u 复用给三阶段、召回解码（偏移 + beam）、粗排/精排对候选非自回归打分、候选集逐级收缩、SID→物品取回。论文**完全没写**：请求接入/网关、特征拼接与特征快照服务、缓存命中策略（C_u 是否跨请求持久化）、batch/调度/限流、SID 索引结构、候选去重与多通道混排、后置规则/竞价、曝光日志落库与特征回写（§5.1 全文范围，A，[论文已给]）

**层② 行业通用（外部来源，不得当论文事实）**

17. **TIGER（NeurIPS 2023 / arXiv:2305.05065）**：RQ-VAE 语义 ID + 自回归解码，**生成式解码取代双塔 + ANN 近邻检索**；推断用**受限/前缀约束 beam search**（torch-rechub/cornac/NextRec 复现均如此）；SID 碰撞另加一层码消歧。（对该系统为 A、对「行业通用」为 B，[行业通用]）

18. **HSTU / M-FALCON（ICML 2024 / arXiv:2402.17152）**：target-aware 因果自回归下改注意力 mask（候选互不可见），把 m 个候选打分从 O(m·n²d) 降到 O(n²d)，再按 microbatch b_m 切；**encoder 级 KV caching 可在 microbatch 间与请求间复用**，命中缓存的前向只算最后 b_m 个 token；同预算服务 285× 更复杂模型、1.50–2.99× 加速。（A/B，[行业通用]）

19. **OneRec（arXiv:2506.13695）**：encoder-decoder + MoE（top-k 路由、无辅助损失负载均衡）；推断用 **beam search（优于 top-k/top-p 采样，因 SID 前缀树与 beam 的系统搜索契合）**，部署 Pass@K=**512**；serving 用 TensorRT + 自研插件（cross-attention、MoE）+ batching + MPS → 吞吐 5×、推断 MFU 28.8%；「每请求返回 k 条、未曝光者入 cache pool」承接高 QPS 降级流量。（A/B，[行业通用]）

20. **美团 MTGR（arXiv:2505.18654 / tech.meituan.com）**：训练按**用户窗口聚合候选**、推断按**请求聚合**，一次前向给一个请求的全部候选打分 ⇒ 推理成本随候选数**亚线性**；自研 mask 防泄漏；相对 DLRM 训练成本持平、**在线推理资源 −12%**。与论文 §4.4/§5.1 的共享上下文复用同构，是美团侧可直接对照的起点。（A，[行业通用]）

**层③ 只能推断（不得写成论文事实）**

21. **端到端工程拓扑整体属推断**：服务编排、特征服务与特征拼接、缓存层（跨请求 C_u 复用与失效）、多通道候选合并去重、后置规则与竞价、日志回流，论文全未写；任何「刷新页面 → 特征拼接 → 缓存命中 → 共享 context 编码 → 三阶段打分/生成 → 产出推荐数据」的逐步描述，除 §5.1 那几环外**均为按行业通用做法补齐的推断**。（[只能推断]）

22. **「三阶段合一」只到参数与训练层**：模型是一个（stage token 参数专属），但服务拓扑仍是三阶段顺序执行、共享 C_u；把「一次前向出全量结果」当论文事实是错的（见第 11 条）。（[只能推断] 的反面印证）

## Gaps

- 论文无服务编排/特征服务/日志回流细节 ⇒ 「刷新页面 → 产出推荐数据」完整链路在论文层面**不可还原**，只能以 §5.1 骨架为真、其余标推断。
- beam 宽 k 与 top-K 缺失 ⇒ 无法估召回量、解码延迟、SID 索引规模；「枚举 z 全部合法组合」的实际组合数也因 z_disc/z_aov 取值数「几个」而不可算。
- serving batch、延迟预算、硬件型号缺失 ⇒ 3.2× QPS 与各加速倍数不可折算为美团硬件上的预期。
- C_u 是否跨请求复用、特征拼接发生在何处、SID 索引如何实现——三项需下一轮专项（含美团侧架构事实）才能收敛。
- 行业通用做法（倒排/ANN、prefix-restricted beam、KV cache 跨请求复用、cache pool 降级）均为**外部**证据，与论文机制同构但非论文内容，教学与落地不得混述。
