# research_2 — OneTrans-V2 DCGR 决策前缀 + 业务偏移 β·φ(z) + 硬强制 — 2026-10-12

时间基准：2026-10-12（CST）。论文 = arXiv:2609.28589v1。本文只还原「软偏好 vs 硬强制」与「容量函数」的事实机制，不做价值判断。

## 事实性结论

**A. DCGR 四维决策前缀：模型自预测，非外部指定**

1. 四维构成：购买等级 z_oc（order count，无购买/一次/多次，3 值）、消费等级 z_aov（average order value，每单价值区间，取值「a few」个）、新颖等级 z_disc（discovery，候选类目相对用户近期行为的新颖度）、供给类型 z_ad（advertising，自然/广告，2 值）。——来源：论文 §4.2.1（A）

2. 前缀由模型预测：z_oc/z_disc/z_ad 三个并行维度各由一个轻量 decision head 从 CTX 位置隐态预测，三者 embedding 求和成一个并行决策 token DT^p；z_aov 依赖购买等级（先知道「买不买」价值区间才有意义），在 DT^p 之后预测为依赖 token DT^d；随后自回归生成三级 SID（SID_0,SID_1,SID_2）。——§4.2.1（A）

3. 训练/推断口径：训练时决策与 SID 在自回归顺序下用交叉熵、ground-truth 决策在对应位置 teacher forcing（标签直接读日志）；推断时枚举 z 的全部合法组合、在缓存的用户上下文上一次前向打分，把前缀折叠成单个打分步，业务偏移作用于此步。——§4.2.1 + Retrieval Decoding Optimization（A）

4. 与外部 task token 的区分：决策是模型从用户上下文预测的结果，不是外部传入；论文明确区别于 UniR2/UniSGR「外部指定的 task token」。——§4.2.1（A）；Pith 审评确认该区分（B）

**B. 业务偏移 β·φ(z) 精确机制**

5. 数学形式（Eq. 4）：打分 = log P(z|H) + β·φ(z)（steered decision prefix）+ Σ_{ℓ=0..2} log P(SID_ℓ|H,z,SID_<ℓ)。β·φ(z) 只加到决策前缀分数，不动 SID/物品项。——§4.2.1 Eq.4（A）

6. 符号含义：φ_j 给维度 j 的每个取值一个偏置分，φ(z)=Σ_j φ_j(z_j)（跨维度求和）；β 是单一标量，控制整个偏移强度。β 在线可调、无需重训练。——§4.2.1（A）

7. 它 = KL 正则化改进步：q(z) ∝ P(z|H)·e^{βφ(z)}，是 max_q E_q[φ(z)] − (1/β)·KL(q‖P(·|H)) 的解，即离线 RL 的 KL 正则化 improvement step（引 [26]，类比 Multi-Game Decision Transformer [19] 的单标量版本）。即：既含 KL 正则项，φ(z) 又扮演「业务价值/优势函数」角色，β 是其逆温度强度。——§4.2.1（A）

8. β 增减含义：β=0 恢复模型自身排序；β 越大越偏离模型自身排序、越偏业务目标；偏移只改变「哪个决策前缀胜出」，给定决策下的物品分布 P(Item|H,z) 不变（模型在该决策下仍返回它认为最可能的物品）。——§4.2.1（A）

**D. §7.8「设计是容量的函数」**

12. 「容量」=模型容量（总参数量/表示能力），非计算量（GFLOPs）非序列长度；稀疏 MoE 把总容量与激活算力、每 token 显存流量解耦。§7.8 例证：多模态 embedding 直接喂入（vs SimTier 直方图）「仅在容量充足时」才有利——即输入/架构设计随容量而变。——§4.3 + §7.8（A）

13. μP/Depth-μP 含义：width-μP 按 ×1/m_d 缩放初始化方差与学习率；Depth-μP 按 ×1/√m_N 缩放残差乘子与学习率——使加宽/加深时超参数自动迁移、无需重搜。——§4.3 scaling 规则表（A）
