# 第七课 · 是否真能拿到业务收益

## 承上：第六课差距表的最后一行，今天展开

第六课那张表最后两行是「起点与余量」和「收益口径」。前者你没量；后者我填了两边报的数——论文侧「人均 GMV +9.74%、同硬件预算端到端 QPS 3.2×（闭源自述，A，不可独立复现）」，美团侧「MTGR：离线 CTCVR GAUC +2.88pp、订单量 +1.22%、PV_CTR +1.31%、推理资源 −12%（B）」（research_1 · A #11 / B #12）。那一格打了 ✅，但它只回答了「两边报的是什么数」，没回答你真正要问的：**这些数能不能当成你在美团能拿到的预期。** 今天只追这一件。

（前六课的追问你都跳过、直接推进了；这一课的四个问不挂在论文上——挂在你自己那套数上，只有你能答。）

## 作者的处境：他面对的不是一个数，是一堆方向打架的数

先还原他被逼到哪个问题。论文 §6.3 摊出来的，若按列读，会是几个互相矛盾的故事（Table 5，同一模型召回阶段线上 A/B，相对「使用预测前缀」，仅统计 V2 召回名下曝光；research_2 · #10，**B 级转载**）：

- 强 β：CTR **−5.4%**、Orders −1.2%、AOV **+28.3%**、GMV +26.7%
- 中 β：CTR −0.9%、Orders **−3.0%**、AOV +13.9%、GMV +10.4%
- 强制 z_aov 最高档：CTR −8.1%、Orders **−33.5%**、AOV **+38.9%**、GMV −7.7%
- 强制 z_oc=0：CTR **+8.2%**、Orders −10.4%、AOV +5.8%、GMV −5.1%

同一批线上实验，说「这根旋钮有用」的人举 AOV，说「它有害」的人举 CTR——两边都不算说谎。这就是他必须先解决的组织性问题：**哪个数说话算数。**

（论文只给了数、没写动机。「他面对的是什么数据处境、因此被逼到哪个问题」是下面这段的重构，标注为读法，不作论文逐字用。）

他的处境里有个硬事实：这些指标是**反向权衡**、不是同向增减——CTR 与 AOV 在上面四行里没有一次同向（可逐行核对）；Orders 与 AOV 在强制档里 −33.5% / +38.9% 正面对冲。于是「挑一个单指标当主口径」这个动作，等于挑一个立场。他能走的只有另一条路：找一个**由这些反向量合成的量**。

GMV 正好是这样一个量——它由订单量与每单价值合成（这层是常识级口径定义，不引论文）；CTR 不是，点击是漏斗前置项，点了不等于买了。这是「为什么是 GMV」的第一层：它能同时吸收 Orders 与 AOV 两个反向的量，把同一批实验从「两个相反故事」收成「一个方向」。**反向权衡被内化进了口径本身，而不是被口径抹掉。**

第二层是「为什么是**人均**」。总量 GMV 同时被两件事推着走：模型变好了，和流量本身变多了。人均把流量规模这一项除掉，留下的才是一个用户身上模型贡献的那部分（这一层标为读法：论文报的是人均 GMV，未解释为何选人均）。同向的第三个数是「用户活跃天数 +0.25%」——它量的不是交易额，而是交易额有没有被**提前透支**（这条读法同样标注为读法，非论文动机）。

这三步合起来，就是 V5 你已裁决的那句「以人均 GMV 为主要业务收益口径」落地时的形态：**一个能收容反向权衡的合成量（GMV）+ 一次剥离流量规模的归一（人均）+ 一个旁证防透支（活跃天数）。**

## 为什么他同时给两张表：一个数要服务两种用途

到这里还没解释 26.7% 与 3.0% 的落差。要解释它，得先看他手里的第二个矛盾——**一个数字要同时干两件不同的事**：

- 一件是**调参**：β 该往哪边推、推多大？这需要在「模型管辖的那批流量」上量，否则信号被别的通道稀释，弹性看不出来。
- 一件是**结算**：整个盘子净增多少？这需要在「系统全体曝光」上量，否则看不见用户被挪来挪去的那部分。

这两件用途要求的切分不一样，一个口径满足不了。所以他没选一个——他并列给了两张表，各自标了统计范围（这层是我对他「为什么给两张表」的重构；论文给的是表，不是理由）。

## 同一批流量、两种切法，看到的两个数

| 切法 | 表 | 统计范围 | 相对谁 | 强偏移下的 GMV |

| 归因口径 | Table 5 | 仅 V2 召回**名下**曝光 | 相对「使用预测前缀」（=不偏移） | 弱 **+7.5%** / 中 **+10.4%** / 强 **+26.7%** |

（两行同出 research_2 · #10 / #11，均为 **B 级全文转载**：arxiv HTML/PDF 直读 DNS 失败，六行百分比在三个独立 B 级信源间交叉一致，但英文表头逐字未直读——是否采信这个 B 级转载是你的判断，research_2 · R7 已把它标为待你裁决。）

差额是怎么来的，用一句话说准：**一个记的是「谁接的」，一个记的是「一共接了多少」。** 同一个用户、同一段时间里的同一份需求，强 β 让 V2 通道更偏向高客单的决策前缀，于是——

- 在 V2 名下的账本里（Table 5），它接住的曝光 AOV 大涨（+28.3%），订单变少但那部分「没在这里成交」的损失**不记在这张账上**，所以它名下的 GMV 净涨 +26.7%；
- 在系统账本里（Table 6），被搬走的那部分需求如果本来会在别的通道成交，就是左手换右手——两张账合起来，净变化只剩 +3.0%。

所以差额不是「哪个数注水」，而是**曝光在通道之间的再分配产生的租值转移**：+26.7% 里有一大块是「从别处挪过来的」，只有 +3.0% 那个量级才是新增的。同一批流量，被两种方式切分，就长出两个都真实的数。

这里能看出为什么「曝光再分配」这件事本身不是缺陷而是调控力的度量：能被重新分配，说明模型真的接过了「该走哪个目标」的判断（V6 你已接受的那件事）。**大数字量的是这根旋钮的调控力，小数字量的是整个盘子的净增。** 两者缺一个都不完整：只有大的，你会把弹性当收益；只有小的，你会误判机制没用（毕竟 −0.6% → +3.0% 的方向是随偏移变过来的，不是随机的）。

## 还有第二层混淆：+26.7% 和 +9.74% 根本不在同一张账上

第六课表里那行「人均 GMV +9.74%」与今天的 +26.7%，很容易被并排放在一起读成「论文说能涨两成多」。它们其实是**两次不同的 A/B，相对的东西不同**：

- **+9.74%（人均 GMV）、+0.25%（活跃天数）、QPS 3.2×**：50/50 哈希分流，**OneTrans-V2 L 替换掉原来那三个模型**（research_1 · A #11，§6.3）——量的是「换架构」的效果。
- **+26.7% / +3.0%**：同一个模型内部，加不同强度的业务偏移 vs **不加偏移**（relative to「使用预测前缀」）（research_2 · #10/#11）——量的是「转旋钮」的效果。

两个基线、两个实验问题。**+26.7% 既不是「换架构」的收益，也不是「你落地后能拿到的数」，它是「同一批流量被旋钮推到某一端时，模型自己管辖范围内账面的变化」**；而 +9.74% 才是「换架构」的账——它的相对项是「你原来那三个模型」，对你而言是「你原来那套粗精融合 + MTGR」。基线一换，同一个机制能给出的数就完全不同——这正是第六课最后一格（起点与余量）要你量的东西。

## 顶层那三个在线数：能看什么、看不了什么

把 +9.74% / +0.25% / 3.2× 三个数逐个摆开，标清它们各自的证据等级与边界（来源 research_1 · A #11，等级随注；三数均为**闭源生产自述**）：

- **人均 GMV +9.74%**：能看的是方向与量级（对单个用户价值的提升）；看不了的是置信区间、显著性、分流方式与周期——材料里都没有（research_1 · R7/Gaps）；也不能独立复现（无代码/权重/数据，R7）。这正是预印本状态的分量：**未经同行评审、截至 2026-10-12 零引用**（research_1 · A #3）。
- **用户活跃天数 +0.25%**：方向为正、量级很小。能看的是「GMV 的涨法看起来不像透支留存」；看不了的是它在噪声里还是真的、以及「一致性透支」的形态（比如涨在几天、掉在几周）——材料未给任何显著性信息。
- **QPS 3.2×（同硬件预算下端到端）**：能看的是吞吐关系的方向；「同硬件预算」是这句话的限定词，不能拆掉读。它和第五课那个张力（662 vs 275 GFLOPs，算力约 2.4×）连在同一处：算力涨、吞吐也涨，**但把 3.2× 归因到哪一条机制，论文没有逐项拆解**（第五课已列四条候选解释，均为推断）。

再横向看一眼美团侧作对照：MTGR 是 **CIKM 2025 会议论文 + 官方技术博客**（B，research_1 · #12），报的是「离线 CTCVR GAUC +2.88pp、外卖首页订单量 +1.22%、PV_CTR +1.31%、在线推理资源 −12%」。两处不能直接比大小，原因也是口径本身：

- **报的指标不同**：一边是人均 GMV，一边是订单量 + CTR + 资源；GMV **包含**订单量的变化（GMV = 订单量 × AOV），拿一个大口径的增幅去比一个子项，不成立。
- **基数与场景不同**：外卖首页排序 vs 字节信息流/电商；美团外卖的客单结构、履约约束与「点击→下单」的漏斗形状都不同（论文未覆盖字节 vs 美团场景差异，research_1 · Gaps）。
- **但有一条可比**：MTGR 的「资源 −12%」与 OneTrans 的「QPS 3.2×」是同一类账（资源/吞吐），这一类账比 GMV 类账更容易在你自己的系统里复现——它不依赖业务口径的定义。

## 这一课带走三样

1. **一个数的三个坐标**（读任何收益数字时先问的三个问题，问题本身内化在上面几节里）：它在**谁的流量**上量的（归因 / 系统切分）？它**相对什么**（换架构的旧系统 / 不转旋钮的同模型）？它是**弹性**还是**净收益**？
2. **弹性与净收益的分层读法**：Table 5 那种归因口径的数读出「往哪推、推多大有多少反应」（诊断仪表）；Table 6 那种系统口径的数读出「整个盘子净增多少」（结算单）。**两个数同时读，才既不会把 +26.7% 当落地预期，也不会因为 +3.0% 就认为机制没用**——它们是同一批流量在两种切分下的两个投影，差额是租值转移，不是谁在撒谎。
3. **一个判定纪律**：外部数（论文、别人的博客、同行的口径）只能给你**方向与机制**，给不了你**幅度**——幅度必须在你自己的流量切分、你自己的基线上量。第六课差距表最后两格（起点与余量、收益口径）之所以是 ❓，就是这条纪律的具体落点。

## 美团要拿收益，必须先量的自己的数

这一节是这一课真正交给你的东西：论文的数给不了你幅度，能给你幅度的只有下面这几个数——**每一个都对应第六课差距表里一个 ❓ 格**（research_1 · Gaps/R7 已列「字节 vs 美团的召回通道数量、粗排特征集、业务目标组合未覆盖，需 human 提供美团侧事实」）：

1. **你们的主口径是哪一个、有没有「人均」这一层。** MTGR 报的是订单量 +1.22%（B，#12），不是人均 GMV。如果你们的主口径是总量，那么「流量涨了」和「模型变好了」这两件事在你们的数里是混在一起的——不先决定要不要归一，你连「值不值得投」都算不出。什么会让你改主口径？这个问题留给下面第 1 问。
2. **你们的基线长什么样。** 论文的 +9.74% 相对的是「三个独立模型」；你的相对项是「已有的粗精融合 + MTGR」（judgment 直觉 3；research_1 · B #12）。起点不同 → 余量不同 → 同一个机制给你的数必然更小或更大，但**方向不确定**（更小是因为余量被吃掉；更大是因为你们已有共享算力、再叠一层一致性可能更便宜）。这一格没量之前，「能不能拿到收益」是悬空的。
3. **跨通道 / 跨阶段的曝光重叠率。** 归因口径与系统口径的差，在字节是 −0.6%→+3.0% vs +7.5%→+26.7%（B 级）；在你们这里差多少，取决于同一批请求里有多少曝光是可被不同通道/阶段互相接住的。这个数小，分层读法就退化成单层（两种切分给出同一个数）；这个数大，双口径就不是可选项而是必需项。
4. **多目标调控现在的形态。** β 类是「在线可调、无需重训」的单标量旋钮（research_2 · #5–#8）。如果你们现在的目标是硬规则/固定配额，那你要拿到的第一份收益不是 GMV，而是「把某条硬规则换成连续可调」这件事本身带来的空间（第四课已讲过软/硬的机制差别，今天只标它的收益侧接口）。
5. **分流与观测的口径。** 论文是 50/50 哈希分流（A，#11），只给点估计。你们自己的 A/B 报不报置信区间、跑多长、怎么切分——决定了你能不能把「+0.25% 这种量级的数」判断成信号还是噪声。
6. **非交易指标有没有埋。** 论文用活跃天数 +0.25% 做旁证（A，#11）。你们如果没有这类指标，GMV 涨的时候你无法判断它是新增还是透支——这是「拿到收益」和「保住收益」的分界。

（这六项里没有一项能从论文里抄到答案，也没有一项是我替你想的——它们的答案都在你们自己的系统里。）

## 落点并列（判断权在你）

从「收益怎么算、算哪个口径」到你在美团的第一个动作，四条并立，代价各不同：

- **甲 · 以系统全口径为唯一准绳**：只认 Table 6 那一类数（净收益），归因口径的表弃用或只作内部参考。最保守、最不容易被高估；代价是失去「旋钮该往哪推」的诊断信息——按 V2 你已接受的软调节路线，β 的调参依据正是归因口径给的那种弹性。
- **乙 · 双口径分层读**：归因口径读出弹性（该往哪调），系统口径读出净收益（净拿多少）；汇报时明确标出每个数属于哪一种。信息最完整；代价是要求你们的埋点与报表体系同时支撑两种切分（即上面第 3 项那个重叠率必须量出来）。
- **丙 · 先只量、不改口径**：不动现有报表，先把第 2、3 两项（基线、重叠率）量出来，再决定要不要引入第二种切分。最轻；代价是这一轮拿不到任何可汇报的收益数字，只拿到「该不该动」的判断依据。
- **丁 · 从资源账切入**：先不碰 GMV 这类业务口径，先复现「资源/吞吐」这一类账（MTGR 的 −12%、OneTrans 的 3.2× 都属此类，B/A）。这类账口径最少歧义、最容易在你自己的系统里量；代价是它证明的是「效率」不是「业务收益」，拿资源时说服力弱一档。

四条不互斥，差别只在「先立哪个口径、先量哪一项」。哪条先走，是你的判断。

## 追问（把你的判断逼出来，不是考你）

1. 你们现在向上汇报模型收益，用的是哪个数——总量 GMV、人均 GMV、订单量、还是别的？如果它恰好是总量而不是人均，你打算在哪一层把「流量规模」这一项剥出来（分品类、分城市、分用户群）？出现什么现象（比如总量与人均在某周方向相反）会让你改主口径——或者反过来，让你坚持总量？

2. 第 3 项那个「跨通道/跨阶段曝光重叠率」，你会用什么代理量来量（同一次请求被多个阶段打分的比例？被不同召回通道同时命中的比例？）？如果量出来两种口径的差在你们体系里接近于零，你会怎么改判——是认为分层读法没必要、还是认为「可被重新分配的曝光太少」这件事本身推翻了某条路线的收益前提（第六课甲乙丙丁里的哪一条）？

3. 外部数（论文的 +9.74%、MTGR 的 +1.22%）要拿来当立项依据，你会先要求补上哪一项（置信区间、分流方式与周期、绝对值基数）？如果只能拿到点估计和很短的观测周期，你会把它当方向性证据用，还是干脆不用、只用自己的 A/B？什么会让你从「先引用外部数开路」改成「先跑自己的小流量实验」？

4. 反过来：若你在美团做出来后，系统全口径只拿到个位数——比 Table 5 那些大数字小一个量级（Table 6 那类数的量级，B 级、是否采信待你判）——你会怎么归因：机制没搬对 / 场景不同（外卖到店的决策维度与字节信息流、电商不同）/ 起点不同（你们已有粗精融合 + MTGR，余量更小）？哪一种归因出现时，你会从「继续投」改成「停手」——而哪一种会让你反而加注，因为小数字证明了「净增为真」？
