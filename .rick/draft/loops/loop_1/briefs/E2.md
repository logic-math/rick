## E2 简报 — Perspective 视角选择

### 5 视角表

| 代号 | 视角名称 | 核心命题 | 与 human-loop 的映射 |
|------|----------|----------|----------------------|
| A | 决策论 | 在不确定条件下，基于预期效用最大化做出选择 | think agent 的"失败概率"判断标准 |
| B | 认识论 | 知识的来源、边界与证成；区分事实与价值 | research agent 的事实性假设澄清 |

| E | 架构论 | 系统各组件的角色、边界与协作关系 | 四 agent 架构 + 三层复核 + sense 调度 |

### 5 处事实层面无法区分的地方

5 视角在以下 5 处事实层面均成立且互相兼容，无法仅凭事实层面区分优劣：

1. **主视角作为整体框架的承载**：5 视角均可作为整体框架承载，事实层面均不矛盾。
2. **与现有四 agent 架构的兼容性**：5 视角均与四 agent 架构（sense/research/think/exporter）兼容，不产生冲突。
3. **与三层复核机制的兼容性**：5 视角均与 research→main→human 三层复核兼容。
4. **与 research 工作 loop 的兼容性**：5 视角均与调研树广度遍历 + 事实模糊性归零兼容。
5. **与简报/悬置项/批判门禁规则的兼容性**：5 视角均与 R1（悬置项）+ R5（简报格式）+ 阶段门禁规则兼容。

> 事实层面无法区分 → 需要价值性假设层面的判断 → 升级到 N Judgment 的前置门禁判断。

### human 选择

**主视角：视角 E（架构论）**
**辅助视角：A 决策论 / B 认识论 / C 方法论 / D 实践论**（理论引用为参考）

### 关键决策点

- **D-E2-1**：选视角 E（架构论）为主视角
  - 理由：架构视角本质上是把 AI 作为人类智能的放大器，对人类心智的扩展；通过对 research(调查) / think(质疑) / exporter(表达) 三能力的抽象实现智能扩展；它帮助人类调查、质疑和表达。
- **D-E2-2**：哲学基础 = "AI 作为人类智能放大器" → 写入新的设计原则条目
  - 这是 human-loop 的哲学基础，作为独立设计原则条目记录。
- **D-E2-3**：sense = 调度能力 = main agent 复核层具象化
  - 二分职责：派发层 + 复核层。
  - sense agent 通过推动 sense 思考引导整个思维流程的正确性；是 research/think/exporter 三者之上的整体性体现。
- **D-E2-4**：四能力映射
  - research（调查）：事实性假设澄清
  - think（质疑）：价值性假设生成（致使目标最终失败的最大风险项）
  - exporter（表达）：将整个会话思考过程表达为 RFC
  - sense（调度/复核）：派发任务 + 核验结果
- **D-E2-5**：ABCD 视角作为辅助（形态：理论引用为参考）
  - A 决策论 / B 认识论 / C 方法论 / D 实践论 作为理论引用参考，不作为主视角。
- **D-E2-6**：派发要素 = 子步骤 + 主题 + 草稿路径 + 前序判断 + 任务派发 + 结果核验
  - 保持现有 7 要素（子步骤/主题/草稿路径/前序判断）基础上，补充任务派发与结果核验的原始功能。
- **D-E2-7**：核验循环终止 = 升级派发 + 最大重试 5 次 + human 介入
  - 当 subagent 返回结果不满足交付标准时，启动另一个 subagent 去解决，直到复核标准；最大重试 5 次后升级找 human 介入。

### sense 角色定义（补充设计原则）

- **sense = 调度能力 = main agent 复核层具象化**
- **派发层**：提供足够的上下文 + 基于 sense 描述目标 + 描述结果的交付标准
- **复核层**：基于交付标准进行检查；如果不满足标准则启动另一个 subagent 去解决，直到复核标准；最大重试 5 次找 human 介入

### 派发要素设计（保持现有 + 补充）

保持现有 4 要素：子步骤 + 主题 + 草稿路径 + 前序判断
补充 2 要素：任务派发 + 结果核验
