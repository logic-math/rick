# OneTrans-V2 统一级联推荐 教学大纲

## ① 领域全貌

推荐系统正处在一个范式拐点：工业界沿用了十几年的「召回→粗排→精排」多模型级联，正被重铸为「单一序列 transduction 模型」——把召回、粗排、精排当成一个因果 Transformer 的三个任务，共享一份「候选无关的用户行为序列编码（user context）」，一次编码、多阶段复用；item 不再靠双塔向量 + ANN 检索，而是被量化成语义 ID（SID）、由模型逐 token 生成。OneTrans-V2（字节跳动，arXiv:2609.28589v1，2026-09）是这条线在工业级联上的最新一环：它不删级联，而是保留三级联、只共享 context；线上替换三级联后 GMV/用户 +9.74%、同硬件预算 QPS 3.2×，离线召回 HR@1 +69.36%（0.0545→0.0923）（research_1.md §一，A）。理解这条线，等于理解推荐系统正在发生的这次范式迁移。

## ② 主要矛盾

学透这个领域，卡住人的不是某个公式，而是一对贯穿始终的张力：**「一次编码、跨阶段共享的统一表示」与「每一级联层各自独立的延迟/吞吐预算与候选特征」不可兼得**。统一能省掉重复编码、共享监督信号，但召回要的是亿级候选下的极致吞吐、精排要的是多 token 富特征下的精度，两者对同一份表示的要求是拉扯的；删掉级联（OneRec 路线）又会丢候选富特征。OneTrans-V2 的每一个设计——token 级独立参数、阶段可见性掩码、DCGR、SNT——本质上都是在给这对张力找平衡点。生成式检索 vs 判别式双塔/ANN 是第二对争论，但它从属于第一对。能否对同事讲清楚，取决于能否随时指出「哪个设计在为这对张力中的哪一侧让步」。

## ③ 核心练习方法

专家更新自己的方法是一条三合一主线，学这条线比背结论更接近学会：
- **手写最小生成式检索**：先用 RQ-VAE/RQ-KMeans 把 item 量化成语义 ID，再搭 autoregressive decoder、用 beam search 解码 SID，跑通一个最小闭环（research_1.md §三，A/B）。
- **漏斗经济学逐层练**：把统一模型放回工业级联，逐层设 latency/吞吐预算，练「一次编码、多候选复用」，对照 MTGR/COLD 的 per-stage 预算（research_1.md §三，A/B）。
- **先验超参迁移放大**：用 μP 小模型调参→放大后超参不变，MoE 用细粒度 expert + sigmoid 路由 + shared expert（research_1.md §三，A）。

## ④ 模块序列

1. **级联为什么到了要统一的时候** —— 还原三阶段独立建模的重复编码、孤立优化、容量碎片，让「动机」先立住 —— 对应核心练习方法的前设：先认清漏斗各层如何独立耗预算。
2. **语义 ID 的细节原理** —— 讲清 RQ-VAE/RQ-KMeans 如何量化出 3 级 SID、为什么量化出的 token 能支撑检索 —— 对应第①步（量化 SID）。
3. **共享 context 的统一架构** —— 讲清「候选无关 user context 一次编码复用 + token 级独立参数 + 阶段可见性掩码」如何做到共享而不破坏分层 —— 对应第②步（decoder 骨架）+ 第③步（保留级联的预算隔离）。
4. **DCGR 生成与 SNT 训练** —— 讲清四决策前缀（purchase/discovery/sponsored/spending）与按用户窗口、序列只编码一次的训练细节 —— 对应第②步（beam search 解码 + 训练）。
5. **把模型放大到线上规模** —— 讲清稀疏 MoE/sigmoid 路由/shared expert 与 μP 先验迁移的工程细节 —— 对应第④步（缩放迁移）。
6. **落到美团搜推：口径换算与决策映射** —— 讲清 GFLOPs/QPS/GMV 口径如何换算到自家栈、DCGR 四决策维在美团的对应物、生成式 vs 判别式在自家场景的取舍，最终形成能对同事讲的内容 —— 对应第③步（放回自家漏斗逐层设预算）+ 良质自检。
