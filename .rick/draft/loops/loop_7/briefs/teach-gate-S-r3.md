## 二、这个领域的知识是什么样子

### 2.1 pi 的 agent loop 源码级解剖:loop 内固有逻辑逐项

本轮调研把 pi 的 agent loop 从三层源码全部读穿(版本 0.84.2,本地文件可复核)。先讲清楚一个总图景:**pi 的「loop」不是一段神秘代码,而是一个 552 行的纯循环(L1)+ 一个 421 行的生命周期包装(L2)+ 一个 2686 行的会话编排层(L3)**。理解了这三层各管什么,「loop 里做了哪些事」「哪些可定制哪些不可」就变成可逐项核对的问题。

**L1 纯循环(pi-agent-core/dist/agent-loop.js,552 行)——loop 内固有逻辑逐项:**

1. **双层 while 结构**。外层循环只负责一件事:agent 本来要停了,查一下 `getFollowUpMessages()` 队列有没有排队的续跑指令,有就接着跑;内层循环负责本轮的工具调用与 steering(中途插话)消息注入。为什么要分两层?因为「本轮做完」和「整个任务做完」是两个不同的停止语义——follow-up 是「任务级续跑」,工具调用是「轮内推进」,混在一层就写不出清晰的终止条件。[本地代码 runLoop()]
2. **事件发射固定序列**:agent_start→turn_start→prompt 消息→每轮〔流式 assistant→工具执行×N→turn_end〕→agent_end。这个序列是 loop 的「合同」——所有下游消费者(渲染/持久化/扩展)都依赖这个顺序,所以它被固定死,扩展只能订阅不能重排。[本地代码]
3. **LLM 流式调用链**:transformContext 钩子(改写送入模型的上下文)→convertToLlm(内部消息格式→LLM 格式)→getApiKey(密钥解析)→streamFunction 流式调用(text/thinking/toolcall 的 delta 事件逐个透传)。每一环都是钩子,意味着「换模型/改上下文/换流式实现」都不需要动 loop。[本地代码 streamAssistantResponse()]

4. **工具调用默认并行**:多工具调用时默认 `Promise.all` 并行执行(executeToolCallsParallel);当 `config.toolExecution==="sequential"` 或任一工具声明 `executionMode==="sequential"` 时降级为串行。**这顺带消解了前轮未消解项**(research-extra-2 ⑥ 的「pi 是否原生并行执行工具调用未核实」)——已验证源码:pi 有原生并行工具执行。[本地代码 executeToolCalls()]
5. **截断保护**:当 stopReason==="length"(输出被 token 上限切断),该消息的所有工具调用**全部标记失败、不执行**。第一性原理:被截断的工具调用参数可能只剩一半——执行半个参数的 shell 命令或文件写入是危险行为,宁可报错让模型重发,也不赌参数是完整的。这是一个「fail-loud 优于 fail-corrupt」的小型范例。[本地代码 failToolCallsFromTruncatedMessage()]
6. **终止条件(四条,组合逻辑固定)**:① assistant 报 error/aborted→立即 agent_end;② 每轮后 `shouldStopAfterTurn` 钩子返回 true→agent_end;③ 本批全部工具结果 terminate===true→终止内层循环;④ 无工具调用+无 pending steering+无 followUp→退出外层。注意结构:**钩子可以「触发」终止,但不能「重写」终止条件的组合逻辑本身**——这是固有面的边界。[本地代码 runLoop()]
7. **轮间快照可变**:`prepareNextTurn` 钩子可在每轮之间替换下一轮的 context/model/thinkingLevel——这是模型热切换的官方入口,同样不需要动 loop。[本地代码 runLoop() 尾部]
8. **钩子全表(loop 暴露给外部的全部接口,共 12 个)**:getSteeringMessages/getFollowUpMessages/transformContext/convertToLlm/getApiKey/beforeToolCall(可 block+terminate)/afterToolCall(可改 result/terminate/isError)/prepareNextTurn/shouldStopAfterTurn/tool.prepareArguments/streamFn 整体替换,外加 config.toolExecution 并行策略。这张表就是「loop 内逻辑可被外部介入的全部位置」——清单是封闭的、可穷举的。[本地代码 agent-loop.js + agent.js createLoopConfig()]

**L2 Agent 包装(pi-agent-core/dist/agent.js,421 行)**:单活动 run 保护(并发调用直接报「Agent is already processing」)/AbortController 取消/steering+followUp 队列/运行失败时**合成一条 error assistant 消息走完整事件序列**(下游消费者看到的是统一的合同,不是裸异常)/事件状态归约(维护 pendingToolCalls 集合)。[本地代码 runWithLifecycle()/handleRunFailure()/processEvents()]

**L3 AgentSession(pi-coding-agent/dist/core/agent-session.js,2686 行)**——loop 外围的会话级编排,共四件事:① **自动 compaction**:agent_end 后检查上下文溢出,可恢复截断→compact-and-retry 一次(有防死循环标志);② **自动重试**:可重试错误按 maxRetries 重试(auto_retry_start/end 事件,成功后重置计数);③ **扩展事件桥**:全部 loop 事件转发给 ExtensionRunner——扩展拿到的是完整事件流;④ **agent_settled**:重试/compaction/followUp 都无剩余才算真 idle——**rick json mode 的终止信号就是这个事件**。[本地代码 agent-session.js:396-600, 1530-1590]

**固有 vs 扩展边界(已验证)**:主循环结构(双层 while/事件序列/终止条件组合/并行策略)**是固有的,扩展不可替换**;可定制面=上述 12 钩子+扩展事件(tool_call/tool_result 拦截、before_provider_request/headers、自定义 compaction、session_before_switch/fork、registerTool/Command/Provider)。[官方 docs/extensions.md 事件目录;本地源码]

### 2.2 异常隔离:坏扩展跳过不阻断——「loop 稳定」与「插件隔离」是两个正交维度

human 问「loop 稳定的好处」并担心「插件错误系统性崩溃」。本轮源码考古给出了精确答案,先讲机制再讲维度拆分:

1. **pi 扩展异常不进主循环**:ExtensionRunner.emit() 对**每个扩展的每个 handler 独立 try/catch**,异常转成 emitError 事件(含 extensionPath+stack)通知用户,主循环继续执行。扩展代码不在 loop 包内(pi-agent-core 对扩展零依赖),仅经钩子/事件桥交互——loop 与扩展之间是事件总线上的松耦合,不是调用栈上的紧耦合。[本地代码 dist/core/extensions/runner.js emit()]
2. **pi 扩展加载失败不阻断启动**:loadExtensionsInternal 对单个扩展的加载错误 push 进 errors 数组后 continue,其余扩展照常加载。坏扩展的后果=该扩展自身不可用+一条错误通知,不是整系统不可用。[本地代码 dist/core/extensions/loader.js:432-452]
3. **dsh 的 loop 是插件**:architecture.md:11 原文「产品的每一部分都是插件,包括…agent loop 本身,可从配置替换」;core/agent-loop 是实现 ctx.agentLoop 接口的默认驱动器。[官方 docs/architecture.md:49;docs/capability-seams.md]

**关键的概念拆分(本轮最重要的教学点)**:「loop 是否可替换」和「插件故障是否隔离」是**两个正交的维度**,逻辑上有四个象限:loop 固定+插件隔离;loop 可替换+插件隔离;loop 固定+插件全树连坐;loop 可替换+插件全树连坐。dsh 的设计把自己放在了「loop 可替换+全树连坐」象限,pi 实测在「loop 固定+handler 级隔离」象限。**loop 稳定≠自动获得插件隔离**(这是两个独立工程决策),但 pi 的实现恰好两者兼备——「loop 稳定的好处」与「不怕坏插件」在 pi 里不是取舍关系,是同存的两个属性。这是事实陈述(research-extra-3 ②-4 原文:「隔离边界与 loop 是否可替换是两个正交维度,loop 稳定≠自动获得插件隔离,但 pi 实现恰两者兼备」),不是对 pi 的推荐。

### 2.3 「稳定内核+插件隔离」的架构学:故障域设计的第一性原理

pi 的上述形态不是孤例,是系统设计里一条成熟谱系的最新成员。讲透这条谱系,才能判断 dsh 的「全树事务」在谱系上处在什么位置。

**第一性原理:故障域。** 任何系统的故障都有一个「爆炸半径」——一个部件坏了,波及多大范围。故障域设计就是主动决定这个半径。隔离手段有一个清晰的优先级阶梯:**进程边界(最强)> 包/模块级停用 > 污染标记后继续运行 > 全树事务(无隔离,一坏全停)**。为什么进程边界最强:进程有独立的地址空间,插件崩溃最多带走自己所在进程,宿主存活;为什么全树事务最弱:它把「所有插件挂载成功」绑定为一个原子单元,任何一个失败都让全部失败。但全树事务也有它换来的东西:**fail-loud**——配置错误在启动瞬间全部暴露,不会有「带病上线」的静默降级。这是一种取舍,不是单纯的错误(取舍的评判归第五节)。

**谱系逐项(全部一手来源)**:

- **Chromium**:设计文档明言「渲染引擎不可能不崩溃」「插件是浏览器不稳定主因」,方案=多进程切分故障域+插件独立进程运行;渲染器崩溃浏览器存活。[chromium.org 设计文档]
- **VS Code**:全部扩展运行于独立 Extension Host 进程,扩展宿主崩溃仅报「terminated unexpectedly」,编辑器存活;官方提供 Extension Bisect 二分定位劣化扩展。[code.visualstudio.com]
- **Firefox**:2017 年起仅支持 WebExtensions(受限 API),进程内旧插件(overlay/bootstrap/SDK)全部停用,官方理由=更安全更稳定——「稳定内核+受限扩展 API」路线的原型之一。[Mozilla 官方博客]
- **Linux**:模块异常只置 taint 标志、不阻断启动(taint 内核的 bug 报告常被开发者忽略,是这个设计的已知代价);oops 行为由 panic_on_oops 分级容错。[docs.kernel.org]
- **OSGi/Eclipse(与 dsh 插件树机制最同构的先例)**:非可选 import 不满足时**仅该 bundle 停在 INSTALLED 状态,框架与其余 bundle 照常启动**;ActivationPolicy:lazy 把激活推迟到首次类加载,规避「单插件阻塞全局启动」。[OSGi Core 8 §3.2.1.1;eclipse.org equinox-dev]
- **微内核史实**:Mach3 实测内存系统性能显著差于单核 Ultrix(Chen&Bershad 1993)——微内核第一波失败;L4 把 IPC 降至 45–121 cycles,证伪「微内核必慢」(Liedtke HotOS-VI)——可行性成立但工程代价真实。这个史实的教学含义:「稳定内核+扩展隔离」的架构**可行但有真实工程成本**,不是免费午餐。

**dsh 在谱系上的位置(源码级证据,见 2.5 详述)**:boot 是全树事务,任一插件激活失败→整树 dispose 抛「plugin tree failed to load」——处在阶梯最底层(无插件级故障隔离);与 OSGi 的 bundle 级停用形成直接对照,而 OSGi 恰是机制上最相似的先例。业界未见「单插件阻塞整体启动」被当作设计目标的先例——OS/浏览器/IDE 一致把它视为需规避的缺陷(leaf-1 结论 2)。[本地源码 packages/boot/app-boot/src/index.ts:757-800]

**postmortem 0001 的教训:组合缺陷的测试盲区。** dsh 官方 postmortem:同一插件多出口形态(export default apply)使 Loader 丢弃 inject 声明,**178 个绿灯单测+100% 行覆盖未拦截,真实 Zed 连接即崩**,修复靠补「真实 Loader 路径」测试。[官方 docs/postmortem/0001]。第一性原理:单元测试验证的是**单元**在**被测环境**里的行为;插件系统的缺陷出在「插件×Loader×组合」的交界处——覆盖率度量的是「代码被执行过」,不是「组合被真实执行过」。这条教训的普适性超出 dsh:**任何「插件很多+全树耦合」的系统,其组合空间测试都天然有盲区**,覆盖率数字不消除这个盲区。这也直接回应 human 的「插件规模化混乱」之问:混乱的机制载体是全树事务+级联卸载+组合盲区三者,不是「插件多」本身(声明面本身是薄的,2.5)。

### 2.4 loop 可定制:什么需求才真正需要「替换 loop」(第一性原理)

human 的核心问题是「loop 可定制有什么好处、代价是什么、rick 未来会不会需要」。先把问题精确化,再讲业界证据,再讲 AI 自改进的特殊维度。

**精确化:「定制 loop」的收益只在钩子表达不了的区间存在。** 2.1 的钩子全表是一个封闭清单:改上下文(transformContext)/换模型(prepareNextTurn)/拦工具(beforeToolCall 可 block)/改结果(afterToolCall)/终止(shouldStopAfterTurn/terminate)/换流式实现(streamFn)/改工具参数(tool.prepareArguments)/并行策略(toolExecution)。用第一性原理问:**什么行为落在这个清单外?** 答案是:① 改变事件序列的**结构**(增删事件类型、改变轮次语义);② 改变终止条件的**组合逻辑**(不是触发终止,而是重写「什么算完成」);③ 改变双层 while 本身的拓扑(如插入新的外层循环类型)。凡是「在既定骨架内改行为」的需求,钩子已覆盖;只有「改骨架本身」的需求才需要替换 loop。dsh 相对 pi 的结构性自由度,精确地就是这个「改骨架」区间(前轮三层清单第①层,r2 2.2)。

**业界证据:loop 定制的形态与代价(leaf-1,全部一手来源)**:

- **LangGraph**:显式 StateGraph+条件边+checkpointer 中断恢复——把「定制循环」重表达为「手工编排图」。代价:图/状态 schema 变更即破坏历史 checkpoint 兼容,旧线程恢复可报 TypeError。[docs.langchain.com;issue#8629]
- **OpenHands**:每迭代 agent.step(State)→Action+append-only 事件流。已知痛点:response_to_actions 是模块级函数,子类难覆写。[官方 README/issue#8025]
- **AutoGPT**:官方架构笔记解释弃用 legacy Plan-Act(REPL 式)loop 的原因——老代码「缺抽象边界、全局状态封装差、难演进」;失败模式=无限循环+token 失控;旧插件体系整体废止。[ARCHITECTURE_NOTES.md;issue#4770]
- **smolagents/CrewAI**:收敛于固定步循环(thought→action→observation),定制上移到 Process 层(Sequential/Hierarchical 编排)。[官方 docs]
- **leaf-1 结论 1**:「Loop 定制业界收敛为显式图/事件流+检查点持久化,而非改死循环代码」——即业界把「可定制」做在 loop **之上**的编排层,不是做在 loop **本身**的可替换性上。

**AI 自改进的关注点分离(第一性原理,承接 human 的问题)。** 把「AI 改进自己的工作系统」拆成两个量:**改进面**(系统里允许 AI 改的部分)和**验证面**(每次改动需要验证才能信任的部分)。这两个量不是独立的——改进面越大,验证面越大,且验证成本通常超线性(见下 seL4 数据)。pi 的形态:自改进面=扩展(registerTool/Command/Provider/事件 handler,JS 可热重载 /reload),loop 结构不在改进面内→验证面=扩展自身单测+pi 稳定 API 契约;dsh 的形态:loop 也在可改面内(配置替换 ctx.agentLoop)→改进面更大,验证面相应更大。**这不是「谁好谁坏」,是关注点分离程度不同**:把不变量(loop 骨架)固定、把变化(扩展)隔离,验证面被压缩到差分面。

**自修改系统的软件工程经验(leaf-2,全部一手来源)**——这个领域有 60 年积累,结论高度一致:

1. **Gödel machine**(Schmidhuber 2003):理论上「任意自身代码可改」的系统,也须先由证明搜索器证得「改写有用」才允许改——效用函数/硬件/初始代码由公理固定为证明基准。**连理论上最激进的自修改系统,也把基准固定、把证明作为改动闸门**。[arXiv:cs/0309048]
2. **GCC 三阶段自举**:stage1-3,`make compare` 对后两阶段逐对象对拍;Rust 自宿主以固定 beta 快照为 stage0——工业级自修改系统的标准手法=**把验证面压到差分面**(只需验证「新编译器编译结果==旧编译器」,不需重验整个工具链)。[GCC Internals;rustc-dev-guide]
3. **Thompson 1984**:自宿主编译器可注入源码不可见的后门——自修改系统的验证面=**整条自举链**,非单一代码库。[CACM 27(8)]
4. **seL4**:8,700 行 C 的全功能正确性验证需 20 万行 Isabelle 证明——**验证成本≫实现成本**,故内核极小化以控验证面。这是「为什么要把可改进面做小」的定量证据。[Klein et al., SOSP 2009]
5. **SPIN**(SOSP 1995):应用经语言/链接期安全机制以「扩展」安全改 OS 接口,**内核核心不动**——「改扩展不改内核」的直接先例。[doi:10.1145/224057.224077]
6. **遗传编程**:交叉高度破坏性,早期仅 ~19.5% 子代不差于亲代,劣化远多于改善;幸存个体靠中性码膨胀(intron)自保护——**大改动存活率低,自改进实际走小步+保护层**。[Langdon & Poli 1997]
7. **leaf-2 结论 1**:「自修改系统工程共识:固定不变量+证明/对拍闸门+改扩展不改内核,把验证面压到差分面。」

**收益/代价的对称结构(小结,不判断)**:loop 可替换的收益=「改骨架」区间的需求未来出现时无需 fork;代价=骨架自身进入可变集合——对 AI 自改进场景,代价的具体形态是验证面扩大(每次改 loop 都要重验「双层 while+终止条件+事件序列」的不变量,而这些不变量恰是下游所有扩展依赖的合同)。pi 的形态把这笔代价换成了另一笔:若「改骨架」需求出现,只剩 fork 一条路。**两笔代价都真实,形状不同**——这与 r2 2.3「churn vs 断崖」是同构的风险形状分析,具体定价归第五节。

### 2.5 dsh 插件规模化风险机制:全树事务/级联卸载/可逆 effect 边界

human 问「插件越来越多会不会系统性混乱、增删是否需要耦合」。本轮 leaf-3 源码考察给出机制级答案,分四层讲:

**声明层(薄,无耦合)**:无单一 cordis.yml 主配置;插件树=四层有序 patch 组合(profile bundles 列表→profile cordis.patch.yml→home 级→--patch,后层按 row id 整体替换不深合并);`dsh plugin` 转发 pnpm,add 自动追加 bundle 层、remove 同步移除;**增删插件不需要手改其他插件文件**——耦合不在声明面。加载顺序非手动序列:插件声明 inject(所需服务名数组),服务出现才激活(fiber 状态机 PENDING→LOADING→ACTIVE/FAILED/UNLOADING→DISPOSED)。[官方 docs/architecture.md:15-27;vendor/cordis/src/fiber.ts:140-155;publish.md:77-110]

**启动层(全树事务,一坏全崩)**:boot 把「整棵插件树挂载成功」当原子单元——任一 entry 激活失败→**整树 dispose 后抛「plugin tree failed to load」**,无单插件故障隔离;晚到的未处理 rejection 也转 exit(1)。[本地源码 packages/boot/app-boot/src/index.ts:757-800,609]

**运行层(级联卸载)**:被依赖服务变化(uid 变化即服务重注册)→inject 它的全部插件自动 UNLOAD→PENDING,服务回来才 RELOAD——依赖链传导,非局部失败隔离。**设置 UI 自身是插件**(ui-settings-plugins inject=['slots','locale','connection','remote','settingsScope']):坏依赖可带走插件管理入口本身——#4175 的故障模式(插件管理 UI 与坏插件同树同殁,卸载入口不可用)有源码同构证据。[本地源码 vendor/cordis/src/fiber.ts _setEpoch;packages/client/ui-settings-plugins/src/client/index.ts:51-53]

**回滚层(可逆 effect 只覆盖注册类)**:所有注册(工具 schema/prompt section/适配器/listener/服务)经 ctx.effect()/ctx.on() 的 disposer 逆序回滚——这部分是真可逆。**不在回滚边界内的四类**:① session 事件日志(append-only 持久事实,LLM 历史由 log 派生);② Cordis API 之外的副作用(写文件/起进程须插件自己包 ctx.effect,否则泄漏——官方教程明示);③ 动态包内存态(agent 自写插件「重启即失」但「可能影响同进程其他会话」);④ profile/package.json 磁盘状态。另:HMR 用户补丁层有独立容错(坏 patch 保留最后好树),但那是**配置层**的容错,不是插件代码层的隔离。[官方 docs/cordis-primer.md:13,44;cordis-tutorial/02-lifecycle;packages/extensions/tool-cordis/README.md]

**对「系统性混乱」之问的机制答案(事实综合)**:混乱风险不来自「插件数量」本身(声明面薄),来自四个机制的叠加——全树事务(一坏全停)+级联卸载(依赖链传导)+组合测试盲区(postmortem 0001:178 绿灯单测不拦组合缺陷)+回滚边界外的副作用。这四项中,全树事务与级联卸载是**结构性**的(改它们=改 Cordis 设计),组合盲区是**测试方法学**的,副作用边界是**插件作者纪律**的。dsh 开源仅数周,长期规模化实证数据不存在(未消解,research-extra-3 ⑥-2)。

### 2.6 判断力度量公式教学:F1 字典序向量 / F2 加权 / F3 分列,与拍板四字段

human 请求「直接给我一个可排序的公式+数据从哪来」。先讲所有公式的共同前置,再逐个讲透三个候选的数学性质,最后给数据来源逐项映射。

**前置结构:拍板四字段(公式共用输入,缺了公式就退化)。** 记四个字段:M=命题(可判对错——到期后 y∈{0,1} 可回收);p=human 报的 0–1 概率;D=截止日;I₀=影响力预估(+可选关联 job 集)。为什么缺一不可:M 不可判对错→分数无法回收(打分对象不存在);无 p→proper 分无输入;无 D→「到期」无定义,y 永远悬置;无 I₀→影响力维度只能事后回填,变成叙事。GJP(IARPA 锦标赛)的全部方法学就建立在这四件套上(概率+截止日+可解决命题)。[Mellers et al. 2014] **这是 rick 层 judgment.md 的格式扩展,与 runtime 无关**(r2 2.6 已定,本轮 research ④再次确认)。

**候选 F1:字典序向量(与 human 拍板「正确性>赔率>影响力」直接同构)。** 记三元组 V=(C, O, I),排序规则:先比 C,C 相同(容差 ε 内)比 O,再相同比 I。逐维讲透:

- **C(正确性,proper score)**:命题到期后按实际结果 y∈{0,1} 回收。两种标准形态:**Brier 形** C = 1−(p−y)²(报 p=0.7 且发生,y=1→C=0.91;报 0.7 未发生→C=0.09);**对数分形** C = y·ln p+(1−y)·ln(1−p)(严 proper,对过度自信惩罚更陡:p=0.99 而未发生→C=ln(0.01)≈−4.6,重罚)。数学性质(为什么用它们):**严格 proper scoring rule**——诚实报告真实概率是期望分数最优策略,虚报概率在数学上对自己不利。这是「分数不可被话术操纵」的全部含义。[Gneiting & Raftery 2007 JASA]
- **O(赔率/非共识)**:需要一个共识基准 q(前轮 N2 问题,2.8 详述其统计学陷阱)。命中时 O=(1−q)/q——这是「押注 1 单位在共识概率 q 的事件上,命中时的赔率回报」:q=0.9 的共识事件命中只得 0.11 倍,q=0.1 的反共识事件命中得 9 倍。数学同构于 LMSR 预测市场定价(Hanson 2002)。未命中 O=0。[Hanson 2002]
- **I(影响力)**:I=H+F。H=历史价值(关联 job 的 durationMs/成本/任务状态变化——meta.json 可直接派生,机器侧已就绪);F=未来期望值(需显式概率树 ΣP(oᵢ)·V(oᵢ),**唯一需人工建模的项**,成本最高,可先置空只用 H)。

**F1 的排序性质(数学事实,不含倾向)**:全序+传递(任意两条判断可排);**无跨维补偿**——正确性不可用影响力买:一条高影响力的错误判断不会排在低影响力的正确判断之上(Goodhart 鲁棒:单一维度被博弈不会污染总排序);缺点两条:① ε 容差是设计参数——ε→0 时微小的概率差(如 0.700 vs 0.701 的 Brier 差)压倒一切后续维度,ε→∞ 时退化为纯影响力排序,**ε 本身需要被拍板**;② 字典序不连续不可微——作为排序函数完备良定义,但作优化目标不可微(无法梯度式改进)。

**候选 F2:加权合成标量。** V = w₁C + w₂O + w₃I(w₁>w₂>w₃ 编码优先级,O/I 须先归一化)。性质:连续、可补偿;**风险(数学事实)**:三项异量纲必须先归一化,而归一化界本身是可被博弈的设计参数(把影响力的量程拉大,同一实际影响力得分升高);可用低 C 换高 I(正确性低的判断靠影响力翻盘)——Goodhart/博弈面重新打开。[Goodhart 1975;Strathern 1997] F2 是 F1 的「软化」:用补偿性换连续性。

**候选 F3:分列记账(账本式,非合成公式)。** 不合成标量:每条判断记 (M, p, q, y, D, H, F, t);汇总层只做分列统计——校准曲线(分档 p vs 实际命中率,**每档≥10 条才有读数**)、分辨力、命中判断的赔率加权和 ΣO、影响力加权和 ΣI;排序=「先按校准带,再按赔率和」。性质:无单一全序但每列独立可审计;**GJP 实际排名用的就是单一 Brier**——分列是学界默认形态,Mellers et al. 2014 的原始设计即如此。

**与 human 拍板的兼容性(事实对照)**:human 拍板「向量化+排序倾向正确性>赔率>影响力(附子判断等价论证)」。对照结果:F1 字典序向量=该拍板的直接数学实现(向量记录+固定优先级排序);F3 分列=向量化+较弱排序(按校准带粗排);F2 加权=human 明确放弃的方向(r2 leaf-D 已论证偏离 proper 范式)。**两个未决口**:① 排序的**用途**——是展示工具(给人看的画像)还是评分规则(进入激励,如影响 dream 反思强度)——用途决定 ε 的严格程度与是否必须 proper(think-gate-S-r3 Q4d:proper 评分对全部预测打分正是防保守化,若只给「敢报的判断」打分,「只做高置信判断」即可最大化正确率,这是保守化激励);② 子判断等价论证(拍板所附论证)的前提与失效面,见 2.7。

**数据来源逐项映射(B2,全部本地已验证)**:

| 字段 | 来源 | 状态/成本 |
|---|---|---|
| M/p/D/I₀ | judgment.md 新增结构化字段 | **需新增**(拍板时写 4 字段,成本最低) |

### 2.7 赔率 vs 影响力:两维的领域知识,与 human 子判断等价论证

human 拍板「正确性>赔率>影响力」并请求调研「影响力 vs 赔率」。调研结论的诚实形状是:**两维各有强大的理论传统,「哪个更重要」取决于分数的用途,不可单值回答**(think-gate-S-r3 Q4d 同判)。正反论证并列:

**支持「赔率(非共识)优先」的论证(全部一手来源)**:

1. **Grossman-Stiglitz(1980 AER)**——决策论上最精确的一条。若价格已完全反映信息(即共识已形成),则**没有人能从昂贵的信息获取中获得回报**;推论:完全信息有效的市场在均衡上不可能存在,超额收益=未被共识定价信息的补偿。对判断力度量的直接含义:**共识性判断的边际认知价值≈0**——注意是「边际认知价值」而非「总价值」,这个限定词是 2.7 末尾争论的根源。[Grossman & Stiglitz 1980, AER 70(3):393-408]
2. **Marks second-level thinking**:超额收益要求「非共识且正确」的价值观点——第一层思维「这是好公司」不够,第二层「大家都知道是好公司,所以价格已反映,什么才是市场没看到的」才有信息含量。[《The Most Important Thing》ch.1;Oaktree 备忘录]
3. **Steinhardt variant perception**:「有充分依据、与市场共识显著不同的观点」,自述为其 28 年**唯一管用的分析工具**(费后年化≈24.5%)。[《No Bull》2001]
4. **库恩/普朗克**:认知增量存在于范式(共识)之外,范式内解题是常规科学;反共识新范式的兑现以代际计(Planck 原则:「新科学真理胜出是因为反对者终将死去」)。[《科学革命的结构》ch.IV/IX;Planck 1949]

**支持「影响力(规模/仓位)独立价值」的论证**:

5. **VoI(信息价值理论)**:Howard 1966——信息价值=对**决策期望值**的改进;「不改变决策的信息价值为零」。推论:信息优势必须经可变动作(仓位/规模/资源投入)才兑现;**无影响力的正确反共识判断兑现不了价值**——判断对了但没有行动通道,认知价值停在认知层。[doi:10.1109/tssc.1966.300074]
6. **预测市场的形式化**:对数效用等条件下,价格≈**财富加权**平均信念——个体的「影响力」(下注财富)就是其信念在共识中的权重;仓位同时是赔率的对手方与影响力的载体,**两者在定价机制中不可分离**。[Wolfers & Zitzewitz, JEP 18(2) 2004]
7. **Soros/Druckenmiller 转述(二手,已标注)**:「关键不是对错,而是对时赚多少、错时亏多少」——收益=正确性×仓位大小。[《The Alchemy of Finance》1987;irishtimes.com]
8. **执行价值形态(leaf-2 综合推断,已标注为推断)**:由 VoI+G-S+财富加权定价推出:已入共识定价的判断,其价值形态转为**执行价值**(范式内执行生产力、大仓位可执行、低边际风险);认知性超额只存在于偏离共识处。「正确的废话」这个表述低估了执行价值这一独立形态——共识性大判断的价值不在认知,在动员/规模/时机。

**两维在不同用途下的不同角色(框架,非结论)**:测判断力(度量目的)→ proper 分+影响力**分列**(Brier 回答「准不准」,O 回答「敢不敢反共识且对」,I 回答「押没押在重要的地方」——三问各自独立有意义);指导决策(行动目的)→ EV 主导(期望值=概率×影响,加性结构),此时「影响力低的高概率判断」与「影响力高的低概率判断」直接可比。另一个调制变量是**竞争性**:零和/竞争场景(投资)才有反共识溢价——你对了的钱来自错了的别人;工程判断通常非竞争(判断对了自己受益,不依赖别人错),反共识溢价的经济学基础在此弱化。

**human 子判断等价论证的成立前提与三个失效面(方法学分析,think/research 双向核对)**。human 的论证形态:「难而正确的判断必然存在高赔率的子判断,故影响力维度可由赔率+正确性吸收」(等价于:子判断层已捕捉影响力)。它成立需要两个前提:①「难而正确」确由某个**因果瓶颈子判断**驱动,且该子判断**当时**反共识(不是事后看);②价值形态是纯认知性(价值全部来自判断本身)。三个失效面:

- **失效面一:分解不唯一(幸存者偏差)**。「哪个子判断是关键的」是**事后回溯归因**——同一个成功可以分解出多个不同的子判断集;事后总能找到「与别人不同」的子判断(成功的案例里一定存在差异点,无论它是否因果)。等价性因此可被**选择性分解操纵**:想证明「有高赔率子判断」时总能找到一个。think-gate-S-r3 Q4b 的表述:「等价性可被选择性分解操纵」。
- **失效面二:执行价值低估**。若价值形态是执行(组织资源/坚持/规模/纪律)——例如「买好生意」类成功更多在执行纪律与仓位规模,不在方向判断——则价值不在任何**认知**子判断中;等价论证把「难」全部归因到判断层,漏掉了「难在做不在判」的整类情形(think Q4a:执行型难题判断全共识)。
- **失效面三:共识性时变**。赔率取决于**度量时点**——共识形成前 vs 形成后,同一判断的 (1−q)/q 完全不同(预测市场早期仓位赔率高,共识形成后趋零);等价论证隐含「共识性固定」假设,而真实判断的共识性随时间漂移。「子判断当时反共识」的前提在回看时最难核实。

这三个失效面不否定论证,它们刻画的是论证的**适用边界**——边界内(纯认知价值+唯一稳定分解+时点明确)论证成立,边界外失效。边界怎么划是判断项(第五节)。

### 2.8 同源 subagent 聚合的统计学:条件独立、相关样本、基线循环

human 的反共识基线方案:「多个独立 subagent 分方向给出观点代替群体概率+dream 中 human 审核+反共识量化系数」。这是本轮最需要讲透的方法学问题——它触及群体智慧成立的统计前提。

**群体智慧的条件(第一性原理)。** 「多个判断聚合比单个准」(Condorcet 陪审团定理一脉)依赖一个核心前提:**个体误差条件独立(或至少弱相关)+无系统性共同偏差**。数学上:n 个判断聚合后方差按 ~1/n 收缩的前提是误差不相关;若误差相关系数 ρ>0,方差下界≈ρσ²——**相关样本聚合后方差不收缩,测到的不是「群体共识」而是「共同偏差的放大」**。这正是「群体智慧」与「群体极化」的分水岭:同一群人,误差独立时聚合变聪明,误差相关时聚合只是把同一个错误说了 n 遍。

**同源 subagent 的问题所在。** 同一底层模型的不同实例(不同会话/不同角色提示)共享:训练数据/先验/世界模型/推理风格——**误差高度相关**。「分方向」(让不同 subagent 调研不同侧面)注入的是**信息差异**,不是**判断者独立性**:两个评委看了不同的资料,仍是同一个「大脑」在评。think-gate-S-r3 Q3 的精确表述:「同源采样共享先验与世界模型,误差高度相关;『分方向』注入的是信息差异,不是判断者独立性……相关样本聚合后方差不按 √n 收缩,测到的是『该模型分布』而非『共识』」。这不是说聚合无意义——它测到的东西仍然真实存在(该模型对命题的分布),**但它不是「共识」这个词通常所指的东西**(人群信念的聚合)。

**什么组合能逼近独立性(候选清单,各有代价)**:① **不同模型**(不同训练数据/先验——独立性最强,但引入「模型间能力差异」混杂:分歧可能来自能力差而非真信念差);② **不同提示框架**(同一模型,认知视角不同的提示——独立性弱,但零成本);③ **不同信息集**(同一模型喂不同资料——独立性最弱,即「分方向」的现状)。研究上判断独立性的经验做法:对同一命题重复采样,看**离散度是否稳定且显著**——若同一模型多实例对某命题概率始终聚在窄带内,说明分布稳定(可作「模型分布」基线);若散乱,说明采样方差大(连「模型分布」都测不准)。

**基线循环问题(think Q3 后半)。** human 方案含「dream 中 human 审核」——human 审核后的概率进入基线 q。那么「共识」变成「agent 群+human 的共识」,而反共识系数测的是「human 拍板与该基线的分歧」——**被测者(human)参与了构造自己的评分基准**。校准基线需要与被测者独立,否则构成循环:human 修正基线→自己的「反共识性」随之变化→系数不再是外部度量。破循环的候选路径(均开放):a) 基线取**原始分布**(human 审核结果不回写 q,审核只用于剔除无效样本);b) 基线改**外部共识源**(预测市场/AI 判断聚合/社区共识——rick 当前无现成可采样源,r2 N2 已记);c) 承认系数测的是「human vs agent 群分歧」并显式改名(不作「反共识」解,作「人机分歧度」解)。另有未定义项:反共识量化系数的**统计量来源**与 human 反馈进入公式的方式(think Q3 末)。

### 2.9 常见误区(本轮知识的反面清单)

**误区一:把「loop 稳定」当「插件隔离」的原因。** 两者正交(2.2):loop 是否可替换与插件故障是否隔离是两个独立工程决策。pi 两者兼备是**实测巧合**(它的 ExtensionRunner 设计+loader 设计恰好都做了隔离),不是 loop 固定的自动后果;理论上存在「loop 可替换+handler 隔离」与「loop 固定+全树连坐」两种未观测组合。

**误区二:把「单插件阻塞启动」当小概率运维事故。** 谱系证据(2.3)显示它被 OS/浏览器/IDE 一致视为**设计缺陷**而非运营问题——OSGi 专门用 bundle 级停用规避它,Chromium/VS Code 用进程边界规避它。dsh 的 #4175(插件管理 UI 与坏插件同殁)是「卸载入口本身消失」的二阶放大,不是普通故障。

**误区三:把「pi loop 固定」当「pi 不能并行执行工具」。** 本轮消解:pi 有原生并行工具执行(Promise.all,默认开,可配串行)(2.1-4)——前轮这曾是未消解项。

**误区四:把字典序向量当连续优化目标。** F1 是**排序函数**(全序+传递+良定义),不是连续可微的评分函数——用途是排序与展示时它是完备的,用途是「让系统优化它」时不可微的性质会显形(ε 的悬崖)。

**误区五:把「反共识」当无条件美德。** 反共识溢价的存在性依赖竞争场景(零和)+共识基准的有效性(2.7);工程判断非竞争时,溢价的经济学基础弱化。且赔率计算依赖 q 的真实共识性——同源基线下算出的「赔率」度量的是与模型分布的分歧,不是与市场/人群的分歧(2.8)。

**误区六:把「子判断等价」当可回溯验证的命题。** 三个失效面(2.7 末)中「分解不唯一」使该论证在回溯数据上**不可证伪**——总能事后找到反共识子判断。可证伪的版本需要预注册分解(拍板时先写下子判断,到期再核),这与 D10 撤销条件预注册是同一个方法学动作。

## 三、启发式追问

以下追问建立在 2.1–2.9 已讲清的知识之上,承接 think-gate-S-r3 top-5+门禁观察,每条附「改变判断的证据」。只问,不替答。

**Q1(承 think Q1)「唯一差异」是否修正为三项结构差异——后两项对 rick 是零期权吗。** 2.2(r2)的三层清单里第①层结构性差异共三项:loop 替换/跨产品子代理后端/三平台 fail-closed 沙箱。human 本轮把差异收敛为「唯一=loop 可定制」,等于把后两项归零。那么:这个归零是**有意的排除**(判断「rick 不需要跨产品子后端、不需要 Windows 沙箱」——若是,应写明理由,因为它们就成了已关闭的期权),还是**无意的遗漏**(收敛时只想到 loop)?两项的现况:跨产品子后端=rick 当前子代理全走 pi-subagents(单后端);fail-closed 沙箱=rick 现无沙箱需求记录。归零的后果:若未来 rick 要把 Claude Code/Codex 当子代理跑,或要在 Windows 上跑带沙箱的 job,这两个「已归零期权」重新计价——而 dsh 裁决若已按「唯一差异」做出,届时是否触发 D10 撤销?
改变判断的证据:rick 路线图出现跨产品子代理或沙箱需求的具体条目(两项应保留在差异清单);或 human 写明排除理由(两项正式记为零期权,「唯一差异」表述成立)。

**Q2(承 think Q1/门禁观察 2)loop 调研结果如何回填裁决——零命中未变,期权怎么定价。** 本轮调研回填了三件事实:① pi loop 稳定+插件隔离**两者兼备**已实证(2.2)——「loop 稳定的好处」与「不怕坏插件」在 pi 内不构成取舍;② rick 需求零命中未变(8 个在用定制点无一落在「改骨架」区间,2.4);③ loop 可替换的收益/代价结构已讲清(收益=「改骨架」区间需求出现时免 fork;代价=该区间空置时,自由度本身无收益,而骨架进入可变集合的验证面扩大)。那么裁决的形状:loop 替换作为**期权**定价(未来出现「改骨架」需求的概率×命中时收益(fork 成本的避免)−持有成本),还是按 YAGNI 记零(需要时再迁移评估)?注意两个框架在「需求概率足够低」时给同答案,分歧区间在概率多高、fork 成本多大。回填后裁决树的状态(think 门禁观察 1):通向 dsh 的路径上只剩 loop 定制+两项被归零的期权——这个「单路」状态是本轮裁决结构的**事实**,接受它还是先补两项期权的计价再裁,是判断项。
改变判断的证据:rick 路线图出现「必须改事件序列结构/终止条件组合逻辑/循环拓扑」的具体需求(期权价值跃升);或 R7 侧确认 pi 钩子清单(12 项)覆盖未来 12 个月全部规划定制点(期权价值趋零,定价完成)。

**Q3(承 think Q3)反共识基线的组合选择:独立性从哪来,循环怎么破。** 2.8 讲清了:同源多实例+分方向=信息差异非判断独立性,聚合测到「该模型分布」;human 审核进基线=被测者参与构造自己的基准(循环)。那么三个子问:① 独立性来源选哪个组合——不同模型(独立性最强但混入能力差)/不同提示(零成本但弱)/不同信息集(现状,最弱)?② 循环破法选哪条——基线取原始分布(审核不回写)/外部共识源(现无)/改名为「人机分歧度」(不作反共识解)?③ 反共识量化系数的统计量与 human 反馈进入公式的方式,是否在拍板前定义?注意这三个子问相互耦合:若选「原始分布+不回写」,系数名与含义要相应改;若选「不同模型」,q 的中位数聚合方式(能力加权否)要重定。
改变判断的证据:同命题多模型(非同模型多实例)采样实验——若分布显著离散且跨轮稳定(可作独立代理);若聚成窄带(同源问题仍存,「该模型分布」基线可用但需改名);或发现可采样的外部共识源(循环整体消失)。

**Q4(承 think Q4)向量排序的用途界定:展示工具还是评分规则。** 2.6 讲清了 F1 的两种身份:作为**展示用排序**(给人看的画像——ε 宽松,不要求 proper,无激励效应)与作为**评分规则**(进入系统回路,影响 dream 反思强度/agent 配置/自我评价——ε 严格,且必须面对保守化激励:正确性优先+「做错必为负」下,只做高置信判断即可最大化正确率;proper 评分的解法是**对全部预测打分**——不只给敢报的判断打分,漏报与虚报同罚)。那么:① 排序的用途先定,还是先定公式再适应用途?② 若作评分规则,「全部预测打分」的采集面=所有拍板(含未结构化的),成本是否可承受?③ 保守化激励的另一应对=影响力维度放末位(已是拍板)是否足够——注意 think Q4d 的反向提醒:「影响力是错误值的放大器,放末位=高影响错误仅靠正确性防护」——正确性防护(proper 分)的强度是否被视为对高影响错误的充分防线?④ 子判断等价论证(拍板附件)在三个失效面(2.7)下是否需要预注册分解才可证伪(误区六)?
改变判断的证据:试算历史 6 个 judgment——若结构化后可回填 M/p/D/y 的比例高(展示用途立即可用);若历史判断大半无法结构化(评分规则用途的采集成本显形);或发现「只给敢报判断打分」的历史数据中高置信判断占比异常(保守化激励已在发生的证据)。

**Q5(承 think Q5)5-job 窗口=采集单位还是 epoch;D10 撤销条件预注册。** 2.6(r2 2.5/2.6)讲清了数量级:GJP 口径每人每期数十~上百条命题,rick 当前密度低 1–2 个数量级;5 job≠5 判断(一个 job 可能零可归因判断);SCD 因果推断需 ABAB≥4 相位(≥20 job 一循环)。那么:① 接受 think 的降级方案否——5-job 窗口=**采集单位**(dream 每 5 job 跑一次,回收到期判断),epoch=**月或季**(跨窗聚合出校准曲线/赔率和的趋势读数,每档≥10 条的读数约束)?② 若接受,epoch 口径定月还是季(取决于判断密度的现实:若月均可归因判断<10,校准曲线读数须到季)?③ D10 撤销条件是否随本轮裁决一并**预注册**(think 门禁观察 1:裁决树近乎单路,撤销条件应前置——两次反转已发生,第三次决策若无预注册,撤销又要靠下一个「感觉不对」)?撤销条件的候选形态:时间型(如「X 月内 dsh rc 节奏破坏 rick 等价层 N 次」)/事件型(「路线图出现 dsh 独有结构需求且 pi 无等价钩子路径」)/度量型(「判断力度量显示 agent 侧指标系统性退化且归因到 runtime 层」)。
改变判断的证据:清点近 3 个 dream 窗口的实际可归因判断数——≥5/窗且难度可标注(5-job 作 epoch 勉强成立);<5/窗(降级为采集单位的必要性坐实,epoch 须月/季)。撤销条件:human 若能写出「什么证据出现我会承认这次裁决错了」的具体形态(预注册成立);写不出(说明撤销条件在当前信息下无法预注册,须记为已知缺口)。

**Q6(承门禁观察 3)机制增殖快于验证:每个新机制配小型校准实验吗。** r2→r3 的轨迹(think 门禁观察 3):每个开放问题都被回答为**新机制**——多 subagent 共识基线/反共识量化系数/固定 5-job 窗口/向量排序公式/四字段拍板格式——**无一先过证伪实验**。这与本轮反复出现的领域教训同构:postmortem 0001(178 绿灯单测=单元验证充分,组合验证缺失)、GJP(方法学先小样本校准再规模化)、遗传编程(大改动存活率 ~19.5%,自改进走小步)。那么:① 每个新机制进入 dream 回路前,是否配一个**小型校准实验**(例:多 subagent 基线→先对 5 个历史命题采样看离散度;反共识系数→先在 10 条已回收判断上试算看区分度;四字段→先回填 3 个历史拍板看结构化成本)?② 还是接受「机制先上、数据后验」(代价:坏机制污染若干 epoch 的数据后才能识别)?③ 校准实验的裁决标准是否与机制同时预注册(避免「实验结果出来再解释」的事后合理化——与误区六同一动作)?
改变判断的证据:任一机制的小型实验暴露出乎意料的行为(校准实验的必要性实证);或全部机制试算后表现符合预期(「先上后验」的成本实证为低);或历史数据回填显示某机制根本无数据可用(该机制在被验证前已死,实验省下了它的运行成本)。
