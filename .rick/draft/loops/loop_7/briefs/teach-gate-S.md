## 一、发生了什么

**human 在 S 阶段给出了四个回答**（judgment 原话转述）：
1. **双 runtime 都要**：CLI 用 pi、web UI 用 dsh——理由：「可将功能迭代成本降到最低」。

**为什么触发批判门禁**：四个回答都是判断性承诺而非事实陈述，各自隐含未经检验的前提。think 门禁把它们拆成 top-5 隐含前提问题（Q1 穷举单测数学边界 / Q2 双 runtime 等价检验机制 / Q3 可量化指标与双循环兼容 / Q4 benchmark 归因 / Q5 成本时序），并给出门禁观察；human 索要的 benchmark 调研（research-extra）同时完成。本简报把两者综合成一份材料。

**门禁发现的核心：四个回答相互构成张力**：
- **张力一（数学边界）**：回答 3 说「spec 可被单测器穷举描述」。但语义等价不可判定、单测是抽样——「穷举」只对有限输入空间成立；可穷举的 spec 即成实现描述，与「runtime 无关」自相矛盾（2.1 详述）。
- **张力二（等价 vs 成本最低）**：回答 1 的理由是「成本最低」，但双 runtime 意味着每新功能两套方言实现并保持行为一致——成本翻倍且复利，除非回答 3 的 spec 可验证层成立（2.2 详述）。
- **张力三（三角结构）**：回答 2 要可量化度量、回答 3 要 spec 可验证、回答 1 要双 runtime——三者构成三角：**spec 可验证性是唯一把「双 runtime」从「两倍成本」变成「spec 的两个实现（反而简化）」的支点**，却恰是三者中唯一没有任何实验验证的环节。门禁建议：该实验列为 gate 通过前置，或明确挂起。[think-gate-S 门禁观察]
- **决策变更事实**：回答 1 实质推翻 loop_6 已决事项「单一 runtime=pi」——这是决策变更，不是复核；judgment 应记录变更理由与撤销条件。[think-gate-S 门禁观察]

**benchmark 调研的顶线结论**（research-extra）：2026-08 时点「哪个最难/最代表」社区无共识；harness 方差≥模型方差已有多个独立量化证据；SWE-bench Verified 已退役、Pro 被审计出约 30% broken——benchmark 分数是易腐品（2.4 详述）。

## 二、这个领域的知识是什么样子

### 2.1 判断性问题的本质：为什么「穷举单测」数学上不可行

**先讲透「语义等价」为什么不可判定。** 判断两个程序（或两个 runtime 的行为）「等价」，意思是：对任意输入，它们的可观察行为一致。Rice 定理（计算理论核心定理）说：**任何非平凡的程序语义性质都不可判定**——不存在一个算法能对任意程序回答「它满足性质 P 吗」。等价性是语义性质，「程序满足 spec S」也是。所以「自动验证任意 spec」在一般情形下没有算法——这不是工程还没做到，是数学证明做不到。[标准计算理论结论，Sipser《Introduction to the Theory of Computation》第 5 章]

**单测为什么只是抽样。** 测试集 T 是输入空间的一个有限子集。「T 全过」只证明「在这批样本上行为一致」，不证明全空间一致。语句覆盖/分支覆盖/变异测试都在逼近「覆盖更多样本」，但不改变抽样本质——Dijkstra：Testing shows the presence of bugs, not their absence。[EWD249《Notes on Structured Programming》/ EWD340《The Humble Programmer》]

**「穷举」成立的条件**：样本可以趋近完备，但完备只在**输入空间有限**时可达。有限状态机、白名单、确定性 shell 检查（rick 的 gates hook 就是这一类）——这些领域穷举成立，因为状态空间可枚举。[本地代码 .rick/ 的 rick-gates hook 为确定性脚本]

**为什么「可穷举的 spec」必然成为实现描述。** 一个 spec 若细到能穷举所有行为——对每个输入给出精确输出——那它本身就完整描述了程序行为，等价于一个实现，只是换了一种语言书写。它不再「无关 runtime」，恰恰相反它绑定一切细节。这与「单 spec、多实现、runtime 无关」的目标**自相矛盾**：抽象的 spec 一定省略细节，省略的细节正是不可判定的那部分；可判定的 spec 没有省略细节，也就不是抽象。

**因此「可验证性」是分层光谱，不是全有或全无**（这是知识，不是结论）：
- **低阶/确定性层**：有限空间、可穷举——格式校验、结构检查、exit code、确定性脚本（rick gates hook 已在此层）。
- **高阶/语义层**：行为空间无限——用**高阶定性契约/行为不变式**：不崩溃、超时可控、产物格式合规、监控指标在界内；「等价」退化为「对测试集 + 不变式一致」。
- 关键认识：**「可验证」≠「穷举」**。可验证 = 存在一个机器可执行的检查程序，能在有限时间内给出通过/不通过——它检验的是 spec 的**可检查子集**，不是 spec 本身。回答 3 若保留「穷举」字样，需先划定哪些 spec 属于可穷举子集；否则应降级为「可验证子集 + 行为不变式」。

### 2.2 双 runtime 等价的真实成本结构与「不可证伪的承诺」

**成本结构三层**（teach-S 2.4 的量化回顾）：
1. **templates 双方言**：写侧 128 处 pi 触发语法、19/30 文件受染（agent:'xxx' 约 75 处、timeoutMs 27 处）。若 dsh 侧无等价 API，就要维护第二套模板方言，且**复利**——每轮新模板、每个新 agent 名引用，两套都加深。[本地代码 internal/prompt/templates/ 逐文件盘点]
2. **双产物读回**：读侧约 11 处/4 个文件读 `.pi/subagents/artifacts/` 布局与 meta.json/transcript.jsonl 格式——dsh 侧需要等价布局，或写读回适配层。[本地代码盘点]
3. **双行为假设**：缓解项——teach-S 已确认模板对 compaction 语义的假设为 **0 处**，成本结构中最重、最难适配的一层目前是空的。[本地代码盘点，research-S-r2 ①]
（Go 层 seam 是薄的、设计好的，不是成本项。）

**为什么「保持等价」在无检验机制时是不可证伪的承诺。** 科学哲学的**可证伪性**（Popper）：一个断言要有信息量，必须存在一个可想象的观察能否定它。「CLI 用 pi、web UI 用 dsh、两者保持等价」——若没定义：等价指什么（输出格式？行为序列？还是只指「都能干活」）、由谁检验、多久检验一次、检验失败怎么办——那么没有任何观察能否定它，它退化成信仰声明。**不可证伪的承诺不是承诺，是修辞。** [Popper《The Logic of Scientific Discovery》第 4 章（Falsifiability）；对应 think-gate Q2]

**让承诺可证伪需要三要素**：等价性定义 → 检验方法 → 频率与责任人。缺一个都是空头支票。这就是 think-gate Q2 问的：等价由谁检验、成本归谁——research 修订方向两案并存：「templates 分版本」（成本归 rick，维护两套方言）或「dsh 侧适配层」（把兼容负担推给 dsh 侧）。[research 修订方向]

**支点关系（门禁观察的核心）**：若 spec 可验证层成立（2.1 的降级形态），双 runtime 退化为「同一份 spec 的两个具体实现」——等价检验自动化（同一测试集在两个 runtime 上跑），成本结构从「两倍实现」变成「两倍执行」。**这是唯一能把回答 1 从「两倍成本」变成「反而简化」的机制，也是唯一完全未经实验验证的环节**（R7-5：workflowScript→dsh ctx.subagents 等价性未实测）。不对称就在这里：一边有数字（128 处耦合），一边只有信念（spec 可验证）。[think-gate-S 门禁观察 + R7-5]

### 2.3 可量化指标 vs 人机双循环：为什么 proxy 语义必须 human 定义

**先回顾事实（teach-S 2.5 已详述，此处从略引用）**：5 类现成数据源——artifacts meta（296 个文件 = 74 个 runs）、run-history.jsonl、父会话 JSONL、raw log、tasks.json——离线就能算出触发率、启动率、延迟、成功率、成本。[本地数据实测]

**关键观察：这 5 类全是 agent 侧指标。** 它们度量的是「agent 干了什么、花了多少钱、成没成」——没有一个度量「human 投入了什么、反馈了什么」。而回答 2 定义性能为「human-ai 双循环解决实际工程问题」。**只测 agent 侧，「以人为核心」就落空了**——你可以证明 agent 变快变便宜，但无法证明「人机协作的质量」在变好，因为循环的另一半（人的反馈）没有计量。[think-gate Q3]

**为什么 proxy 语义必须 human 定义。** 指标是目标的 proxy；目标是「什么算好」，这是价值判断；测量是「现状是多少」，这是事实。任何指标选择都隐含了「什么重要」的取舍——机器只能测量，不能替 human 决定测什么。具体到 rick：「预期派发数」（什么算「本应派发」）没有机器可读定义，是度量落地的唯一工程前置——这个定义只能 human 给（例如：briefs/*.md 存在即应派发？还是按任务类型分派发规则？）。human 侧候选指标同样需要 human 定语义：干预频率（多少次 human 介入改写）、返工率（多少产物被退回重做）、human 耗时（每轮循环 human 花多久）——这些指标**没有现成数据源**，需要先定义再采集（或从父会话 JSONL 找近似）。[think-gate Q3 + teach-S 2.5]

### 2.4 benchmark 测评的第一性原理

**benchmark 是什么**：一个固定任务集 + 一套判定规则。分数 = f(harness, model, 配置, 任务子集, effort, 环境)——它是**组合属性**，不是 harness 的属性，也不是 model 的属性（teach-S 2.3 的 TB2.1 82.70 vs 0.51 是这条规则的极端演示：两者甚至不构成同一实验）。

**为什么 harness 方差 ≥ 模型方差（2026 已有多个独立量化证据）**：
- Scaffold Effect（[arXiv 2607.22585]，300 次试验）：固定模型跨 harness，通过率差仅 0-8pp，但 **tokens/已解任务差 40×**；失败指纹与模型无关（Goose 死因 REASON、OpenHands 死因 VERIFY、OpenCode 死因 idle-loop）。
- Binding Constraint Thesis（[arXiv 2605.23950]，ICML 2026）：受控因子实验 harness 方差 18.48 vs 模型方差 2.37 pp²——**7.8 倍**；9 对模型比较中 6 次排名反转；同一模型跨 scaffold 在 SWE-bench Verified Mini 上差 34-48pp。
- Harness-Bench（[arXiv 2605.27922]，5,194 轨迹）：同任务同模型池，harness 分差 23.8pp，效应集中于弱模型 + 工具密集/有状态工作流。
- 教学结论：**「换 runtime 分数就变」不是 bug，是评测的固有结构**。所以评测单元必须从「model」改为「**harness–model 对**」（Position 论文 [arXiv 2606.17799] 的处方：harness-aware 元数据 + 多解形 verifier + 组件级指标：tokens/solved、no-action turns「监督税」、失败向量、恢复率、上下文保持、控制滞后）。[research-extra ③]

**归因陷阱与主场优势**：模型在自己的原生 scaffold 生态里有主场优势（AgencyBench, ACL 2026）——要归因到「方法/编排」的贡献，必须**固定模型 + 固定任务集 + 同 attempt 预算**，只变方法。rick 恰好是 harness（引导程序）不是模型，这个设计可直接套用：同 model、同任务集，「有 rick 方法 vs 无」才是能归因到 rick 的对照。[research-extra ③④]

**SWE-bench Verified 为什么退役**：OpenAI 2026-02 宣布因污染+设计缺陷不再报告（「no longer measures frontier coding capabilities」）；2026-07 审计 Pro 公开集 731 任务约 30% broken（自动管线 27.4%、5 名工程师人工 34.1%），撤回推荐；Artificial Analysis 因可作弊移除。教学：**benchmark 是易腐品**——任务集会被训练数据污染、分数会饱和、厂商会博弈；「最难」是移动靶。[openai.com 两篇原文经镜像核实 + the-decoder 2026-07-09，权威性打折（R7）]

**2026-08 时点「最难/最代表」为什么无共识**：SWE-bench 测「补丁能力」（issue→patch，pass@1 测试判定），TB/Frontier-Bench 测「终端长程操作+工具恢复」——**是不同技能，不是难度阶梯**；Frontier-Bench v0.1（74 任务，顶分 ~34-43%）与 DeepSWE（113 原创任务，判官分歧 1.4% vs Pro 32.4%）是最硬候选；ARC-AGI-3 是难度上限参考（非工程，人类 100% 可解 vs Opus 5 仅 30.16%）；METR time horizon 官方承认近饱和；Verified 退役、TB2.1 饱和于 74-84% 带。[research-extra ②，backgrind.com；ARC-AGI-3 技术报告；arXiv 2607.07946]

**结论性知识**：选哪个 benchmark 之前必须先定「要测什么」——模型能力、方法质量、还是 runtime 差异，三者口径不同（pass@1 / METR time horizon / mean reward / 轨迹质量指标），不能共用一份数据。[research-extra ④]

### 2.5 HITL 主观反馈如何客观化（与 rick human-loop 的对应）

**human 的反馈是主观的，但 2026 已有三条把它客观化的路线（均有量化证据）**：
1. **成对偏好 + Elo 排序**（Computer Agent Arena, ICLR 2026）：2,201 票 / 1,058 用户，正确性为主驱动——把「我觉得 A 比 B 好」变成排序，排序变成 Elo 分。局限：需要真实用户规模化。
2. **开放反馈 → 指标诱导**（AutoLibra, ICLR 2026）：80 条轨迹即可把自由文本反馈诱导成可优化指标，3 阶段成功率 +20%。局限：依赖 LLM 理解反馈。
3. **模拟用户 + rubric 自动评测**（AgencyBench, ACL 2026 的 user-sim；LH-Bench [arXiv 2603.22744] 的专家 rubric 使 judge 一致性 κ 0.46→0.60、结构化反馈恢复 70.3% 执行错误）：绕开 HITL 的扩展性瓶颈。局限：判分仍依赖 LLM，真实人类验证规模小、人群偏差存在。[research-extra ③]

**human 参与度本身是可测设计变量**（HAS-Bench, [arXiv 2607.04329]，397 任务）：5 级 agency × 3 通道——A3 平等伙伴 vs 全自动 A1：Pass@1 +8.4、安全率 +26.9，可恢复 65.4% 自主失败；但 A3→A4 边际递减（救 27 破 13），弱模型 ≈0 增益——**人类参与收益非单调**，不是「越多越好」。[research-extra ③]

**与 rick 的对应（事实层）**：harness 评测范式里的「监督税」（no-action turns）与控制滞后恰是 rick human-loop 的目标变量；AutoLibra 式指标诱导可直接处理 rick 的 draft 记录；HAS-Bench 的「参与度可配置」对应回答 2 的「human-ai 双循环」——双循环不是口号，它有一组可测变量（参与度、监督税、恢复率）。[research-extra ③④]

### 2.6 常见误区

**误区一：把 benchmark 分数当能力属性。** 分数属于 harness×model×配置的组合（2.4 节）——「dsh 82.70」不是 dsh 的能力，「某模型 96%」也不是模型单独的能力；换 harness 排名可以反转 6 次（Binding Constraint 数据）。正确的读法永远是「某 harness 上的某模型在某配置下得了多少分」。

**误区二：把「可验证」当「穷举」。** 测试是抽样，「全过」≠「等价」；可穷举的 spec 即成实现描述（2.1 节）。「可验证」的正确定义是「存在机器可执行的检查程序」，它检验 spec 的可检查子集——低阶可穷举、高阶只能契约。把「可验证」当「穷举」会让承诺看起来比实际强一个量级，这是本轮最危险的认知偏差之一：它支撑着回答 3，而回答 3 是三角张力的支点。

**误区三：把双 runtime 当免费。** 「CLI pi + web UI dsh」不是「两个界面共享一个后端」，而是「每新功能 ×2 实现 + 永远存在的等价检验义务」——除非 spec 层成立，把「两倍实现」变成「两倍执行」（2.2 节）。「都要」不是零成本决策，是**成本转移决策**：把成本从「单 runtime 的损失」转移到「双方言维护 + 等价检验」，转移是否划算取决于 spec 层是否成立——而它未经验证。另外注意：web UI 用 dsh 的理由（dsh 自托管 web）与 CLI 用 pi 的理由（生态存量）是**两类不同需求**，放在同一个「等价」框架下时，等价义务由谁承担需要单独回答。

## 三、启发式追问

以下追问建立在上面已讲清的知识之上（2.1-2.6），每条附「改变判断的证据」——标明什么证据出现时，该问题应被重新掂量。承接 think-gate top-5，以教师方式重组：

**Q1（穷举单测的边界怎么定）**：2.1 节已讲：语义等价不可判定、单测是抽样、可穷举的 spec 即成实现。那么回答 3 的「spec 单测穷举可验证」要保留，就必须先划界——哪些 spec 属于可穷举子集（确定性、有限空间，如产物格式、流程纪律、gates 类检查），哪些只能降级为高阶契约（行为不变式、监控指标界）？「runtime 无关」的承诺是否也随之收窄为「可验证子集无关」？——划界本身就是一个待拍板的规格任务。
改变判断的证据：小规模 spec→等价重实现实验成功（用 spec 重建 rick 某模块并过功能验收）；或对穷举边界给出形式化论证（哪类 spec 可穷举、哪类只能契约）。

**Q2（双 runtime 等价由谁检验、成本归谁）**：2.2 节已讲：无检验机制的「保持等价」是不可证伪的承诺；成本三层结构里行为假设层目前是空的（唯一缓解项）。那么：等价性定义、检验方法、检验频率、责任人——四项由谁定？成本归谁（templates 分版本 = rick 维护两套方言；dsh 侧适配层 = 把兼容负担推给 dsh 侧；两案已在 research 修订方向里）？
改变判断的证据：R7-5 spike 实测 workflowScript 在 dsh 侧等价可用；或 human 给出等价性检验机制的操作化定义。

**Q3（可量化指标选哪个口径、proxy 语义是什么）**：2.3 节已讲：5 类数据源全是 agent 侧，human 侧指标无现成数据源；proxy 语义是价值判断、必须 human 定义。那么第一个落地的指标是 agent 侧（触发率/延迟/成本——离线可算，但测不到「以人为核心」）还是 human 侧（干预频率/返工率——测得到双循环，但需先定义采集）？「预期派发数」的机器可读定义是什么？
改变判断的证据：human 给出候选 proxy 及语义定义；或度量运行后发现 agent 侧指标与主观感受背离（说明 proxy 选错了方向）。

**Q4（先度量后支持，还是先支持后度量）**：2.2+2.4 节已讲：双 runtime 成本复利，而 dsh 的性能理由无度量支撑（受控对比不存在、基线未运行）。那么：在 R7-4 度量基线跑出来之前支持 dsh，是在什么证据上做决定？「先支持」若成立，撤销条件是什么（什么数字出现就回退）？R7-4（度量脚本）与 R7-5（dsh spike）哪个先做？
改变判断的证据：R7-4 运行后定位瓶颈确在 runtime 层；或双方言维护工作量被实际核算（不再是估计）。

**Q5（benchmark 用途：验证 rick 方法，还是 agent 能力基线）**：2.4 节已讲：分数是 harness-model 组合属性；归因需要对照设计（同 model 同任务集 ±方法）；rick 是 harness 不是模型——它站在 pi 之上，与 pi/dsh 不在同一层。那么 benchmark 要回答的问题到底是「rick 的方法/编排是否有效」（需要对照实验设计）还是「选哪个 runtime」（需要 harness 级对比）还是「agent 能力基线」（只需固定配置跑分，不做归因）？三个用途对应三种完全不同的评测设计，不能共用一份数据。
改变判断的证据：出现同 model 同任务集「有 rick 方法 vs 无」对照数据；或 human 明确 benchmark 用途是「agent 能力基线」（则归因问题关闭）。

**门禁观察补充追问（决策变更记录）**：回答 1 推翻 loop_6「单一 runtime=pi」，judgment 应记录变更理由与撤销条件——「web UI 用 dsh」这个选择的撤销条件是什么（dsh 1.0 未至？Web UI 未落地？等价检验失败？）？
改变判断的证据：human 给出撤销条件清单。

## 四、延伸学习指导

以下材料按「读完你能判断什么」挑选，分四组。每项附一行为什么读。

**benchmark 方法论（对应 2.4 节）**
1. Scaffold Effect（[arXiv 2607.22585]）——为什么读：harness 方差≥模型方差的第一手量化证据（通过率差 0-8pp 但 tokens 差 40×、失败指纹与模型无关），是「分数属于 harness-model 对」的核心论据。
2. Binding Constraint Thesis（[arXiv 2605.23950]，ICML 2026）——为什么读：受控因子实验证明 harness 效应 7.8× 大于模型效应、排名可反转——判断「benchmark 能/不能回答什么」必读。
3. Position 论文（[arXiv 2606.17799]）——为什么读：评测单元改为 harness-model 对的完整处方（harness-aware 元数据、多解形 verifier、组件级指标清单）——rick 若做 harness 级对比，这是施工图。
4. Harness-Bench（[arXiv 2605.27922]）——为什么读：5,194 轨迹证明 harness 分差 23.8pp 且集中于弱模型+工具密集场景——设计对比实验的样本与模型选择时用。
5. OpenAI 关于 SWE-bench Verified 退役的公告（openai.com，经镜像核实）+ the-decoder 2026-07-09 对 Pro 审计的报道——为什么读：理解 benchmark 的污染-饱和-博弈生命周期，把「最难」当移动靶而不是常量。

**可验证性哲学（对应 2.1 节）**
6. Rice 定理——标准计算理论教材（Sipser《Introduction to the Theory of Computation》第 5 章）——为什么读：语义等价不可判定的严格证明，是「穷举单测数学不可行」的根；读完你能自己判断哪些 spec 属于可穷举子集。
7. Popper《The Logic of Scientific Discovery》第 4 章（Falsifiability）——为什么读：把「不可证伪的承诺不是承诺」讲成原则——给「保持等价」设计检验机制、审阅任何 future 承诺时用。
8. Dijkstra EWD249/EWD340（「Testing shows the presence of bugs, not their absence」出处）——为什么读：一句话点破「全过」≠「等价」，作为 2.1 节的直觉锚点。

**指标设计（对应 2.3 节）**
9. Douglas Hubbard《How to Measure Anything》第 1-3 章——为什么读：测量 = 不确定度减少、用廉价既有观察替代昂贵埋点的方法论；回答 2 的「可量化度量」与「预期派发数」定义问题都在射程内。
10. Goodhart 定律（Strathern 表述：「When a measure becomes a target, it ceases to be a good measure」）——为什么读：proxy 一旦成为目标就会被博弈——设计 human 侧指标时的警告，也是 2.4 节「benchmark 是易腐品」的一般化。

**HITL 评测（对应 2.5 节）**
11. Computer Agent Arena（ICLR 2026）——为什么读：成对偏好+Elo 的实证（2,201 票/1,058 用户），是「主观反馈 → 排序 → 分数」的完整案例。
12. AutoLibra（ICLR 2026）——为什么读：开放反馈→指标诱导（80 条轨迹即可），rick 的 draft 记录可直接对标。
13. AgencyBench（ACL 2026）——为什么读：模拟用户评测 + 主场优势/归因陷阱，一次读两个概念。
14. LH-Bench（[arXiv 2603.22744]）——为什么读：专家 rubric 如何提升 judge 一致性（κ 0.46→0.60），为「若用 LLM 判分」做质量预期。
15. HAS-Bench（[arXiv 2607.04329]）——为什么读：人类参与度是可测设计变量、A3 最优且收益非单调——回答 2 的「双循环」若要量化，这是最直接的方法论参照。
