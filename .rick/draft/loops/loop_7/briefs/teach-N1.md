## ② 这个领域的知识是什么样子

### 2.1 系统论描述符：给系统画一张完整的地图

第一性原理：要谈一个系统的矛盾，先得能把系统**完整地描述**出来。描述符就是为此设计的观看框架，五问——**node**（系统里有哪些组件）、**input/output**（系统与环境交换什么）、**inner**（组件内部如何变化）、**edge**（组件之间是什么关系）。

这个框架的价值不在「列清单」，而在强迫你回答三个容易混过去的问题：

1. **什么在系统内、什么在系统外**（边界不是地图上的线，是「哪些变化你要负责对冲」的划分）；
2. **谁对谁有依赖**（edge 不是「有连接」，是「一方变化时另一方承压」）；
3. **交换的方向与义务**（input/output 不是中性流量，每一笔交换背后都隐含「对方维持某种行为」的假设）。

rick 系统将在 2.1.1 用 node 清单完整刻画。在那之前先交代本简报通用的一个概念工具——契约角色语言：research-N1 不用技术术语（服务/模块/进程）描述依赖，而用**制度语言**（缔约方、履约者、缔约对方、转包方）。为什么这样描述有力量：技术描述告诉你「A 调用 B」；契约描述额外告诉你**A 对 B 有什么权利、B 对 A 承担什么义务、谁有权单方修改这段关系**。后两问正是 loop_7 视角（契约/制度）的立足点。

本节结构：2.1.1 九类节点与契约角色；2.1.2 最关键事实「边界切开契约」；2.1.3 名义契约面 vs 真实契约面。2.2 逐一讲透八种矛盾状态。2.3 稳态跃迁控制学。

#### 2.1.1 九类节点与契约角色

rick 在描述符框架下的完整刻画（来源：research-N1 ①，全部可溯 internal/ 代码与 .rick/ 实测）：

| 节点 | 契约角色 | 一句话定位 |
|---|---|---|
| human | 缔约方+巡检终审者 | 系统的判断功能物理上由 human 实现 |
| rick agent 层（internal/ 七包） | 履约者 | cmd/handler/builder/prompt/env/runtime/workspace |
| pi runtime | 缔约对方 | 契约物=12 钩子+扩展事件；主循环结构固有不可替换 |
| templates | 履约工具（方法层载体） | 128 处 pi 触发方言，最大耦合面，非中立层 |
| sense loop | parent 编排者+think/research/exporter 三 agent | 5 阶段四段链+重试/回流，单写者文件隔离 |
| dream/loop 机制 | 履约监测（部分） | 5 job 窗口+判断回收 X5+dream 日志；巡检/度量为规划中 |
| human-loop | 判断记录器 | judgment.md 逐条 human 原话 |
| .rick/ 形态 | 系统记忆 | domain/（12 文件，pi-runtime.md=协议雏形）、draft/loops、jobs、skills、dream、RFC |
| 第三方扩展 pi-subagents/pi-web-access | 转包方 | fanout 与 web 访问依赖；worker/reviewer/researcher 为其内置名 |

三个角色需要讲透，因为后面的矛盾态全部建立在这三组关系上：

**human 是缔约方+巡检终审者**。human 与 agent 之间是**主契约**：human 义务=判断+终审+反共识基准；agent 义务=调研/教学/不替 human 决策（载体=human-loop judgment.md+dream 回收 X5）。注意 research-N1 的一个关键定性（事实）：human 是**系统组件而非外部评测者**——benchmark=human+agent。这个定性的分量在于：human 的响应速度从此是系统的**设计参数**，不是可以假装恒定的环境常数——M1、M3 两个矛盾态都从这里生长出来。

**pi 是缔约对方**。agent 与 pi 之间是**执行契约**：agent 权利=经 12 钩子+扩展事件干预；pi 义务=公开 API 稳定（载体=Runtime seam+templates 方言）。「缔约对方」的准确含义：pi 不是 rick 的下属模块，是一个**有自己意志的主体**——它的义务来自它自己的承诺（npm 版本纪律），而承诺的内容可以被它自己单方面修改。rick 与 pi 之间不存在任何 rick 有发言权的治理机构。

**第三方扩展是转包方**。pi-subagents/pi-web-access 的上游作者对 rick **没有任何义务约束**（research-N1 ③单列的第三方边脆弱性）。「转包」的含义：你的履约能力依赖一个与你没有契约关系的人的持续配合——他改接口、弃坑、改变行为模式，你都没有追索权。八态中没有它的独立位置，这一点留到 ③ 启发式追问再回来。

#### 2.1.2 最关键的事实：边界切开契约

research-N1 ④有一条加粗结论，值得当作理解整个 loop_7 的钥匙：

> **pi runtime 在系统边界内，pi 的意思机关（社区决策权）在边界外。**

用类比讲清楚这句话的力量：你租下一间店面做生意——店里的水电线路（runtime 代码）确实归你用，运行在你的机器上、你的进程里；但房东（pi 社区）不是你的家人：房东可以修改租约条款（发布新版本）、可以在你不知情时改造整栋楼（变更钩子语义），而你对租约内容没有投票权。你的生意的稳定性，建立在「房东恰好讲信用」这个你无法执行的假设之上。

由此得出 research-N1 的结构性判断（事实，非观点）：**契约漂移不是偶发事故，是结构性产物**——缔约对方坐在你的系统内部，同时保有单方改约的自由。「结构性」三个字的含义：不存在一劳永逸的修复，只有持续对冲（这正是协议清单巡检这个规划中组件的全部存在理由）。

顺着这个事实还有一个容易被忽略的推论（think-N1 ①的假设分析）：「契约漂移只能持续巡检对冲」隐含一个代价——**巡检义务是对 human 终审带宽的永久征税承诺**。漂移在结构上不可避免→巡检必须永远在岗→每份 diff 都要有人裁决→这个「有人」只能是 human。这就是 M1 的完整生成链：一个结构性事实（边界切开契约）经过两次推导（漂移不可避免→巡检永久化）变成对 human 时间的永久索取。

#### 2.1.3 名义契约面 vs 真实契约面

rick 与 pi 之间存在**两个大小相差一个数量级的契约面**——这是理解「协议清单」为什么难的第一步：

- **名义契约面 = 12 钩子封闭清单**（research-extra-3 源码考古全表）：steering、context 转换、模型与轮次、工具拦截、终止、流式、并行策略等共 12 面，外加扩展事件。这是 pi **公开承诺**的接口面——可枚举、有文档、语义相对稳定。主循环结构（事件序列/终止组合/while 拓扑）**固有不可替换**，连钩子都够不着它。
- **真实契约面 = 128 处 pi 触发方言**（research-S-r2 统计）：`agent:'xxx'`≈75 处、`timeoutMs` 27 处、散布于 30 个 prompt/skill 文件中的 19 个。这是 rick **事实上依赖 pi 行为**的握手点——弥散、无文档、随模板编辑自然膨胀。

两者关系的教学：钩子清单像合同里的**明示条款**，方言实例像交易双方多年形成的**默示惯例**。合同纠纷里真正致命的往往是后者——明示条款双方都盯着，默示惯例没有清单，某天对方行为一变，你甚至说不清自己损失了什么、损失在哪一行。

常见误区：把「读了钩子文档」当成「理解了契约面」。协议清单巡检（控制手段 1）之所以必须覆盖 128 处方言而不只是 12 钩子，原因就在这里。think-N1 的原话值得引用：「枚举对象自身在膨胀」——清单固化的对象是**方言全集**，且清单本身需要维护（模板每加一处 agent:'xxx'，契约面就宽一格，除非清单同步更新）。

### 2.2 八种矛盾状态逐一讲透

先建立概念工具，否则下面八个都会被误读成 bug 清单。

**「矛盾」与「问题」的区别（第一性原理）**。问题=存在一个坏东西，消除它系统变好（有解，解=删除）。矛盾=**两股都必要的力量互相拉扯**，消除任何一方都造成损失。测试方法：想象彻底消灭其中一侧，看系统是变好了还是残废了——巡检完备性（M1 的 A 侧）消灭后漂移无人看见；human 终审（M1 的 B 侧）消灭后 rick 失去判断基准。两边都是系统的必要器官，它们却在争夺同一份资源。矛盾不能被「解决」，只能被**稳态机制**对冲——让两股力量在某个平衡点长期共存。所以下面每个矛盾态都按同一结构讲：**两股力量→张力来源→稳态机制（现状如何共存）→失衡后果（稳态失守会怎样）**。

---

**M1 巡检完备性 vs human 终审带宽**

- **两股力量**：A=巡检完备性要求——E 拍板明确 domain 清单+dream 巡检「最终一致」，即巡检要捕获 rick-pi **全部**语义对齐点，一个不漏。B=human 终审带宽——巡检产出的每份 diff 都需要 human 裁决，而 human 判断周期以天计（judgment 七轮拍板跨 4 天、全部手动文字；research-N1/think-N1 共同引用的事实）。
- **张力来源**：完备性要求以「human 审得完」为隐含前提；终审带宽以「diff 不太多」为隐含前提。两个前提互相指对方兜底，谁也不为对方负责。
- **稳态机制**：清单尚「规划中」，巡检义务未生效；同时 pi 锁版本冻结了漂移源——**版本锁定代偿清单缺位**：没有漂移就没有 diff，没有 diff 就不需要裁决。
- **失衡后果**：一旦清单落地+版本受控解锁，若 diff 生产率持续高于裁决速度，终审退化成 rubber stamp（只盖章不看），误判风险记录变成只进不出的**风险黑洞**。
- **失衡检验**（消灭一侧会怎样）：消灭 A 侧（不做完备巡检）→漂移在默示惯例层静默累积（回到 2.1.3 的误区）；消灭 B 侧（终审自动化）→「human=系统组件」的设计前提被推翻，误判无人负责。

**M2 上下文主义表达力 vs 代码级效果不可达**

- **两股力量**：A=上下文主义——human 原话「一切效果可通过改变上下文达成」（E 阶段拍板；human 自标「不一定正确但符合目标」，即这是**信仰而非验证过的命题**——事实与观点的区分在此处至关重要）。B=源码事实——pi 的 12 钩子封闭+主循环结构固有不可替换（research-extra-3 源码考古，事实）。
- **张力来源**：同一个 human 的判断记录里并存两个方向——E 的上下文主义信仰，与 S 门禁 3 的「长期需改 loop 时 fork 或自研」。层 B≡Y1 触发器（12 钩子外骨架替换→全池重评：fork/自研/新 runtime）正是为 B 侧预留的出口——注意：预留出口不等于张力消失，只等于张力有了引爆条件。
- **稳态机制**：loop 被重定义为「行为模式循环（提示词实现）」——系统级 loop 需求被移出视野；短期无 loop 定制需求（think-N1 归纳，**观点非事实**）。
- **失衡后果**：上下文主义的失败协议是**空的**（「暂不定义失败分流」）——某天效果只能靠改 loop 达成时，没有中间分流路径，直接触发 Y1 全池重评。矛盾平时不可见，爆发时成本最大。

---

**M3 双循环节奏不对称：agent 迭代速度 vs human 判断速度**

- **两股力量**：A=agent 层分钟-小时级（timeoutMs 60min、5 阶段四段链、重试/回流上限——全部代码事实）。B=human 判断以天计——系统的**唯一不可加速组件**（think-N1 ②；judgment 时间戳为证）。
- **张力来源**：双循环定位本身（S 门禁 Q2 原话）——内循环（agent 推进）快、外循环（human 判断）慢是**设计使然，不是故障**。设计文档里这是特性（快慢分离让系统在 human 缺席时仍能产出），运行时它就是节拍差。
- **稳态机制**：单写者文件隔离让 agent 在 human 缺席时照常推进，判断积压**不阻塞产出**——但阻塞 X5 判断回收（判断没有回收就没有度量的原料）。
- **失衡后果**：判断积压→度量数据饥饿→Y4 周环比无数据→三维统计值永远小样本。注意这条失衡链与 M5 会**合流**——M3 的失衡是 M5 爆发的前提条件之一；单看 M3 觉得无害（产出没停），沿着它的失衡链走到头就是 M5 的死法。
- **失衡检验**：消灭 A 侧（agent 降速等 human）→产出退化为 human 带宽的函数，双循环设计作废；消灭 B 侧（判断自动化）→回到 M1 的同一深渊。

**M4 契约稳定性（锁版本）vs 红皇后环境（上游持续进化）**

- **两股力量**：A=update-pi 锁版本，冻结 12 钩子契约面，给 rick 一块稳定的执行地基。B=pi 社区+模型厂商+npm 扩展作者持续单方迭代——「红皇后」环境（出自 Lewis Carroll《爱丽丝镜中奇遇》：你必须不停奔跑才能留在原地；对 rick 更残酷的是，「跑」的主动权在别人手里）。
- **张力来源**：2.1.2 讲过的结构性事实——pi 在边界内、决策权在边界外；叠加共享全局安装的卸载连坐风险（npm 包共享全局安装，卸载一个可能伤到另一个，research-N1 ③）。
- **稳态机制**：被动观察——P4 观察哨+benchmark 降级为环境监测项（judgment 拍板），不追红皇后。即：用「不跑」换稳定，用观察哨保证「不跑」是有信息支撑的决定而非昏睡。
- **失衡后果**：锁版本=放弃上游修复（已知 bug 留在身上）；不升级=生态红利衰减（第三方扩展依赖新 API，见 2.1.1 转包方角色）。**两头慢性失血**，且升级成本随锁龄**单调上升**——锁定越久，一次性迁移的跨度越大，最终被迫一次性大迁移（那时 M4 从慢性病变成急症）。
- **失衡检验**：消灭 A 侧（随时追新）→漂移不可控，M1 直接爆仓；消灭 B 侧（上游冻结）→这不由 rick 决定，恰恰是 M4 成立的原因——B 侧不是 rick 的选择，是环境属性。

---

**M5 度量体系完备冲动 vs 判断密度稀疏现实**

- **两股力量**：A=度量机器的完备设计——三维向量（正确率>赔率>影响力）独立可微+中位数/max/均值+周/月环比+X3/Y5 并行冲突上报+X8 四字段（全部为 judgment 拍板的规划中组件，research-N1 ⑤）。B=判断是**稀疏事件**——现存七轮拍板数十条，按 5 job 窗口（N4）回收。
- **张力来源**：Y4「human 判断次数应该会越来越多」是**预期而非事实**（think-N1 ②明确标注）；设计完备度远大于数据生产速度。类比：一台高精度质谱仪已经设计完毕，但样品每周只来几滴。
- **稳态机制**：度量全部规划中——纸面完备零运行成本；且判断日志已存在、理论上可离线回补计算（research-N1 ②）。但注意 think-N1 ①戳破的一个隐含假设：「无需新埋点」隐含散文日志已含判断→结果映射的结构化字段——**未验证**，散文不可直接计算（这是事实与假设必须分开的又一处）。
- **失衡后果**：度量上线后密度不足→统计值噪声>信号→三维排序无判别力→X4「独立优化」无梯度可循→**度量空转**。仪器越精密，空转时越浪费。
- **失衡检验**：消灭 A 侧（不做度量）→判断力提升失去反馈回路，X3/X4/X8 全部拍板落空；消灭 B 侧（强制高频判断）→判断质量被产量挤压，与系统「human 原话、不替 human 决策」的纪律冲突。

**M6 生态复用验证红利 vs 自生成自由度（human 的自我分歧）**

- **两股力量**：A=短期路线「基于 pi 演进」，复用 pi 的 cli+社区+第三方扩展生态（judgment 拍板）。B=长期怀疑——S 门禁 3 原话「开源组件复用提升效率的假设可能不成立……完全可以自己生成扩展，最彻底激进的自改进路线」。
- **张力来源**：这个矛盾态的特殊性在于，它不是系统内两股力量的拉扯，而是**同一个 human 在同一份文件里的两向判断并存**（think-N1 把它列为矛盾态的理由）。两向判断各自成理：A 侧有生态红利+验证成本低的当下优势；B 侧有 128 处方言维护负担+缔约对方不可治理的长期担忧。分歧本身没有裁决机制——Y1 撤销条件（pi 扩展无法满足需求）依赖的需求信号从不主动收集（Y8「纯观察即可」拍板）。
- **稳态机制**：Y1 触发器+层 B 预留，悬置；Y3 反驳「基于已存在扩展语义级对齐，验证成本可控」（**观点**）。
- **失衡后果**：两个方向都有损失敞口——若自生成成本<复用+对齐成本，128 处方言维护是负资产；反之自研是幻觉。而 Y8 的「纯观察」意味着裁决数据**永远不主动收集**，分歧永悬：既不确认也不证伪，机会成本无法核算。悬置不是免费的，悬置的代价是无法定价。
- **失衡检验**：消灭 A 侧（立即自研）→失去生态验证红利，重走 M8 已排除的轮子；消灭 B 侧（永久绑定 pi）→M4 的锁死变成永久承诺，Y1 触发器作废。

**M7 度量自指：判断力提升目标 vs 度量反噬判断行为（古德哈特）**

- **两股力量**：A=度量的目的——提升 human 判断力，三维得分反馈形成学习回路。B=被度量的 human 会改变行为——古德哈特定律（Goodhart's Law：「当一个度量变成目标，它就不再是好的度量」）。
- **张力来源**：这个矛盾是**度量系统与被度量对象是同一个人**造成的结构问题：X3 反共识由 human 主观自答「暂时接受」+X4 三维独立优化——两个设计都隐含假设 human 的判断行为在度量面前不变。而一切度量-human 系统的历史经验都指向相反方向。
- **具体反噬路径**（think-N1 ②列举，**推演非事实**）：赔率=共识概率倒数→故意反共识刷赔率；正确率→规避高风险判断（只答有把握的）。两条路径都让得分上升而判断质量下降——分数与它声称度量的东西脱钩，这正是古德哈特定律的机制。
- **稳态机制**：度量规划中，自指回路未闭合，human 看不到自己实时得分——**回路断开本身就是当前的稳态**。
- **失衡后果**：回路闭合后 human 优化得分而非判断质量→反共识成表演→benchmark=human+agent 个性化评价体系失去效度——**度量杀死被度量物**。这是八态中唯一「建成即可能自毁」的矛盾：其他七态的失衡是系统退化，M7 的失衡是评价体系本身失效。控制手段 7（度量开环运行）就是专门为它设计的缓释剂。
- **失衡检验**：消灭 A 侧（不设度量）→判断力提升退回纯直觉积累；消灭 B 侧（human 不看得分）→学习回路断开，度量变成纯档案。

**M8（修正版）dsh 排除的不可逆性 vs 排除依据的时点性**

> **⚠ 事实修正标注**：think-N1 原 M8 称「dsh 崩溃实测请求至今悬置（R7『3 4 5 6 悬置』）」——**有误**。事实（research-extra-4，该调研**已完成**）：dsh（github.com/deepseek-ai/deepseek-harness，2026-08-13 开源，~19 万 star）开源后 13 天观察窗内，插件故障讨论 **≥35 条**（web 检索下限）：**21 无法启动**（典型报错 `plugin tree failed to load`）、**11 部分功能损失**（工具调用全崩/Windows PTY 损坏）、**3 数据损坏**（会话日志不可再加载/会话永久不可恢复）；机制经 **boot 全树事务源码互证**（插件加载失败会拖垮整树启动，含「卸载入口与坏插件同殁」模式）；社区隔离 PoC 落地 fork 分支（franksong2702/recoverable-bundle-failures-poc，commit c601d5a，29 文件改动），**未见官方回应、未转 PR、未合入上游**。以下按修正后事实重写。

- **两股力量**：A=排除的**不可逆性**——dsh 已被终裁排除（「牺牲隔离性的自改进不可取」+E 问 9「dsh 作为运行时也排除」），且排除的架构后果已固化：rick 被 128 处 pi 方言锁定在 pi 上，即使排除依据动摇，迁移成本也已不可逆地垒高。B=依据的**时点性**——35 条是 **13 天窗口内的 web 检索下限**：它既是下限（真实故障只会更多，检索覆盖不全+未发帖用户），又是时点快照（一个 19 万 star 的年轻项目，修复机制完全可能随后出现）；PoC 在 fork 分支未合入，上游是否修复是**开放变量**。
- **张力来源**：排除依据已从「推测」升级为「下限统计支撑」——这是相对原 M8 的实质变化，决策的证据基础**变厚了**。但**不可逆性也在同步加深**：每多一行 pi 方言、每多一个月锁版本，「依据若失效、代价多大」的答案都在变大。证据在变强，退出门槛也在变高，两者在赛跑——这就是「不可逆 vs 时点性」的准确张力。
- **稳态机制**：dsh 不进入任何执行路径，排除与观察（P4 观察哨）互不接触——观察结果不回灌排除决策，两边各自静止。
- **失衡后果**：若 pi 出现同类崩溃（research-extra-4-leaf-4 对照：pi 有崩溃案例但多数获官方修复+降级兜底），或 dsh PoC 被合入并长期验证稳定——排除依据的时点效度被质疑，但架构已锁：正确率维度记负资产，影响不可逆。反方向同样失衡：若 dsh 长期不修而 pi 衰败，排除正确但系统已被锁在衰退的 runtime 上（与 M4 合流）。
- **失衡检验**：消灭 A 侧（重开 dsh）→迁移成本即时兑付+排除决策的严肃性受损；消灭 B 侧（假设依据永久成立）→时点性是数据属性不是选择，恰恰不可消灭——M8 与 M4 同属「B 侧是环境属性」型矛盾。

### 2.3 稳态跃迁控制学：从 A 到 B 怎么走

先教「稳态」这个词的准确含义。矛盾无法消除，但系统并没有天天爆炸——因为存在**代偿机制**在吸收张力。稳态不是「没有矛盾」，而是「矛盾被某种机制按住了」。识别代偿机制是控制学的第一课：它们在系统图纸上通常**不显形**（没人设计「锁版本是为了代偿清单缺位」），但拆除任何一个之前必须知道它现在替谁挡着什么。

**稳态 A（现状）的三个代偿机制**（think-N1 ③）：

1. **锁版本代偿清单缺位**：协议清单不存在，但版本锁死了、没有漂移，巡检义务落空也无后果——M1 被「冻结」按住。
2. **散文代偿结构化**：判断是 judgment.md 里的散文原话，机器不可计算，但 human 读得懂——记录功能由 human 的阅读能力兜底。
3. **规划代偿运行**：度量/巡检都在「规划中」，纸面设计不需要维护成本，也不产出需要兑现的承诺。

**稳态 B（目标）**：协议清单+自动化 diff（dream 巡检）+human 终审（diff+裁决+误判风险记录）+三维度量积累（X5/X8/统计值）。B 不是「修好 A 的 bug」，而是**用运行机制替代代偿机制**——代偿的特点是零显性成本但零能力（锁住的版本不会漂移，但也吸收不了任何上游修复；散文读得懂，但算不出环比），机制的特点是有运行成本但真实工作。

**B 的 8 项控制手段，按依赖顺序**（顺序本身是 think-N1 ③的核心产出；下面讲每步为什么在这个位置）：

1. **清单固化（前提）**——domain/pi-runtime.md 雏形→全量对齐点清单（128 方言+12 钩子）。B 的一切组件（巡检、diff、终审）都以清单为**对象**：没有清单，巡检无物可巡。研究已完成、落盘未完成——一次性考古成本。
2. **判断结构化**——judgment 散文→X8 四字段条目。这是**数据骨架**：巡检的误判率、度量的三维值都从结构化条目计算；历史回填是一次性成本。它必须排在巡检/度量之前，因为后面的组件消费它的输出。
3. **巡检自动化**——dream 增巡检 job（SelectPendingJobs 窗口机制已有），产出只含变化点的结构化 diff——直接控制 M1 的终审带宽：diff 越小，裁决越快。
4. **终审常规化**——误判风险记录必须有出口（定期 dream 复盘），防止 M1 的失衡形态「风险黑洞」：只记录不复盘的档案等于只进不出的负资产账本。
5. **度量冷启动**——明确「N 条判断前只算不比」的降级策略，控制 M5：承认密度稀疏是初期事实，统计值在小样本期不参与排序——仪器开着，但读数标注「校准中」。
6. **版本受控升级**——锁版本→每次升级触发协议巡检，红皇后从被动观察变**受控吸收**，控制 M4 的单调恶化：不追新，但也不让锁龄无限增长。
7. **度量开环运行**——先只记录不反馈（得分延迟揭示），控制 M7：自指回路推迟闭合，直到行为数据攒够、human 对「被度量」这件事本身脱敏。
8. **触发器显式化**——Y1/层 B 条款写入 domain、程序化识别，不靠 human 记忆，压低 M2/M6 的悬置成本：悬置条件若只存在于 human 记忆里，触发时机取决于 human 记得与否。

**跃迁的顺序敏感性（think-N1 ③的核心警告）**：A 的三个代偿机制在 B 建设期必须**逐个解除**，而解除顺序错误会产生比 A 更不稳定的中间态——代偿已撤、机制未建，张力直接裸露：

- 先解锁版本再落清单=**漂移窗口**（没有清单的巡检，漂移无人看见）；
- 先上度量再结构化判断=**数据噪声**（度量机器开动，原料是散文）；
- 先闭自指回路再攒密度=**行为扭曲**（M7 在小样本期就反噬）。

**第一推动问题**：A→B 的建设期本身消耗 human 终审带宽（清单终审、结构化确认、diff 裁决）——即 **M1 在 B 落地之前就已存在**，而 human 判断是系统唯一不可加速组件（M3）。推论（**结构事实，非建议**）：跃迁的第一推动只能是 human 的一次集中投入，系统内没有任何组件能替代这个启动动作——这不是「应该由 human 做」的规范性陈述，而是「只有 human 能做」的拓扑陈述：所有其他节点要么可并行、要么可等待，唯独 human 的判断既不可并行也不可代行。

## ③ 启发式追问（协议三问）

以下问题建立在上述已讲清的知识之上。每条附一行「改变判断的证据」——即什么事实若出现，你的回答会不同。

**问题一：你看到哪两股力量在拉扯？**

M1–M8 中哪一种最贴近你的**体感**？注意「体感」与「分析」的区别：think-N1 从描述符推出八态是分析工作——八态在逻辑上**同等成立**（每个都满足「两股必要力量+失衡检验」）；但哪个矛盾在你的实际使用中真实消耗过你的时间与注意力（终审排队、版本升级纠结、判断积压），只有你知道——分析覆盖不了的地方恰是体感的领地。或者：是否存在 think-N1 未捕获的**第 9 种**？给你一个检查方法（非暗示答案）：回到 2.1.1 的节点-契约角色表，逐一检查每条边的权利义务是否在八态中都有位置——例如**转包方（pi-subagents/pi-web-access）的义务真空**：research-N1 单列了它的脆弱性（上游无义务约束），但八态中没有它独立的矛盾态——这是遗漏，还是它已被 M4 的生态红利侧吸收？
*改变判断的证据：下一轮 dream 复盘中时间消耗的实际分布——哪些矛盾态消耗过真实时间，哪些只存在于分析中。*

**问题二：系统按现状运行 3 年后会怎样？**

不引入新假设，只用 M1–M8 的失衡后果推演。四个候选终局，哪些先到、哪些会合流：

- **判断积压**（M3→M5 链）：判断密度若维持七轮/4 天的斜率，3 年后 judgment 条目到什么量级？够不够统计值脱噪？注意 2.2 中 M3 的提醒——单看 M3 无害（产出没停），沿失衡链走到头就是 M5 的死法。
- **锁版本失血**（M4）：锁龄 3 年时，一次性迁移跨度与生态红利衰减，哪个先越过你愿意支付的阈值？M4 的特殊性：B 侧是环境属性，到达时间不由 rick 控制。
- **度量空转**（M5/M7）：度量若 3 年后才上线，历史散文可回填的比例是多少（think-N1 已标注「无需新埋点」隐含未验证假设）？回填比例不足则冷启动期顺延。
- **风险黑洞**（M1）：误判风险记录若在清单落地后才开始积累，只进不出的存量 3 年后到多大规模？——注意 M1 的当前稳态（版本锁代偿）在 3 年尺度上恰好是 M4 的失血源：**A 的稳态机制本身在给某个终局供血**。
*改变判断的证据：pi 社区实际发版节奏（3 年内钩子语义变更次数）与 human 判断频率的实际轨迹（密度上升还是维持）——两者都是可观测的时间序列。*

**问题三：哪个节点消失，系统会重组？**

候选：human / pi / templates / dream / 判断记录（judgment.md）。契约视角的问法：哪个节点的消失不是「功能缺失」而是**契约结构塌陷**——即剩余节点之间的权利义务关系不再成立？一个辅助区分：有设计出口的消失是**重组**（系统按预案变形），无出口的消失是**塌陷**（关系网解体）。逐个摆出事实（不给结论）：

- **human 消失**：主契约（human↔agent）无缔约方，agent 层失去判断基准与终审——benchmark=human+agent 的等式一边为空；M3 的慢组件消失同时意味着 M1 的终审者消失。
- **pi 消失**：缔约对方不存在，128 处方言瞬间悬空——但 Y1 全池重评（fork/自研/新 runtime）是为这一刻**设计过的出口**。
- **templates 消失**：128 处方言所在的履约工具没了——但方言是 rick 自己写的，模板可从 git 历史重建；契约面随之重建。
- **dream 消失**：监测与判断回收（X5）缺位——但判断记录与 agent 层照常运转，失去的是 A→B 的建设载体（控制手段 3/4/5 的宿主）。
- **判断记录消失**：系统失去全部历史判断，度量与终审的数据骨架归零——但缔约关系本身（human↔agent↔pi）仍然成立，可以重新积累。
*改变判断的证据：对每个候选节点核对 rick 中是否存在已设计的替代路径（Y1 对 pi、X8 结构化对判断记录、git 对 templates）——出口的存在与否是可核查的文档事实，不是判断题。*

## ④ 延伸学习指导

以下材料按本简报涉及的知识域分组。每项附「为什么读/读完你能判断什么」。只说明材料与决策的关系，不替代你的选择。

**系统论**

- Donella Meadows《Thinking in Systems》（中译《系统之美》）。为什么读：stock（存量）/flow（流量）/反馈回路/杠杆点是识别系统行为的通用语法，M1–M8 本质上都是回路结构（M7 是典型的「度量成为目标」回路，M4 是「锁龄→迁移成本→更不敢动」的增强回路）。读完你能判断：稳态 A 的三个代偿里哪些是 stock（缓冲）、哪些是 delay（延迟），以及 B 的 8 项控制手段中哪一项作用在回路结构上、哪一项只是参数调整——这直接关系到问题三的「重组 vs 塌陷」。
- 任一系统动力学教材的「boundary critique」（边界批判）章节。为什么读：2.1.2 的「边界切开契约」不是唯一画法。读完你能判断：把 pi 的决策权划在界外、runtime 划在界内，是当前唯一自洽的切法，还是存在替代切法（例如把「pi 的承诺记录」划入界内、把「pi 的 bug」划在界外）——边界画法不同，同一批事实会推出不同的矛盾态清单。

**控制学**

- W. Ross Ashby《An Introduction to Cybernetics》第 11 章「Requisite Variety」（必要多样性定律：调节器的多样性必须≥被调节系统的多样性，调节才可能）。为什么读：M1 的本质可以一句话重述——pi 漂移的多样性 vs（巡检+终审）的多样性之争；控制手段 1（清单固化）在增加巡检侧多样性，human 终审带宽是多样性瓶颈。读完你能判断：dream 自动巡检（手段 3）是必要组件还是奢侈品——这比「终审带宽不够」的直觉判断多一层结构依据。
