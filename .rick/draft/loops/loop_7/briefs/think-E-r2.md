## 一、事实性模糊消解结果（附证据）

### 消解 1（原问题 4）：pi 扩展能承载 web ui——成立，附生命周期边界

- 扩展=普通 TS 模块经 jiti 载入主进程，无沙箱、与 pi 同权限，node:http 可用（docs/security.md 已核）⇒ 可起 server/监听端口/接外部连接。实证：Firstp1ck/pi-coding-agent-forge 以扩展形态实现 web ui（remote-webui：/remote 开 LAN+PIN 认证+QR 手机接入）。
- 边界：扩展生命周期为**会话级非进程级**——工厂函数禁启 sockets/timers，须 defer 到 session_start；/new /resume /fork /clone 及进程退出均触发 session_shutdown（extensions.md L222-224）⇒ 扩展内 server 只活在「宿主进程+当前会话」。进程级长驻 web ui 的官方路径是 SDK createAgentSession（文档明示 web ui 用例）或 RPC 模式，不是扩展。
- fork 非必要：官方「自扩展无需 fork」+ SDK/扩展/外部语言三架构均有第三方实现（xiaoyc/pi-web-ui、hyperdreamer/pi-webui、官方 @earendil-works/pi-web-ui 组件库等）⇒ Q4 事实链成立，「此路不通回 Y1 重评」担忧解除。残留（R7-1/2，低优先）：第三方成熟度未核；工时成本无公开数据。

### 消解 2（原问题 2 事实子项）：巡检自动化可行性——已澄清，否定结论

- 「LLM 判两份文本语义一致」的日常化自动巡检**无工业先例**：工业 spec 一致性检查全为结构/语法级（Pact matching rules、oasdiff 514 条规则），语义级契约检查仅学术提案无落地。
- 单次判定不可靠：LLM-as-judge 重复评估成对偏好平均 **13.6% 翻转**（29 任务）；SummEval 33–67% 文档存在偏好 3-cycle；human 一致性 κ≈0.46–0.60；可靠化手段（N-of-M 投票/确定性参数）出自评测文献非生产实践。
- 结论：r1 期待的「可测判据先例」未出现，子项以否定方向消解——「语义对齐存在可操作一致性判定方法」无既有实践支撑，判据只能自造（定义权在 human）+自验（指向 X6）。此事实加重下方问题 2。

## 二、需 human 回答的问题（保留判断性 top-3 + Q4 残留小项）

### 问题 1（保留）：loop 重定义是否架空层 B 触发器

**问题**：若「loop=提示词层行为模式」成立，那么也假设了「一切改 loop 需求都可由提示词满足、层 B（12 钩子外骨架替换）触发器永不点亮」——这真的正确吗？新证据补强架空风险：扩展同样改不动系统级结构——只有会话生命周期钩子、无调度控制面，dream 触发时机/job 调度节奏只能由 pi 内核或 fork 改动。即提示词与扩展两层都触不到调度级 loop，这类需求必然以 Y1 形态现身。兼容解读（层 B≡Y1 同一触发器两种表述）与架空解读（调度级需求迟到现身、届时已积累专用性负债）仍需你择一。

**依据**：judgment.md Y2+S 终裁「改 loop 需 fork 源码」原话；research-extra-5 ①（扩展生命周期会话级、禁启后台资源）。

**改变判断的证据**：你确认两词分指且层 B 判据仍指系统级骨架；或出现提示词+扩展均无法承载的调度级需求（架空成事实）。

**性质**：判断性（决定 E 通过条件与问 6 重答方向）。

### 问题 2（更新）：给定「无先例+13.6% 翻转」，「一致」判据与 X6 如何定

**问题**：若「dream 巡检协议清单可达成 rick 与 pi 的最终一致」成立，那么在消解 2 的否定结论下，也假设了「你会自造一套可靠化判据、并愿为协议清单机制补走 X6 实验」——这真的正确吗？你悬置了语义等价（回答 4「随选择 pi 悬置了」），却上马了依赖语义等价判定的巡检机制——悬置与依赖直接矛盾。三路择一：①定义可操作判据（如 N-of-M 投票一致率阈值+spec 单测穷举）且机制走 X6（「新机制发布前需实验」是你已拍板规则，此处正好适用）；②降级 human 终审（巡检只产出 diff 报告，「一致」由你裁决，回到 teach-E 问 7 语义）；③显式接受误判风险并记录在案。

**依据**：回答 4/5 原话；judgment.md X6 拍板；research-extra-5 ③。

**改变判断的证据**：出现工业级语义一致性巡检先例（推翻消解 2）；或你对三路之一显式拍板。

**性质**：判断性（判据定义+X6 走否需你裁决；事实底座已由 research 钉死）。

### 问题 3（保留）：上下文主义的失败模式协议缺失

**问题**：若「一切效果都可通过改变上下文达成」成立，那么也假设了「模型迭代分布漂移无需独立监测、上下文表达力无硬边界」——这真的正确吗？你自评「不一定正确但符合它的目标」是信仰声明，却被用作关闭 P2 警报的理由。新证据再补一刀：扩展的代码级效果（起 server/网络监听）就在 12 钩子能力面内——你的「语义对齐改动点清单」已承认非上下文依赖面存在，「一切」的边界在哪？边界声明需失败协议：上下文达成不了的效果，归扩展面代码、触发 Y1、还是 rick 能力边界外信号？Ashby：无监测的边界等于无边界。

**依据**：回答 2/5 原话；teach-E 问 5/9；research-extra-5 ①（扩展代码级能力面实证）。

**改变判断的证据**：X6 窗口内新旧判断回收一致性显著下降；或你划定显式边界+失败分流规则。

**性质**：判断性（失败协议需你定义；目标一致性不能证明手段有效性）。
