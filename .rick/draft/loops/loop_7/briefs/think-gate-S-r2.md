# think-gate-S-r2 简报

> 阶段:loop_7 S 批判门禁第 2 轮|主题:拍板后复审(spec 降级+runtime 取舍+三维判断度量)|输入:human Q1-Q5 原话+teach-gate-S(D1-D11)+research-S/r2

## 需 human 回答的问题(top-5)

### Q1 「灵活→掌控→性能」因果链:单调性与瓶颈错位
**问题**:若「dsh 更灵活可定制→对 LLM 更绝对掌控→更适合 rick」成立,那么也假设了「掌控度与产出质量单调正相关,且 rick 瓶颈确实在 runtime 掌控不足处」——这真的正确吗?控制收益非单调(HAS-Bench A3→A4 边际递减、弱模型≈0 增益);rick 掌控点(templates/gates/spec)本在 runtime 之上,pi 扩展面(事件拦截/自定义 compaction)或已够用——「替换 agent loop 本身」的增量掌控,rick 哪个功能需要?
**依据**:research-S ④(pi 扩展已含拦截+自定义 compaction);基线未运行、直接对比不存在(S-r2 ③/④)。
**改变判断的证据**:R7-4 基线显示瓶颈在 runtime 层;或路线图列出必须替换 loop/session log 的功能。
**性质**:判断性;子项「pi 能否等价实现」建议 research 澄清。

### Q2 判断→结果归因:dream 真能「回收每个判断的结果」吗
**问题**:若「dream 复盘可回收每个判断的结果、算判断力得分」成立,那么也假设了「判断→结果因果链在无对照、无反事实下可被可靠归因」——这真的正确吗?结果=判断×执行×环境的混杂;dream 归因是 LLM 判别任务(κ≈0.46 噪声);多数判断无「不判断会怎样」的反事实。
**依据**:research-extra ③(归因需对照;专家 rubric 才到 κ 0.60);judgment 无结果记录字段。
**改变判断的证据**:试评历史 judgment:归因一致率高、或可划定「有验收信号的判断」子集,则对该子集成立。
**性质**:判断性(可归因子集=设计选择);「历史判断记录现状」建议 research 清点。

### Q3 反共识维度:共识基线缺失,权重/估值模型悬空
**问题**:若「赔率=反共识,代表判断独一无二性,是价值正向维度」成立,那么也假设了「存在可采样的共识基线,且能区分孤独的正确与孤独的错误」——这真的正确吗?rick 判断是 n=1 决策,无判断者群体,「与多少人不同」无数据源;未来估值概率模型由谁跑、数据从哪来未指定;三维权重谁定——得分一旦成为目标,Goodhart 化几乎必然。
**依据**:human 原话;Strathern(measure becomes target 即失效)。
**改变判断的证据**:可操作共识基线候选:以 agent 初步建议为「共识」(human 偏离且正确=反共识价值,human-loop 可测);否则删或降权。
**性质**:判断性(维度取舍+权重);操作化候选可 research 验证。

### Q4 「度量在 dream 中完成」:样本量与数据可得性
**问题**:若「度量在 dream 中完成」成立,那么也假设了「dream 频率×可归因判断数足以积累统计可判读样本,且数据可采集」——这真的正确吗?单 human 序列需每 epoch 足量判断;「主观好/差」n=1 且难度未校准(难任务的差评可能是任务难);工具出错/异常路径耗时:meta.json 的 exitCode/usage/durationMs 可离线派生,工具级错误与异常 episode 需 Trace 落盘(现仅 stdout)——属新采集。
**依据**:research-S-r2 ②(Trace 未落盘、预期派发数无机器定义)。
**改变判断的证据**:清点每 loop 可归因判断数;若 <5 条,趋势判读须按月/季聚合。
**性质**:事实性(数据可得性矩阵建议 research 澄清)+判断性(epoch 口径)。

### Q5 度量设计真能裁决 DSH vs PI 吗
**问题**:若「完成度量后可据以裁决 DSH vs PI」成立,那么也假设了「度量需求在两 runtime 间有判别力(至少一项仅一者满足)」——这真的正确吗?度量所需能力(事件访问/无头集成/产物持久化):pi 有事件拦截+appendEntry+rpc/SDK,dsh 有 typed events+插件树+headless——可能都满足;若判别力为零,裁决退回成熟度(0.1.x-rc breaking vs 254 版)/生态(≈4,300 包 vs 无目录)/维护(bus factor 1 vs 34 人)。
**依据**:research-S ②/③(扩展与插件 API 对照);S-r2 ④(直接对比不存在)。
**改变判断的证据**:列度量所需能力清单逐项核对,发现某项仅一者支持(如需替换 session log→仅 dsh)。
**性质**:判断性(hard constraints=human 定);能力对照建议 research 完成。
