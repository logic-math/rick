计算式：期望分 = (影响程度 × 置信度) − (不可逆性 × (1−置信度))；最终分 = 期望分 × 影响范围分。

### 打分依据说明（只陈述理由，不替 human 选择）

- **影响范围**：各视角共享同一组已证实事实、覆盖全部命令，故全局性均 1.0。差异在「决定性」：V3 聚焦「任务形态契约」（对应 D3），不直接定位「触发语法/agent 名」改进点（D1/D2），故决定性 0.5；V6 是解释性框架，其改进动作落到「显式语法」与 V4/V5 重叠、不独有决定性动作，故决定性 0.5。
- **不可逆性**：六视角收敛于同一动作（显式触发语法 + agent 名对齐），选错视角的可修正成本低，故均 0.5。
- **影响程度**：V1~V5 均直接给出可落地动作（强制语法/显式化/契约/注册符号/协议对齐），高赔率=1.0；V6 的边际贡献是「为何外部化有效」的解释，动作与 V4/V5 重叠，低赔率=0.5。
- **置信度**（0~1，理论+事实+融贯性；因「来源理论网络出处未核验」（R7）统一小幅下调）：
  - V4=0.80：名字解析为 CS 公认基础；BP-2「Unknown agent 拒绝」+ B1~B4 直接证实；续洽直接对应 human 已确认方向（内置为系统级 agent）。
  - V2=0.75：指令遵循为 LLM 成熟主题，但「遵循度=显式程度×形态」是启发式非定律。
  - V5=0.75：协议对齐精确类比，BP-9「tool description 是模型认知来源」直接支撑。
  - V1=0.70：Ashby 定律经典，但「必要多样性」到「触发确定性」的映射较松。
  - V3=0.65：委托代理理论经典，但「激励相容/监督」到「触发语法」映射较远。
  - V6=0.60：分布式认知经典，但解释性最强、可操作性最弱。

## top-N 视角的 3 启发性问题

### V4：编程语言/编译器（名字解析/确定性派发）

- Q1 信念：关于「自造角色名无法解析 → 注册为真实 agent 名即可解析」这个视角，你内心最确信的是什么？最不确定的是什么？
- Q2 前提：这个视角要能指导改进，需要什么前提（例如：pi 的 agent 发现目录与 rick 隔离环境能正确映射、agent 名不与内置名冲突、自定义 agent 空系统提示词起步后上下文如何注入）？这些前提你确认过吗？
- Q3 反例：什么证据会让你认为「名字解析」这个视角失效、被另一视角取代？

### V2：人机交互/指令遵循

- Q1 信念：关于「遵循度 = 指令显式程度 × 指令形态」这个视角，你最确信与最不确定的边界分别在哪里？
- Q2 前提：「显式化能提升遵循度」要成立，需要什么前提（例如：模型对显式触发语法确有更高遵循度，而非仅对语义内容敏感；长脚本被 summarize 压缩后 subagent 段是否仍存活）？这些前提你确认过吗？
- Q3 反例：什么证据会让你改变「显式化能提升遵循度」的判断？

### V5：协议设计（协议对齐/握手）

- Q1 信念：关于「触发概率低 = 协议未对齐/握手失败」这个视角，你最确信的是什么？最不确定的是什么？
- Q2 前提：「协议对齐后握手成功率提升」需要什么前提（例如：tool description 确实是模型侧唯一认知来源、提示词与 tool description 对齐即足够）？这些前提你确认过吗？
- Q3 反例：什么证据会让你认为「协议对齐」这个视角失效或被取代？

## 门禁结论

✅ **通过（候选层面）**：V1~V6 候选的融贯性（自洽/他洽/续洽）已由 research 验证，打分完成，top-N 已给出，供 human 综合出原创视角。
