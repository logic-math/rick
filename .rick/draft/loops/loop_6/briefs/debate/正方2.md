- pi 运行时 `@earendil-works/pi-coding-agent` **v0.84.1**；subagent 扩展 `pi-subagents` **v0.47.1**——均为已发布 npm 包、长期迭代的稳定版本号，非预览版。

### P2：pi 有明确、文档化的 subagent 触发最佳实践（稳定契约）
- pi 的 subagent 触发机制有九条显式最佳实践（BP-1~BP-9）：触发入口唯一且显式（workflowScript）、agent 名显式、任务=compact contract、async 默认、context 明确、单写者、编排 recipe、编排权在 parent、模型认知来源=tool description。
- 证据：`.../loop_6/briefs/research-report-S-bestpractice.md`（BP-1~BP-9，来源 pi-subagents SKILL.md + references/ + docs/）。

### P3：pi 有成熟扩展生态与明确扩展点
- pi 提供多种「方法层外化」承载机制：自定义 agent（frontmatter markdown，注册作用域 builtin/package/user/project）、skills（SKILL.md）、agentOverrides、refinement overlays；且 rick 侧已验证这些机制可实施。
- 证据：`.../loop_6/briefs/research-report-S-reasons-agent.md`（B1~B4）；pi-subagents `docs/agents.md`。

### P4：rick 已在 pi 上完成迁移，有现成基础与验证
- rick 已从 claude code 迁移到 pi（loop_4 RFC），迁移含 3 项端到端验证通过（TestRealPi_RealToolCall / TestParseStream_RealDeepSeekToolCall / executor_e2e_test）——长期演进已有可运行的起点，而非从零评估。
- 证据：`.../draft/rfc/rfc-rick-pi-迁移的价值基础与架构定位-2026-08-10.md`；`.../loops/loop_5/SESSION_RESUME.md`（job_30 commit a81eda0）。

## 对对方（deepseek-harness）的反驳点（生态/稳定性缺点）

### D1：developer preview，官方明示「未来将出现破坏兼容性的变更」
- README.md 明写：**"DeepSeek Harness is currently in _developer preview_ and is iterating rapidly. THERE WILL BE COMPATIBILITY-BREAKING CHANGES."**——API 不稳定，rick 若深度绑定，长期演进需持续跟进破坏性变更。
- 证据：`/workdir/sunquan20/AI_CODING/deepseek-harness/README.md:11`、`README.zh.md`。

### D2：会话格式无兼容承诺（SESSION_FORMAT_VERSION=0）
- AGENTS.md 声明预发布立场「foundation over blast radius：无外部消费者，宁可破坏兼容」；`dsh-session` 保持 `SESSION_FORMAT_VERSION = 0`，「with no compatibility promise」；backends 拒绝旧磁盘格式。
- 证据：`AGENTS.md:7`（"Backends reject old on-disk formats... SESSION_FORMAT_VERSION at 0 with no compatibility promise"）；`docs/persistence-catalog.md:10`（"the whole format is pinned at SESSION_FORMAT_VERSION = 0 — pre-release, no compatibility implied"）；`docs/subsystems/session.md:530`（"this unreleased format intentionally has no compatibility promise"）。

### D3：预发布立场允许自由改名/重组，外部集成无稳定锚点
- AGENTS.md：「rename or repackage freely and update every reference together」——在首个 tagged release 前，包名/结构可自由重构，第三方（如 rick）的集成代码无稳定锚点。
- 证据：`AGENTS.md:7`（"Remove this section at the first tagged release" 段落）。

### D4：工程门槛较高（较新 Node + vendored Cordis）
- 依赖 Node ^22.19 || >=24；架构建立在 **vendored（内嵌）Cordis** 之上（`vendor/` 目录），即自维护框架分支，生态依赖深、迁移/升级成本高。
- 证据：`AGENTS.md`（"pnpm workspaces, node ^22.19 || >=24"）；`docs/architecture.md`（"vendor/ Vendored Cordis source"）。

## 结论（一句话）

pi 以成熟版本（0.84/0.47）+ 文档化稳定触发契约（BP-1~BP-9）+ rick 现成迁移基础，在长期演进/稳定性上显著优于仍处 developer preview、会话格式无兼容承诺（SESSION_FORMAT_VERSION=0）的 deepseek-harness。
