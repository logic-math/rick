# 反方2：独立性/可迁移/不绑定视角

> 立场：deepseek-harness 更利于 rick 方法长期独立演进与可迁移；pi 存在目录/扩展/触发入口/生态四重绑定。
> 证据均实读自 `/workdir/sunquan20/AI_CODING/deepseek-harness`（dsh 源码）与 rick 侧已调研事实。

## 论点（反方立场，含证据出处）

### 1. MIT 许可 + 「一切皆插件」无特权核心（dsh 可 fork/可替换，rick 方法可独立承载）
- `LICENSE`：`MIT License, Copyright (c) 2026 DeepSeek` —— 宽松许可，可自由 fork、二次开发、私有化，无许可证锁定。
- `docs/architecture.md`（Cordis 节）：「Every part of the product is a plugin, including the model adapter, the tool registry, the session log, and the agent loop itself, so every part is replaceable from configuration. **There is no privileged core to patch**: you extend dsh by mounting a plugin beside the others」——模型适配器、工具注册表、会话日志、agent loop 本身都是插件，无一特权核心。这意味着 rick 方法层可作为一组插件「挂载」进 dsh，而非被某一运行时「内化」。

### 2. LLM 适配器是 seam，多 provider 并存（不绑定 DeepSeek 模型，甚至可复用 pi 的模型层）
- `packages/llm/` 目录含 `llm-deepseek`、`llm-pi-ai`、`llm-replay` 三个 provider 包——模型适配器是 `ctx.llm` seam（`docs/architecture.md` 核心包表：`llm/llm`「Message and stream vocabulary plus the adapter seam」）。
- `packages/llm/llm-pi-ai/README.md`：「Generic **multi-provider** adapter ... backed by `@earendil-works/pi-ai`」；「an OpenAI-compatible gateway, a self-hosted server, or a provider newer than the installed catalog is **configuration rather than a code change**」。
- 含义（关键事实）：dsh 非但不受 DeepSeek 模型绑定，还能挂载 Earendil 的 `pi-ai` 作为 provider——即 **pi 的模型能力可被 dsh 复用，但 dsh 运行时不必绑定 pi 的整个目录/扩展/触发体系**。rick 若迁到 dsh，模型层仍可用 pi-ai，实现层却不被 pi 锁定。

### 3. subagent 后端是 seam，多 provider 共存（不绑定单一子 agent 机制）
- `packages/subagent/README.md`：「This family lets an agent delegate work to child agents. **Multiple named providers may coexist in one context.**」列出的 provider 包括：`subagent-spawn-in-process`、`subagent-fork-in-process`、`subagent-acp`（ACP 协议）、`subagent-codex`（真实 Codex app-server）、`subagent-claude-code`（真实 Claude Code）、`subagent-dsh-sdk`（TypeScript SDK）。
- `packages/subagent/subagent-claude-code/README.md`：「registers the fixed `claude-code` subagent provider. Each accepted run invokes the official Claude Agent SDK」。
- 含义：dsh 的「think/research/exporter 子 agent」可走进程内、ACP、甚至真实 Claude Code 子 agent 多种后端，rick 的 subagent 角色不绑定某一种专有触发语法（对比 pi 的唯一 `workflowScript` 执行面，见下方反驳点）。

### 4. profile/bundle/patch 分层组合，运行时可由用户 patch 重写（可移植、可组合）
- `docs/architecture.md`（Profiles and bundles 节）：「A running `dsh` is a plugin tree composed at boot from ordered layers... A **patch** targets a row by id and replaces its whole config, or inserts new rows」；「Any row it prints can be replaced by a patch of your own」。
- 含义：rick 方法层可作为 bundle 分发、作为 patch 覆盖，环境/模型/子 agent 后端的差异用配置层表达，而非改私有目录或硬编码。

## 对对方（pi）的反驳点（缺点，含证据出处）

### 1. pi 目录结构绑定（rick 需隔离环境硬适配）
- rick 侧已调研事实（`research-report-S-reasons-agent.md` B2 节）：pi 的 agent 发现路径硬绑定 `~/.pi/agent/agents/**/*.md`（user 级）与 `.pi/agents/**/*.md`（project 级）；rick 被迫用 `PI_CODING_AGENT_DIR=~/.rick/pi/agent` 隔离（`tools_init_pi.go` 注入 `piagent.AgentEnv()`）才能在 pi 的目录布局里安放自己的 agent。→ 方法层与运行时目录布局强耦合，迁移/隔离成本高。

### 2. pi npm 扩展绑定（subagent 能力依赖具体扩展包）
- rick 侧已调研事实（`research-report-S-reasons-agent.md` A2 节）：rick 的 `tools_init_pi.go` 硬编码 `requiredExtensions=["pi-subagents","pi-web-access"]`，`ensureNpmExtension("pi-subagents","pi-subagents")`。→ rick 的 subagent 能力不是方法层自有，而是依赖 Earendil 的 npm 扩展；扩展失效/演进即 rick 能力受制。

### 3. pi 唯一触发入口 + 固定内置 agent 名（方法需「翻译」成 pi 语言）
- rick 侧已调研事实（`research-report-S-bestpractice.md` BP-1/BP-2）：pi 下触发 subagent 唯一公开执行面是 `subagent({workflowScript:...})` + `runs.run(agent:'worker',...)`，内置 agent 名固定 7 个（scout/worker/reviewer/researcher/delegate/oracle），名字不在名单即「Unknown agent」拒绝。→ rick 的自造角色名（think/research/exporter）必须「翻译」成 pi 的语法与 agent 名才能触发（human 在 S-R 已明确「翻译」是必要成本）；而 dsh 的 subagent seam 允许自定义 provider，角色承载方式不受单一语法约束。

### 4. 生态锁定（长期跟随单一厂商运行时）
- pi 是 Earendil Works 的 pi-coding-agent 产品生态，rick 的迁移（loop_4 RFC）使 rick 长期绑定该生态的目录/扩展/触发约定；而 dsh 的 `llm-pi-ai` provider 反向证明：**pi 的模型层是可被第三方 harness 挂载的 provider，而非必须整体绑定其运行时**。rick 绑定 pi 整个运行时，是把「实现」与「方法」耦合过深（恰与 human S-R 判断「rick=方法、pi=实现」相悖——方法本应可与实现解耦）。

## 结论（一句话）

deepseek-harness 以 MIT + 插件化 seam（LLM/subagent/组合均可替换、可复用 pi-ai 而不绑定其运行时）为 rick 方法提供「实现可迁移、不锁定单一生态」的载体，而 pi 以目录/扩展/触发入口/生态四重绑定将 rick 方法与单一运行时深度耦合。

## 保留（诚实标注，供对方反驳与主 agent 汇总）
- dsh 处于 developer preview：`README.md` 明示「THERE WILL BE COMPATIBILITY-BREAKING CHANGES」、`AGENTS.md` 明示「Backends reject old on-disk formats... no compatibility promise」——「可迁移/不绑定」的代价是当前 API/存储格式不稳定，迁移后需承担其快速迭代成本。
