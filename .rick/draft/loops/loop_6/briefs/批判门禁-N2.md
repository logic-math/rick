# 批判门禁-N2 简报

**阶段**：N2 主要矛盾判断 · 批判门禁（think subagent 输出）
**主题**：subagent 在 pi runtime 下触发概率低，优化提示词（使触发确定性提升到上限内最高）。

---

## 输入（待审材料 · human 本次回答原话）

> 我认为是理解清楚 pi 的触发语言是什么，深度跟 pi 的 subagent 体系结合才行。
> 理解了他的触发语言，这个作为主要的控制手段，我们以此改造 prompt 即可。
> 理解触发语言应该作为关键的控制方法，从 A 到 B 的关键转换其实就是改造深度。 这点毋庸置疑
> 而为了实现这一点，我们应该先从理解 pi 的行为开始。

## top-N 假设的 3 启发性问题

### 假设 #1：如果 [理解 pi 行为是改造的前置必要步骤] 成立，那么 [不先理解 pi 行为就无法正确改造] 成立
- Q1 信念：关于"不先理解 pi 行为就无法正确改造"，你内心最确信的是什么？最不确定的是什么？
- Q2 前提："理解 pi 行为是必要前置"成立需要什么前提（例如：pi 触发语言存在人类可读且完整的规范，而非只能靠反复试错才能摸索）？这些前提你确认过吗？
- Q3 反例：什么证据会让你改变"必须先理解 pi 行为"的判断？（例如：pi 已有可直接套用的官方编排 recipe，无需从零理解行为）

### 假设 #2：如果 [理解 pi 触发语言（含 subagent 体系）是改造 prompt 的充分前提] 成立，那么 [以此作为主要控制手段改造 prompt 是可行且充分的] 成立
- Q1 信念：关于"理解触发语言后改造 prompt 即可"，你内心最确信与最不确定的边界分别在哪里？
- Q2 前提："理解即足以改造"成立需要什么前提（例如：理解触发语言后能直接得到改造规则，而非还需额外注册系统级 agent 定义、调整配置）？这些前提你确认过吗？
- Q3 反例：什么证据会让你改变"理解触发语言→改造 prompt 即可"的判断？（例如：光理解语法不够，还得把 think/research/exporter 注册为 pi agent 定义才能触发）

### 假设 #3：如果 [改造深度能代表各命令低触发的共性根因] 成立，那么 [统一按改造深度方向可覆盖各命令] 成立

- Q3 反例：什么证据会让你改变"统一改造可覆盖各命令"的判断？（例如：某命令改正后触发率仍低，暴露出另一处独立原因）

## 门禁结论：✅ 通过

top-N（A4/A2/A5）的 Y 均已由 human 显式确认：
- **A4（先理解 pi 行为是前置必要）**：human 原话「而为了实现这一点，我们应该先从理解 pi 的行为开始」显式陈述。
- **A2（理解触发语言→改造 prompt 是控制手段）**：human 原话「理解了他的触发语言，这个作为主要的控制手段，我们以此改造 prompt 即可」显式陈述。
- **A5（统一按改造深度覆盖各命令）**：承接 S 阶段 human 第 4 点「都是提示词未对齐 pi 触发机制」的共性根因确认，本回答未引入新例外。

**随 N2 带入下阶段的待验证项/残余风险（非阻塞，human 已承接或已显式判断）**：
1. **A1（解药正确性/达上限内最高）**：因果已由 human S 阶段确认，但「上限内最高」依赖模型能力，human 已承接「改正后实测验证」（R7）。
2. **A3（K4 是主要矛盾、其余从属）**：human 本回答显式确认「关键转换就是改造深度，这点毋庸置疑」→ 主要矛盾已选定，无需再澄清。
3. **A7（pi 行为稳定性）**：pi 是外部依赖，其触发语言/行为当前有明确规范（已证实），但「稳定/可完全理解」未证实——与 human N1 自提的「3 年后失去先进性」相关，建议带入 S-R 阶段留意（不阻塞 N2）。

**禁止项自检**：未含倾向性（不替 human 选定主要矛盾）、未替 human 决策 Y、假设均从 human 推理提取（未生成价值性假设）、7 假设 ≥ 5、多视角覆盖（演绎+归纳+溯因+交叉）、每 top-N 假设 3 问、均为启发性句式。
