## 0｜从你的两答切入（认知强制裁决位）

**b 答：guardrails 你明示不知道——先补概念。** guardrails（安全护栏）：硬编码在 harness 里的「不许做什么」层——约束规则＋输出校验＋安全边界（例：「不许改生产配置」「输出必须过格式校验才放行」）。与 prompt 的区别一个字：prompt **劝**、guardrail **拦**——劝的是模型倾向（可被更好的提示覆盖），拦的是硬边界（违背即拦截，不进入执行）。为什么它偏偏是 8 类部件里你叫不出名的那个？因为在 superopt 里它**不在 agent 可编辑面**——你的对应物散在框架层：框架级门禁（门先证红）＋exploit_registry（软门禁）＋Go 监督层。这个对照正是本课核心命题（§4 展开）：**harness 部件从「人写死」到「可编辑＋可进化」——哪些件能走进进化面，哪些必须留在人写死层。**

**a 答：离线编译可测——强直觉，本课最重一节收下它。** 你的原话：「我们在线推理场景，其实是有离线编译优化的，这个离线编译优化过程是可以进行测试的信号。」这句话命中本课的承重矛盾：Harness² 的 Probe 要求**任务可重复执行**（跑两遍对比），在线推理没有这个奢侈——而你的答案恰好是替代信号的结构（A/B 的离线替身思路，第 2 课离线重放生产数据那条轴）。§5 正面展开成三层＋残余位，先带着它读机制。

## 1｜它要解决什么：开放世界的三前提

出处钉死：arXiv 2610.14224（v1 2026-10-09，Google Cloud AI Research，Xu Ruiyao/Chen Yanfei/Pfister 等）＋GitHub google-research/harness2〔A〕。谱系第 5 课已定位（ADAS 开山 → Darwin Gödel Machine → 2026 主战场），直引不重讲。

三前提（R §③，A）：

- 任务在 harness **设计时未见过**
- **测试时新颖**
- **无 ground-truth verifier**

作者的处境还原（原创思考过程，非结论罗列）：路线 1/3 你已机制级掌握——verifier 客观可自动判定（编译/正确性/计时/吞吐），loop 最稳；路线 2 退一步，verifier 是 benchmark 分（第 5 课）。Harness² 的作者面对的是再退一步的处境：真实世界的专业任务连 benchmark 都没有 ground-truth verifier——办公/工作流任务没有「标准答案可对」。矛盾显形：**改进 loop 需要信号，而这个世界不提供信号源**。他们的逆转：既然没有外部 verifier，就让**候选互为对照**——不问「这个改动好不好」（无从回答），改问「两个改动在同一环境跑出了什么差异」（可观测）。这是 A/B 对照实验结构装进 RSI——你的主场语言。

## 2｜两级递归：机制图（一课一事的主件）

```
两级递归总图（Harness²，R §③ A）

内环｜task-level recursion —— 改进当前任务（当场收益）
  当前任务 ＋ 现行 harness
    ↓ Propose：editor 起草两个可执行候选
        候选 A → 攻通用弱点（规划／工具使用）
        候选 B → 攻领域流程约束
    ↓ Probe：同模型 × 同环境 × 两候选各跑一遍 → 对比轨迹
    ↓ Compose：从对比轨迹组合出改进版
    ↓ 改进版 harness 执行当前任务

外环｜harnessing-level recursion —— 沉淀未来能力（未来收益）
  内环的编辑 ＋ 轨迹 ＋ 结果
    ↓ 从这些编辑中沉淀经验
  更新「持续改进 harness」（8 类可编辑部件）
    ↓ 下一个任务拿着更高的起点进内环
```

两级各一句：

- **task-level（内环）**：对当前这一个任务当场改进 harness——收益落在**这次**执行上。
- **harnessing-level（外环）**：从一批任务的编辑历史沉淀经验，更新一个「持续改进 harness」，让 agent 更好适应**未来没见过的**任务——收益落在**下一批**任务上。

为什么外环是本课独有件（判别一句话）：路线 2 其他工作你见过的都是单层——改 harness、跑基准、留分；外环做的是**把改进本身变成留存物**。挂到你的留存家族谱上一句（家族表已四次，此处只挂位不重摆）：前谱第 3/7/9/10/11 课——程序数据库（种群）→骨架库→Booster Pack→GEAK KB（库）→自晋升链（链），留存物是工件或知识两种亚族；harnessing-level 是家族在 harness 域的新形态——**留存的不是工件也不是文档，是可插拔的 harness 部件本身**（「知识文档」亚族的结构化升级：更新的不是 md，是 system prompt/skill 这些直接装载的件）。

## 3｜内环三拍：Propose-Probe-Compose（机制级各一句）

- **Propose（起草）**：editor 起草**两个**可执行候选——不是一个：候选 A 攻通用弱点（如规划、工具使用），候选 B 攻领域流程约束。两个候选的差异设计是刻意的：通用与领域两个方向各押一注。
- **Probe（探测）**：同模型、同环境跑两候选。环境与模型全同，两轨迹的差异**只能**归因于 harness 编辑本身——你第 2 课「环境控制」要素（同机对照、唯一随机源是编辑差异）在 RSI 里的形态。代价：任务必须**可重复执行**（§5 本课对你的主件）。
- **Compose（组合）**：对比两条轨迹，组合出改进版——哪段谁走得好取谁的结构，拼出第三版执行当前任务。

预算结构（R §③，A）：可并行（两候选同时跑）／串行扩预算，预算加大增益继续涨（§6）。用你第 13 课的三分类接一句：两候选不是你那三种搜索策略（启发式贪心/概率建模/退火进化）之外的第四种——它是**对照结构**：信号不从单点分数来，从**差异**来。§1 的矛盾在此闭合：无 ground-truth verifier 时，单点分数无锚，**差异结构有锚——两臂互为锚**。

## 4｜可编辑 8 类部件 × superopt 对照（guardrails 落位处）

Harness² 把 harness 定义为可插拔件集合：**8 类可编辑部件**（R §③ 录名：system prompt、guardrails、memory、skills 等——8 类只录 4 名＋「等」，其余未核对全文、不臆造〔R7〕）。八件套你已机制级掌握（探针 2①：agent＝llm＋harness，模型外围一切——prompt/skill/工具/记忆/编排/插件都在你自己的枚举里）。**Harness² 的增量不在清单，在「可编辑」三字：部件从人写死，变成 loop 的编辑对象。**

superopt 对照表（你的架构口径：ABCD 四 agent＝adjust/builder/coding/debug＋Go 监督×py 调度器×agent 池——judgment.md 第 13 课插叙）：

| Harness² 部件（R 录名） | superopt 对应物 | 在哪一层 |
|---|---|---|
| system prompt | ABCD 四 agent 的 prompt 模板（在迭代） | agent 可编辑面——**在进化** |
| memory | archive＋events＋domain_knowledge | agent 可编辑面——**在进化** |
| skills | env skills 层 | agent 可编辑面——**在进化** |
| tools | gates＋CLI 工具面 | agent 可编辑面——**在进化** |
| guardrails | 框架级门禁（门先证红）＋exploit_registry（软门禁） | **散在框架层**（Go 监督）——不在 agent 可编辑面 |
| 其余 3 类 | ——（R 未录名，R7 不臆造） | —— |

对照结论（本课核心命题在此落地）：superopt 已经在做 task-level 的事——四类部件在 agent 可编辑面持续迭代；你的 guardrails 类**已存在、也在演进，但散在框架层**，门禁是人写死的硬框架。这个两层分工不是落后，恰是 **#9 自指性边界的 harness 域落地**：prompt/skill 层是性能优化面，进化它＝优化能力；门禁层是正确性/安全面，进化它＝verifier 进化自己＝自指危险区（你第 5 课自推、z.ai 独立收敛的那条线）。而 Harness² 把 8 类**全**摆进「可编辑」——包括 guardrails——这正是第 16 课批评层的靶位之一：持久 harness 有安全问题（坏经验、危险工具规则、泄漏数据可被写回复用——HUINHB 论文自述局限，R §④）。

## 5｜「任务可重复执行」前提与在线替代信号（你的离线编译答案展开）

前提拆解（R §③ 局限自述，A）：Probe 要「同模型同环境跑两候选并对比」——**任务必须可重复执行**；单步 k=1 就是 4 次任务执行（baseline 1＋两候选 2＋组合改进版 1），预算加大次数更多。局限原文方向：单步增益依赖「任务可重复执行做 Probe」——**在线推理场景无此奢侈时需替代信号**。

你的答案接住（原话）：「我们在线推理场景，其实是有离线编译优化的，这个离线编译优化过程是可以进行测试的信号。」——裁决：这正是 A/B 的离线替身思路（第 2 课你的轴：判真＝离线重放生产数据；在线＝部署段）。把「Probe 的执行环境」整体搬到离线侧，**三层对应**：

1. **任务源层**：回放生产 trace 当任务源——FlashInfer-Bench 模式（第 8 课：真实 trace 采集→sanitize→当 workload）。「任务」不必是新鲜生产请求，回放 trace 就是可重复执行的任务流——两候选各跑同一条 trace，差异归因干净。
2. **对照环境层**：离线 benchmark 当对照环境——离线全控（负载自造、环境自锁、同机对照，唯一随机源是测量噪声——第 2 课离线结构本质）。「同模型×同环境」这个 Probe 前提，在离线侧天然成立。
3. **部署层**：离线验证过的改动走灰度放量——你的五步管线（第 8 课）：灰度放量观察→效果验证→推全。离线 Probe 组合出的「改进版」不直接推全，进灰度——在线段只接收离线判过真的候选。

在线残余位（离线探不到的，一刀补齐）：真实流量的**到达分布**（突发长尾 vs 离线负载自造）、**时段效应**（流量按小时星期波动）、**容量竞争/队列行为**（开式系统，延迟分布由到达过程方差决定，Little 定律 L=λW 连接——你的排队论主场，探针 3② 机制级）。这就是探针 3 素材的正式接入位：**在线指标噪声、流量波动、混杂因素**——三样离线侧拿不到，只能在线灰度里量；它们怎么进判真协议，正是第 2 课交棒点「在线灰度判真协议形式化无先例」的空白——你的原创主场（第 21 课承重件）。

**留白（你来推）**：离线编译当 Probe——列三个离线侧拿得到、三个拿不到的信号；拿不到的那三个，各对应你五步管线里哪一步补位？（清单本身不唯一——列得出它，就是美团版 contrastive probe 的设计件。）

## 7｜原创视角（判断权在 human）：在线场景 harness 进化的两层分工

本课给你的原创接口不是「要不要学 Harness²」，是一道设计题：**在线推理场景里，harness 部件的「可进化面」划到哪条线？**

- **性能面（可进化候选）**：prompt 模板、memory、skills、工具面——进化它＝优化能力，verifier（离线判真＋灰度）在人手里闭环，撞不到 #9。
- **安全面（必须人写死？）**：guardrails 的美团对应物清单——**服务降级规则、限流阈值、熔断器**——哪些可以让 loop 在离线判真护栏内进化（如限流阈值的离线搜索），哪些必须永远人写死（如熔断触发条件、降级顺序）？

判断权在你：这条线画在哪，就是 #9 自指性边界在 harness 域的具体坐标。Harness² 把 8 类全放进可编辑面（含 guardrails）是一个极端答案；superopt 现状（guardrails 全在框架层）是另一个极端；中间态（如「guardrails 可进化但需人审生效」——z.ai 职责③审关键变更的形态）是否存在、值不值得，第 21 课提案时定。
