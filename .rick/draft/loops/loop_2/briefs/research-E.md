## 信源配置

| 信源 | 权重 | 验证方式 |
|---|---|---|
| 代码原文 | 0.4 | R1-R8 已落盘 briefs(事实基础,不重复调研) |
| 运行时行为 | 0.3 | R1-R8 已落盘 briefs(事实基础,不重复调研) |
| 文档 | 0.2 | 任务派发明确指定的跨领域理论(编译器/OS/IoC/插件/控制论/信息论/复杂系统/工作记忆/元认知/心流/现象学/实用主义/过程哲学/共生/生态/神经科学)——公认理论框架 |
| 反事实 | 0.1 | 视角候选的融贯性自洽/他洽/续洽推理 |

加权公式:置信度 = Σ(信源验证结果 × 权重),验证结果 ∈ {0, 1}
高置信度阈值:≥ 0.8(终止)

**信源限制声明**:本轮 WebSearch/WebFetch 因网络策略阻断不可用。E 阶段视角生成依赖的跨领域理论均为任务派发明确指定的公认理论框架,基于既有知识 + R1-R8 事实构建视角候选。置信度评估的是"视角候选的融贯性"(来源理论真实存在 + 事实支撑准确 + 自洽/他洽/续洽成立),而非"迁移是否可行"(后者已在 R1-R8 完成)。

## 已澄清事实基础(R1-R8 摘要)

### rick 现状
- ai_cli = `internal/agent/` 抽象层(AgentExecutor 接口 + ClaudeCodeExecutor 实现)
- 13 处 exec.Command 调用点(仅 1 处走接口,12 处直接硬耦合)
- stream-json NDJSON 协议(per-task 启动退出无 RPC)
- 9 个命令入口

### pi 框架
- 开源轻量级 agent(earendil-works/pi),MIT,v0.83.0,Node.js ≥22.19.0
- 支持 Bun 编译 standalone binary(30-44 MB,6 平台预编译,真零 Node 依赖)
- 显式 No MCP/No sub-agents/No permission/No plan-mode(设计哲学)
- 4 种模式:interactive / print / json / rpc
- 6 类扩展点:Prompt Templates / Skills / Extensions / Themes / Pi Packages / Agent Core 钩子
- 5 类 compaction 自定义扩展点
- 30+ provider + 11 种 API 协议,per-prompt 模型切换
- 官方 subagent extension 范例(spawn 子 pi,独立 context,single/parallel/chain)
- compaction 保留 system prompt

### 6 项迁移价值(V0-V5)
- V0 二进制编译脱离 node / V1 TDD 门禁内嵌 / V2 compaction + system prompt 自定义 / V3 skill allowlist 注册 / V4 loop 渐进式动态加载 / V5 subagent 递归

### 首阶段边界 + rick 职责
- pi 二进制安装 + 与 claude code 保持相同功能 + rick 现有功能不变性
- rick = 解析命令 + 调度任务 + 构建系统提示词启动 pi agent
- 所有反馈性、检查性门禁做成扩展内嵌到 pi 中
- Y8 内嵌 = 内嵌到 agent loop 内部(pi 的扩展内部),可自由组合上下文 + 分区 + 保留/压缩
