# N3 认知科学视角 — rick 迁移到 pi agent

## 视角名:工作记忆分区 + 元认知调控 + 心流注意力

## 来源理论(任务派发指定 + 公认知识)

### T1:Baddeley 工作记忆模型(Working Memory Model)
- **中央执行系统**(central executive):注意力控制器,决定哪些信息进入工作记忆。
- **语音回路**(phonological loop):语言/听觉信息短期保持。
- **视空工作台**(visuospatial sketchpad):视觉/空间信息短期保持。
- **情景缓冲区**(episodic buffer):整合多源信息,与长期记忆交互。
- **容量限制**:Miller's 7±2 → Cowan's 4 chunks。工作记忆是有限资源,需分区管理。
- **关键洞察**:不同分区独立维护,可并行,但中央执行系统是瓶颈。

### T2:元认知(Metacognition — Flavell)
- **元认知知识**(metacognitive knowledge):对自身认知能力的知识("我不擅长数学")。
- **元认知监控**(metacognitive monitoring):对当前认知过程的觉察("我没看懂这段")。
- **元认知调控**(metacognitive control):基于监控调整策略("我重读一遍")。
- **执行功能**(executive function):前额叶皮层,负责计划、抑制、切换、更新。
- **关键洞察**:元认知 = "对认知的认知",是高阶调控系统。

### T3:心流理论(Flow — Csikszentmihalyi)
- **心流条件**:挑战与技能匹配 + 明确目标 + 即时反馈 + 控制感。
- **注意力分配**:心流中注意力高度集中于任务,无关信息被过滤。
- **上下文切换成本**:任务切换损耗 20-40% 认知效率(American Psychological Association)。
- **关键洞察**:心流是认知最优状态,频繁切换会破坏。

---

## 视角本质描述(一句话)

> **rick 迁移到 pi = 把 agent 的"工作记忆"从单一中央执行(claude code 无分区 context)升级为分区的中央执行 + 语音回路 + 视空 + 情景缓冲(pi 的 transformContext 分区 + compaction 选择性保留)——rick 成为 agent 的"元认知调控器"(监控 + 控制),pi 成为"认知执行器"(工作记忆 + 长期记忆);迁移的本质是给 agent 装上"元认知前额叶",让它能觉察并调整自身的认知过程。**

## 事实支撑(引用 R1-R8)

### 工作记忆分区映射(T1)
- **现状(claude code)**:context 是单一 blob,无分区。所有信息(system prompt + tool 历史 + skill 内容)堆在一起,compaction 时无差别压缩。
- **迁移后(pi)**:
  - **中央执行系统** = pi agent core loop(决定调用哪个 tool)。
  - **语音回路** = system prompt(语言信息,需保留)。
  - **视空工作台** = tool 执行结果(结构化数据,可压缩)。
  - **情景缓冲区** = pi 的 session 持久化 + rick 的 debug/bug*.md(跨 session 长期记忆)。
- **R5-N4 事实**:Y8 pi 不原生支持分区需自建抽象——但 pi 的 transformContext 扩展点(R4-N3)允许 rick 注入分区逻辑。迁移后 rick 可在 transformContext 中实现 "语音回路保留 / 视空工作台压缩" 的分区策略。
- **human Y8 确认**:"内嵌是内嵌到 agent loop 内部...不同区域的上下文在 loop 的过程中实现保留或压缩"——这正是工作记忆分区的工程化。
- **R4-N2 事实**:pi compaction 保留 system prompt(N2=1.0 决定性证据)——语音回路(系统提示词)不被压缩,视空工作台(tool 历史)可压缩。

### 元认知调控映射(T2)
- **元认知知识** = rick 的 domain 知识(commands/architecture/go-patterns 等描述性文档)。
- **元认知监控** = rick 的 doing_check / easy_check(检查 agent 产出是否符合规范)。
- **元认知调控** = rick 的 learning 阶段(基于 debug/bug*.md 调整 skill / loop)。
- **执行功能(前额叶)** = rick 的 plan/doing/learning/dream 四阶段调度 = 计划、抑制(门禁)、切换(阶段转换)、更新(learning 更新知识)。
- **现状(claude code)**:元认知调控在 rick 侧,但**只能在 agent 执行后**做(事后监控),无法在 agent 执行中干预(因为 claude code 无 hook)。
- **迁移后(pi)**:rick 的 extension 在 tool_call / tool_result / session_compact 事件回调中**实时**监控并控制——元认知调控从"事后"升级为"在线"。
- **R7-N5 事实**:V1 TDD 门禁 = 元认知监控(检查测试是否通过)+ 元认知调控(未通过则注入修正指令)。
- **human Y11 确认**:"所有反馈性的,检查性的门禁都做成扩展内嵌到 pi 中"——元认知调控内嵌到认知执行器。

### 心流与上下文切换映射(T3)
- **心流条件映射**:
  - 明确目标 = system prompt(R5-N3)。
  - 即时反馈 = tool_call / tool_result 事件(R2-N4)。
  - 挑战与技能匹配 = LLM 能力 + skill 提供的脚手架(R3-N2 skill 系统)。
- **上下文切换成本**:现状(claude code)per-task 启动退出,每次任务是一个独立的"认知片段",启动成本 = context 重新加载。迁移后(pi)rpc 模式支持长连接,agent 可保持心流(R2-N3 pi 4 种模式)。
- **但 V4 loop 渐进式加载系统提示词**有张力:渐进加载 = 上下文动态变化,可能破坏心流(注意力需重新聚焦)。需权衡"信息丰富性"与"心流稳定性"。
- **R3-N1 事实**:pi standalone binary 30-44 MB——启动快,降低上下文切换的物理成本。

## 融贯性评估

### 自洽
- ✅ T1/T2/T3 三理论在"认知资源有限,需分区 + 调控"上自洽:工作记忆是资源,元认知是调控器,心流是资源被最优利用的状态。
- ✅ "给 agent 装元认知前额叶"的叙事自洽:rick 从外部观察者升级为内嵌的元认知调控器。

### 他洽
- ✅ 与 N1 软件工程视角他洽:IoC 扩展点 = 元认知调控的"接入点",框架调用扩展 = 认知执行器接受元认知调控。
- ✅ 与 N2 系统工程视角他洽:反馈回路 = 元认知监控 → 调控的工程化;二阶控制论 = 元认知(对认知的认知)。
- ⚠️ 与 N4 哲学视角有张力:认知科学假设"心智是信息处理系统"(信息处理范式),但现象学(Heidegger/Merleau-Ponty)反对这种"离身认知"——认知是具身的、情境的。这个张力是 N4 的核心。

### 续洽
- ✅ V0-V5 全部可被认知科学解释:V1 TDD 门禁 = 元认知监控;V2 compaction 分区 = 工作记忆分区;V3 skill allowlist = 控制进入工作记忆的内容;V4 loop 渐进加载 = 动态调整工作记忆负载;V5 subagent 递归 = 多重认知主体协作。
- ✅ human Y11 "rick 深入 agent 内部" = 元认知调控从外部观测升级为内嵌执行功能。

## 独特偏见

1. **偏见:认知主义假设**。认知科学假设"心智 = 信息处理",但 LLM 是否真的"有认知"是 open question。把 rick 类比为"元认知前额叶"可能 anthropomorphize(拟人化)了一个本质上是统计模型的系统。
2. **偏见:个体认知假设**。工作记忆/元认知/心流都是**个体**认知理论,但 rick-pi 是**人机协作系统**(human + agent)。认知科学视角容易忽视人类开发者的认知负荷(human 需理解 agent 行为)。
3. **偏见:分区可控假设**。Baddeley 模型假设中央执行系统能控制分区,但 LLM 的"注意力"是涌现的、不可完全控制的。rick 注入 transformContext 分区逻辑,LLM 是否真的"遵守"分区?这是不可观测的。
4. **偏见:忽视情感/动机**。认知科学视角聚焦信息处理,但人类开发者的动机、疲劳、情绪显著影响协作效果。这是 N5/N4 能补的盲区。

## 3 启发性问题

### Q1(信念追问)
**这个视角的核心信念是"分区工作记忆 + 元认知调控 = 更好的 agent"。但人类认知的分区是**演化**出来的(神经回路硬件支持),而 rick 注入 pi 的分区是**设计**出来的。如果 rick 的分区策略与 LLM 内部的"注意力机制"冲突(例如 rick 保留"语音回路"但 LLM 实际关注"视空工作台"),分区是否会**降低** agent 表现?这个视角是否高估了"外部设计分区"对 LLM 内部注意力的控制力?**

### Q2(前提追问)
**这个视角的前提是"元认知调控能改善认知执行"。但心理学研究表明,**过度元认知**会导致"思维反刍"(rumination)和"分析瘫痪"(analysis paralysis)——频繁的自我监控反而破坏心流。如果 rick 在每个 hook 都注入检查(TDD 门禁 + doing_check + easy_check),是否会让 agent 陷入"每步都自我审查"的认知过载?元认知调控的**最优频率**是什么?**

### Q3(反例追问)
**反例:心流理论强调"上下文稳定"是心流的前提,但 V4 "loop 渐进式动态加载系统提示词"恰恰是**动态改变上下文**。如果系统提示词在 agent 执行中变化,agent 是否会失去心流?这个视角下,V4 是否与心流理论冲突?如果冲突,risk 是选择"心流优先"(放弃 V4)还是"信息丰富优先"(牺牲心流)?**
