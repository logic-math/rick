# N4 哲学视角 — rick 迁移到 pi agent

## 视角名:现象学器具性 + 实用主义效果验证 + 过程哲学本体论

## 来源理论(任务派发指定 + 公认知识)

### T1:现象学(Phenomenology — Heidegger)
- **ready-to-hand(上手状态/Zuhandenheit)**:工具在使用中"消失",使用者不意识到工具本身,只意识到任务。例如熟练使用锤子时,不意识到"锤子",只意识到"钉钉子"。
- **present-at-hand(在手状态/Vorhandenheit)**:工具损坏或不可用时,工具"显现"为对象,使用者意识到工具本身。例如锤子断了,突然意识到"这是个工具"。
- **breakdown(故障)**:从 ready-to-hand 到 present-at-hand 的转换触发点。故障让工具从透明变为可见。
- **关键洞察**:最好的工具是"消失"的工具。工具显现 = 工具失败。

### T2:实用主义(Pragmatism — Peirce / James / Dewey)
- **工具主义(Instrumentalism — Dewey)**:观念/理论是"工具",其价值在于效果而非真理性。真理 = "what works"。
- **效果验证(pragmatic maxim — Peirce)**:概念的意义 = 其产生的实际效果差异。
- **可错主义(fallibilism)**:一切知识是暂时的,可被未来经验修正。
- **关键洞察**:不问"是否为真",问"是否有效"。迁移是否成功 = 迁移后是否更有效。

### T3:过程哲学(Process Philosophy — Whitehead)
- **事件 vs 实体**:世界的基本单位不是"物"(substance),而是"事件"(event)/"过程"(process)。每个 actual occasion 是一个生成事件。
- **流程本体论**:存在 = 生成(becoming)。静态实体是过程的暂时稳定化。
- **prehension(摄持)**:每个事件"摄持"先前的事件,并将其纳入自身。历史通过 prehension 累积。
- **关键洞察**:系统不是"物 + 关系",而是"事件流 + 摄持历史"。

## 视角本质描述(一句话)

> **rick 迁移到 pi 的本质,从哲学看,不是"替换引擎"而是"改变工具的可见性"——claude code 是 ready-to-hand 的(透明使用,但不可定制意味着其"消失"也是黑盒的);迁移到 pi 是把 agent 工具从"不可见的黑盒"转为"可见可改的白盒",**让工具在需要时能 present-at-hand(定制 compaction/skill/hook)而在执行时仍 ready-to-hand(agent loop 透明运行)**;过程哲学看,迁移是从"实体替换"(换引擎)重构为"事件流重组织"(rick-pi 的事件回调链是新的过程本体)。**

## 事实支撑(引用 R1-R8)

### 现象学器具性映射(T1)
- **claude code = ready-to-hand 但黑盒**:rick 调用 `exec.Command("claude")`,不关心 claude 内部如何工作——工具"消失"。但**当 claude code 出错时**(如 duration_ms 缺失、字段不对齐),工具"显现"为黑盒——rick 无法干预其内部(R2-N5:5 项字段不对齐 + duration_ms 缺失,只能 rick 侧适配)。
- **迁移到 pi = 让工具在故障时可控地显现**:pi 的 6 类扩展点(R2-N4)= 工具的"可见性接口"。rick 可在 tool_call / session_compact 等 hook 注入逻辑——工具从"全黑盒"变为"半透明",执行时 ready-to-hand,故障时 present-at-hand 且可干预。
- **R8-N3 事实**:pi resources_discover 是追加式,30+ 事件 0 个能拦截路径——pi 的"可见性"是有限的(不能拦截核心路径),仍有 ready-to-hand 的内核。
- **human Y9 确认**:"语义等价 = 功能等价"——这隐含工具主义立场:不问内部是否"真"等价,只问功能效果是否等价。

### 实用主义效果验证映射(T2)
- **工具主义**:pi 的价值不在其"架构优雅",而在其"能否实现 V0-V5"。R7-N5 已论证 6 项价值(4 项 claude code 不能做 + 2 项部分能做)——这是 pragmatic maxim 的应用。
- **可错主义**:首阶段 4 决策项(accept JSONL / accept .pi 并存 / skill 路径引用 / duration 自维护)是"暂时妥协",后续可修正(方案 A 去掉 .pi)。这是 fallibilism 的工程化——接受不完美,保留可修正性。
- **效果验证**:human Y11 "保证行为轨迹的捕获是等价的"——不问内部实现是否相同,只问行为轨迹(可观测效果)是否等价。这是 pragmatic maxim 的精确表述。
- **R5-N2 事实**:13 处调用点的 pi 映射表,8 完全等价 + 5 部分等价——实用主义视角下,"部分等价"是可接受的(只要效果差异在容忍范围内)。

### 过程哲学事件流映射(T3)
- **实体视角(传统)**:rick 是"程序",claude code 是"程序",两者通过协议通信。迁移 = 替换一个实体。
- **过程视角(Whitehead)**:rick-pi 系统是"事件流"。每个 pi extension event(before_agent_start / tool_call / tool_result / session_compact)是一个 actual occasion。rick 的 extension 是对这些事件的 prehension(摄持)——rick 把历史事件纳入自身,调整下一个事件。
- **R4-N3 事实**:pi 5 类 compaction 自定义扩展点 = 事件流的"记忆压缩"环节。compaction 不是"删除实体",而是"对历史事件的选择性摄持"。
- **human Y8 确认**:"不同区域的上下文在 loop 的过程中实现保留或压缩"——这是过程哲学的"事件选择性摄持"。
- **V5 subagent 递归** = 事件流的嵌套(子 pi 是父 pi 的 actual occasion 的子过程)。

## 融贯性评估

### 自洽
- ✅ T1/T2/T3 三理论在"工具/真理/存在都是动态的"上自洽:现象学说工具在使用中显现/消失,实用主义说真理在效果中验证,过程哲学说存在在生成中构成——都是反静态实体、主过程性。
- ✅ "从黑盒 ready-to-hand 到白盒可控 ready-to-hand"的叙事自洽:迁移不是"换工具",而是"让工具同时具备透明性和可控性"。

### 他洽
- ✅ 与 N2 系统工程视角他洽:过程哲学的"事件流" = 控制论的"反馈回路";prehension = 比较器(摄持历史 + 调整未来)。
- ✅ 与 N3 认知科学视角他洽:工作记忆 = 过程哲学的"actual occasion 的暂时稳定化";元认知 = 现象学的"反思意识"(从 ready-to-hand 退到 present-at-hand 的元层次)。
- ⚠️ 与 N1 软件工程视角有张力:软件工程假设"边界稳定"(前端-后端 ABI),但过程哲学说"边界是过程化的"(边界在事件流中持续生成)。这个张力指向"契约的动态性"——见启发性问题 2。

### 续洽
- ✅ V0-V5 可被哲学视角解释:V1 TDD 门禁 = 让"测试失败"从不可见的 ready-to-hand 故障变为可见的 present-at-hand 信号;V2 compaction = prehension 的选择性;V3 skill allowlist = 控制哪些工具"上手";V4 loop 渐进加载 = 事件流的动态构成;V5 subagent = 事件流嵌套。
- ✅ human "rick 深入 agent 内部" = 从"使用工具"到"塑造工具"——从 ready-to-hand 的使用者转为 present-at-hand 的设计者。

## 独特偏见

1. **偏见:过度哲学化**。现象学/过程哲学是高度抽象的理论,应用于工程实践容易"听起来深刻但难以操作"。具体决策(如选方案 A 还是 C)难以从哲学直接推导。
2. **偏见:反结构倾向**。过程哲学反对静态实体,但软件架构需要稳定的结构(接口契约/数据格式)。过度强调"过程"可能弱化对"结构稳定性"的重视。
3. **偏见:个体体验假设**。现象学的 ready-to-hand 是**第一人称**体验,但 rick-pi 系统的工具"上手"是**第三人称**的(agent 的"体验"不可直接观察)。把现象学应用于 AI agent 有 anthropomorphism 风险。
4. **偏见:实用主义短视**。实用主义"效果验证"可能让短期效果好但长期技术债高的方案被采纳(如 .pi 并存的妥协)。

## 3 启发性问题

### Q1(信念追问)
**这个视角的核心信念是"工具最好的状态是 ready-to-hand(消失)"。但 human Y11 说 "后续 rick 的功能将逐渐深入到 agent 内部"——这意味着 rick 想**主动让工具 present-at-hand(可见可改)**。这是否与"工具应消失"的信念冲突?迁移的真正目标,是让 pi 成为 ready-to-hand 的(透明运行),还是让 pi 成为 present-at-hand 的(可深度定制)?如果是后者,是否意味着 rick 团队**希望工具不消失**?**

### Q2(前提追问)
**这个视角的前提是"过程哲学比实体哲学更适合理解 agent 系统"。但软件工程的全部基础设施(类型系统/接口契约/数据格式/版本管理)都基于"实体"假设。如果采用过程哲学视角,rick-pi 的"契约"应如何重新理解?是"稳定实体间的协议",还是"事件流中的暂时稳定化"?如果是后者,pi 的 extension event 签名变更(20 天 9 版本)是否不是"破坏契约",而是"过程演化的自然表现"?**

### Q3(反例追问)
**反例:实用主义说"真理 = what works",但 claude code 在过去显然"worked"(rick 已运行多版本)。如果迁移到 pi 后,某些场景下 pi "works less well"(如 compaction 策略不成熟导致长程任务表现下降),实用主义是否要求**回退**到 claude code?这个视角下,如何定义"works"的衡量标准?是"功能等价"(Y9),还是"V0-V5 价值实现"?如果两者冲突,哪个优先?**
