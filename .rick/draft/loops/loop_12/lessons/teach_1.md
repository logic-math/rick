# M1 把 v6 读成一台机器：状态推断 → 内容生成 → 测量 → 推进/倒退

> 本节只做一件事：把你那四句直觉放到同一张图上，看每一句落在哪个位置。图里的实线全部来自 `prompts/sense_loop.md` 协议原文（等级 A，本轮直读可复核）；虚线是我标注的解读——标出来，你就能推翻它。
> 有形收益：学完你手上多两样东西——一张后面七块都能挂上去的图，和一个可复核的清点方法（去协议原文里找判据，而不是听我说）。

## 先接住你的四句（原话）

1. 「输入消息后，他会根据需求和过去这台机器上的 loop 内容知道我的状态」
2. 「也是测量用户到底真的会了，测量标准就只有一个，那其实就是费曼技巧，把概念讲出来，ai 去核实是否符合事实。来判断是否合格」
3. 「测量 和 决策就是不存在的」
4. 「目前只依赖 需求的输入而已」

第 3 句我可以直接拿协议原文核验；第 1、2、4 句需要拆——它们各自对了一半，而错的那一半，恰好都落在同一个位置：这台机器的接口。

## 一 布线图

```text
                          human
                            │ ①需求（mission.md 自己写）
                            │ ②表态 / 修订要求（→ judgment.md）
                            ▼
   ┌──────────── parent（编排者，独占会话上下文）────────────┐
   │                                                          │
   │  状态推断 = 文件状态机：只看「哪个文件缺 / 哪一栏空」      │
   │      读 mission / values / syllabus / judgment /          │
   │         research/* / lessons/*                            │
   │                                                          │
   │  派发选择：本回合派 research，还是直接派 teach            │
   └──────┬──────────────────────────────────┬────────────────┘
          │ 派发（fresh 上下文，不继承历史）   │ 逐字呈现（不改写、不摘要）
          ▼                                  ▲
   ┌─ research（SENSE 第1步）─┐               │
   │ 写 research_N.md          │               │
   │ 追加 values.md 待裁决条   │               │
   └───────────────────────────┘               │
   ┌─ teach（第2-5步 + 全部呈现内容）─┐        │
   │ 写 syllabus.md / lessons/*.md  ──────────┘
   │ 最终回复 = 正文全文             │
   └────────────────────────────────┘
```

四段分别落在哪、由什么文件承载、线通不通：

| 段 | 承载它的东西 | 落盘文件 | 输出去哪 | 线型 |
|---|---|---|---|---|
| 状态推断 | parent 的文件状态机（7 个分支，判据全是「文件缺失」谓词） | mission / values / syllabus / judgment / research / lessons | 决定本回合派发谁 | **实线，但读的是流程状态** |
| 内容生成 | teach（fresh 上下文，正文全文返回） | syllabus.md、lessons/teach_N.md | parent 逐字呈现到你的屏幕 | **实线，全在 AI 侧** |
| 测量 | 三处候选（见二·三） | judgment.md（你的原话） | 不进入任何规则 | **虚线：记录，不断言** |
| 推进/倒退 | 大纲模块序 + 一处回退条款 | syllabus.md | 下一课讲什么 | **实线但开环：按计划，不按测量** |

## 二 逐段：机器在这一段实际读了什么、写了什么

### 1. 状态推断是实线，但它读到的是「流程状态」，不是「能力状态」

协议「文件状态机」的七个分支，逐个看判据：

- 使命缺失 → 面试 human（判据：`mission.md` 不存在或为空）
- 事实材料缺失 → 派 research（判据：`research/` 里没有覆盖主题的 `research_N.md`）
- 价值未裁决 → 阻塞（判据：`values.md` 某条「human 裁决」栏为空）
- 大纲缺失 → 派 teach(syllabus)（判据：`syllabus.md` 不存在或为空）
- 否则 → 教学回合（判据：以上都不缺）
- 大纲变更请求 / 终止考核 → 由 human 触发

**七个分支，没有一个是「human 现在会什么」。** 全部是「文件在不在、栏空不空」。

所以你那句「根据需求和过去这台机器上的 loop 内容知道我的状态」，读到的东西可以清点成三类：

- **你写的**：`mission.md`（需求、目标、起点自述）
- **你的原话**：`values.md` 的裁决栏、`judgment.md`（表态与修订）
- **AI 写的**：`syllabus.md`（teach 的推理）、`research/*.md`（research 的事实）、`lessons/*.md`（teach 的课）

用两个词把这件事切开：机器持有的是**偏好快照**（你要什么、你同意过什么），不是**能力快照**（你能讲出什么、你讲不出什么）。历史文件里没有一处记录后者。

这一点值得你判断，而不是我替你判断：如果你身上「偏好」与「能力」高度一致，历史文件就够用；如果不一致，机器推出来的「你的状态」在第一层就是**自报数据**——它测的是你的立场，不测你的能力。

### 2. 内容生成是实线，且全在 AI 侧

teach 每回合 fresh 上下文，产出正文全文返回，parent 逐字呈现（「不改写、不摘要、不只给路径」）。「输出长」的三处明文来源就在这里：teach 正文必须全文返回 + parent 逐字呈现 + lesson 三硬要求（引注／2-4 启发式追问／荐 primary source）；loop_11 实测 ≈160KB/会话（syllabus 22.7KB + 9 课 131KB）（research_1 Q1，A）。

这一段里你在接收端。生成主体是 teach。

### 3. 测量：三处候选，三处都没接线

- **候选一：每回合的「认知强制」**。协议原文：派发前先请你用自己的话表态（`在你看来，……？`），理由是「避免把 AI 的理解当自己的理解」。注意它的两个属性：**可跳过**（「若 human 本回合已经给了判断，则跳过」）、**不判分**（协议「禁止」清单明文含「无打分」）。它是一次**诱发**，不是一次测量。
- **候选二：考核演练回合（assess）**。存在，但只在终止时触发；而且判「通过与否」的是你（「通过与否由 human 判断，不自动判定收敛」）。
- **候选三：`syllabus.md` 里每块的「验证学会」**。它写得最像判据——但它写给的对象是你，是一道让你自检的题，不是机器每回合读取的信号。

硬事实（你可以自己核）：v6 协议原文里，「强/中/弱」「费曼」「回忆」「复习」「掌握」「阐述」「讲出来」「判据」「验证学会」「推进」「倒退」——**全文出现次数全部为 0**。而 `values.md` 里 V6／V7／V9／V10／V11／V18 都已裁决。

也就是说：你那套测量设计，一条也没有进到 `sense_loop.md`。

### 4. 推进/倒退是实线，但开环

- **推进**：状态机第 5 步原文「按大纲当前模块……产一节课程」——指针挂在 syllabus 的模块序上，由**计划**推动，不由测量触发。
- **倒退**：协议里只有一处——考核演练发现薄弱环节 →「回到教学回合按薄弱处补课」。终止式的一次性回退，不是每回合的决策。
- **但推进/倒退的假设已经藏在内容里了**，只是不叫这个名字：`syllabus.md` 六节每块的「位置理由」就是一份先修假设（M1 建图 → M2 减量 → M3 传感器 → M4 决策规则……）；lesson 的难度序是第二份；parent 每回合「派 research 还是直接派 teach」是第三份；「human 含糊 → 启发式追问」「human 跳转 → 跟随」是第四份。

四份假设，没有一份有名字、有触发条件、有判据，也没有一份被写下来。你把它们叫临场语感，可以说得通；但从图上说，它们确实在做推进/倒退决策——只是决策的证据在派发那一刻的上下文里，而那个上下文下一回合就不存在了（fresh）。

## 三 你那三处张力的正面答复

### ① 「根据需求和过去 loop 内容知道我的状态」——历史是 AI 的账本，不是你的成绩单

「需求」在协议里是**输入**，而且是你自报的输入：`mission.md` 里写着「天天用我很熟」「这些领域基本的概念我是理解的」——这两句本身就是自报。自报可以用，它只是不叫测量。

「过去 loop 内容」在协议里是**AI 侧材料 + 你的表态痕迹**。你的原话确实被记录了（`judgment.md` 逐条原话、`values.md` 裁决栏），这是这台机器做得好的一处——但从语句类型看，你留下的是「同意／这样改／这样裁」，不是「我把某个概念讲了一遍」。前者测立场，后者才测能力。

### ② 「测量标准只有一个：费曼技巧，讲出来 + AI 核实符合事实」

这确实是一个可运行的测量设计，而且成本结构比大多数测评便宜：不需要题库、不需要标定、不需要长表（对照一下代价：CAT/IRT 的收益以「一维 IRT + 已标定题库 + SE 终止」为前提，中等能力＋固定短表时收益≈0，research_3 Q1②，A）。

但它现在的位置是 `values.md` 的一条裁决，不是协议的一步。三处缺口要说清，且它们不是同一个东西：

- **协议缺口**：零处实现（上文那串 0）。
- **效度缺口**：learning-by-teaching g=.27（39 研究）、准备教 .35、教+测 .56、self-explanation g=.40–.70 都是**学习收益**证据；作为**测量工具**的效标效度（信度、与 IRT 估计的一致性、区分度）无系统证据，teach-back 16 项 RCT 中仅 8 项（N=721）真正测了知识获得且方法学受限（research_3 Q1②：A 级收益 / B 级效度缺位）。
- **核实者缺口**：你的判据有一半是「AI 去核实是否符合事实」。核实需要事实在上下文里，而 teach 是 fresh 上下文——它核实的是「当回合 `research_N.md` 里有的那些事实」；超出这个范围的部分，核实退化成模型的记忆，而记忆不是 A 级信源。这正是上下文经济的代价：skill＝注入当前上下文、agent＝独立上下文只回摘要，两种挂载拿到的事实面不同（research_3 Q2，A/B）；而每回合重读约 6 份材料的成本已经写在协议里（research_1 Q1，A）。

这三处缺口不说明这个设计错。它们只说明：设计还没上线，而上线时你必须选一个「核实者从哪拿事实」的方案——这个选择权在你，M7 会正面再遇到它。

### ③ 「测量和决策不存在」+「只依赖需求的输入」

按证据分四类清点，你的判断落在第 1 类；机器真实的状态横跨四类：

| 类别 | 具体项 | 证据 |
|---|---|---|
| **明文接入**（陈述 → 判定 → 改变下一个动作） | 无 | 协议判据类关键词 0 次；「禁止」清单含「无打分」 |
| **明文声明但未接线** | 每回合认知强制；assess 回合；syllabus 的「验证学会」 | 三者都不产生分数、不改变下一课 |
| **隐蔽形式存在** | 模块顺序＝先修假设；lesson 难度序；派发选择；回退条款 | 都在做事，无名字、无触发条件、无记录 |
| **真不存在** | 任何闭环 | — |

所以更精确的一句是：**测量以「诱发」的形式存在，决策以「默认」的形式存在，两者之间没有那根线。** 你说「不存在」的，正是那根线——这个判断我核出来成立。

至于「那根线的缺失，是不是你抱怨的啰嗦与低效的成因」，这里有两个读法，我不替你收敛：

- **读法甲**：接线缺失 → 没有跨回合活状态 → 每回合重读重述 → 冗长与延迟（结构链证据：research_1 Q1，A）。
- **读法乙**：接线缺失只是症状，真因是生成主体错位——系统生成思考、你只生成「同意」，于是效率越高替代越彻底（判断落点：Bastani 2024 无护栏辅导损害无辅助考试，加护栏后损害消失，research_1 Q5，A 期刊·未复验；V4 你已裁「可以维护」）。

两个读法预测的东西不同：读法甲预测「补上状态后会大幅减少重述」，读法乙预测「补上状态后你仍觉得在被替代」。

## 四 这台机器是怎么被造出来的（把协议读成一次思考的产物）

它有一个完整的前半段，和一个断掉的后半段。

**原始问题**：loop_4 那套（S/E/N/S-R/EC 阶段序列 + think/research/exporter 三代理 + 批判门禁重试 ≤5 次 + 逐派发文件 + RFC 产出）跑出来的东西，你的评价是「不够有原创性」（mission 原话）；同时你抱怨输出啰嗦、效率低。

**事实**：旧协议的成本结构（fresh 重读、强制串行、门禁重试、每阶段固定产物）与 SENSE 的真实分工（第 1 步可外包；第 2-5 步可由 AI 代做，但代做的后果是你在消费别人的思考）（research_1 Q1，A）。

**价值**：V1「教学就是认知负荷管理，就是 ZPD……通过这种方法来管理多轮对话的节奏」；V8「一个会话讲透，会话重访是为了跨领域启发」；V11「讲出来可以作为达标判断，但要看讲的内容是否符合事实」；V18「主动判断吧，连续三次不行我觉得就是不行了」。

**知识领域**：认知负荷与专长反转（强相关）；上下文经济（强相关——skill＝注入 vs agent＝独立上下文，research_3 Q2，A/B）；概念整合与去固着（弱相关，留给 M5/M6）。

**视角**：「教学不是交付物，是节奏」——于是协议被重写成教师会话，删掉阶段标签、门禁重试、RFC 产出，改成 mission → research → 价值裁决 → syllabus 确认 → 逐课教学 → 考核 的状态机。

**主要矛盾**：篇幅占满工作记忆、留白为零、生成主体在 AI 侧。

**逆转**：把「完整性」从 AI 的输出搬到你的输出——AI 每回合给一个可判断的靶子 + 最少必要事实 + 一处留白，完整性由你讲出来补齐。

**断点在这里**：这个逆转落进了**内容形态**（syllabus 的结构、lesson 的追问与留白），没落进**状态机**（每回合读什么、写什么、凭什么换下一课）。协议里「谁在生成」的答案变了；「谁在判」的答案没变——因为原来靠的是阶段门禁，门禁一删，判就没了，而没有人给它补一个新位置。删除是对的（门禁重试本身是成本），补位没做。

延续这条断点的代价链：

```text
fresh 上下文 → 没有跨回合的活状态 → 每回合靠重读约 6 份文件重建上下文
            → 重建即重述 → 重述＝你感到的冗长，重读＝你感到的延迟
```

链条第一环与最后一环是 A 级事实（research_1 Q1 明文「fresh 上下文各重读约 6 份 canon/材料」「协议自记单轮 TTFB 可达 8 分钟」；上下文经济 research_3 Q2，A/B），中间两环是我的结构性推理。v6 没有 token/延迟日志，无实测（research_1 Gaps）——所以「哪一段的缺失会同时制造冗长与延迟」这句话，你这回合能拿到的只有结构证据，不是数据。

> **这张图的置信边界**（边注）：① 骨架来自协议原文，A 级，可逐字核；② 「隐蔽假设」四类是我从行为反推的解读，不是原文声明——推翻它的方式很简单：指出原文某处明文写了「测量 → 改变下一课」，图就错一格；③ 「无状态 → 冗长」的中间两环缺实测，只能算结构性理由，不能算证据。

## 五 四个追问

1. 如果明天开一个新会话，只带 `mission.md` 和 `judgment.md` 进去，机器能推出「你在 loop_12 学到了什么、卡在哪」吗？它推不出来的那部分，是缺一个文件，还是缺一类文件永远装不下的东西？
   - 什么会让你改变判断：若你能指出历史文件里某一类条目实际携带了能力信息（不是你的立场，而是你能讲出的内容），这一问作废。
2. 你的判据要 AI「核实是否符合事实」。当你要讲的那个概念恰好不在当回合 `research_N.md` 里，核实者用的是什么？在你看来，这个来源够不够撑起「合格」这个判断？
   - 什么会让你改变判断：若你认定「核实者可以现场检索、不必依赖当回合上下文里的 facts」，那测量就绑上了调研，代价与延迟会换一个位置（M7 见）。
3. 你说推进/倒退不存在。那么「下一课讲 M2、再讲 M3」这个决定是谁做的、依据是什么？如果把它换成随机顺序，第一个会坏掉的是哪一课？
   - 什么会让你改变判断：若你发现模块顺序并不承担先修假设（任意顺序都能学会），那推进/倒退确实不存在，你的判断成立。
4. 「只依赖需求输入」——需求是你自己写的，包括「天天用我很熟」「这些领域基本的概念我是理解的」。如果这句话在某处写错了，这台机器里现在有哪个位置能发现它？
   - 什么会让你改变判断：若你指出协议里某个环节会主动质疑需求（而不是接受需求作为前提），这一问作废。
