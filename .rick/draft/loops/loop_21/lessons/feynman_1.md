## 探针 1｜AlphaEvolve 闭环机制 — 建议状态：边缘

最终对错条目（按子问）：

- ①数据库+proposer IO｜**对（方向）**：「调用 llm 生成代码 diff 并把代码 diff 应用于 code db 成为一个新的分支」——diff 输出命中事实源「proposer 产 SEARCH/REPLACE diff」；「从通过采样器选择一个格子，提取这个格子的描述以及 code 代码，然后随机选择相邻岛的格子，汇总他们的代码作为灵感，构建一段提示词」——prompt=历史解采样命中「prior programs」（「相邻岛」属 FunSearch 谱系措辞，反锚点不判分）。**未命中**：数据库组织判分锚（代码+多维分数+执行输出入库、「最优回浮」、exploration/exploitation 张力）三轮未现。
- ①数据库载体｜**需补事实**：「所有的代码维护在一个关系型数据库中，维护一套元数据信息……包括 code 的 git 地址，版本信息」——2506.13131 未载「关系型数据库」「git 地址」，真伪不可判；细节级不扣分。
- ②评估工程机制｜**对**：第二轮「多级门禁，先用成本低的检查快速校验，成本高的检查后续继续逐级评估，最后用 LLM 兜底」——评估级联 ✓ + LLM 反馈 ✓（「兜底」与事实源「补分或直接淘汰」方向一致）；rubric「任提其二」已满足。并行评估未提（修正②已交付视为已见，无复述）。
- ③多样性存在理由与退化形态｜**对**：「其目的是为了跳过局部最优解」「如果没有多样性机制，搜索行为会退化为纯利用问题，对某个有效方法会一直优化陷入死胡同」——命中「防种群收敛进单一局部最优」与 §4 消融解读（退化为围绕单一初始程序的重复采样）；「纯利用」是对 exploration/exploitation 张力的单边通俗触及，张力本身未显式命名。
- ④双模型分工｜**错→半修正**：第一轮「采样生成优化计划需要更强的模型，但写代码并不需要，这样做可以节约成本，使得进化能够规模化发展」——与事实源冲突（非「计划/写码」任务分工，是吞吐-质量联合：Flash=低延迟高频候选、Pro=偶发高质量跃迁）。第二轮追问 3「pro 的智能更强，产生原创想法的概率更高」仅命中 Pro 半边，Flash 高频候选角色三轮未现。修正③已交付，最终无完整正确复述。
- ④多维分数｜**错**：第一轮「多个指标联合优化同样是将目标视为一种约束，可以启发 LLM 再选择优化方案的时候直接考虑约束目标以提高生成优秀代码的效率」——与事实源多样性论证不符（次要指标高分程序结构相异→回注回浮进 prompt→刺激多样候选→提高命中主指标新颖解概率；非「约束启发」）。第二轮追问 2「当进化不可预测，也就说无法进行优胜劣汰的选择时，进化则成为了一种无序运动，可能强也能弱，变得不可预测」——答非所问且「selection 失效」判断与事实源冲突（分数驱动保留从未失效）。修正①已交付，无复述。

档位理由：会线四锚中稳中「评估机制任二」一锚；数据库组织锚空、④两锚一错一半——正中 rubric 边缘档「部件名单齐全但运转关系或设计理由含糊」。

## 探针 2｜RSI 部件通用概念 — 建议状态：边缘

最终对错条目（按子问）：

- ①harness 定义｜**对**：「harness 是指 除了 LLM 模型之外的一切构建 agent 的基础设置的总称，通常是指agent=llm+harness」——命中概念清单「harness=模型外围系统」。
- ①可编辑部件｜**对**：「典型可编辑的组件有， loop，skill，model，agent 的扩展或插件」——skill 命中 8 类可编辑部件；「sunagent， dag，moeromoy 等等」为笔误例举，不判分。
- ②proposer/verifier 分工｜**对**：「proposer 在 loop 中负责生成解决方案， verifiler 负责检查这个生成的解决方案是否满足目标需求」。
- ②gate/信号分开的理由｜**第一轮边缘→最终对**：第一轮「因为正确性与性能是两个相互依赖但彼此正交的指标，先检查正确性在验证性能，通常成本更低」——只给了级联成本序，且「相互依赖但彼此正交」自相矛盾。第三轮追问 4 补答：「速度快但错误，会导致错误传播出去，逐步呈现性能极度上涨，但最终结果无效的情况。而对于 正确但性能慢的候选，逐步陷入局部最优解，优化停滞。」——命中「性能买不通错误（快但错→错误传播）」与「correct-but-slow 停滞」两条失败模式，rubric 会线理由补齐。最终状态：对。
- ③OOD 缩水｜**缺失（不判对错）**：第一轮明言「OOD 这个概念我不理解」，后续轮次从未作答，按缺失处理。

档位理由：①②两子问达机制级（含第三轮失败模式补答），但 OOD 缩水作为 10 份新材料公共承重语言整题缺失——rubric 会线要求防御手段任一，未满足，判边缘。

## 探针 3｜在线推理 verifier 迁移面 — 建议状态：边缘

最终对错条目（按子问）：

- ①天然 verifier 候选｜**对**：「精度验证 作为 正确性信号，在线延迟或吞吐作为性能信号。 二者是分离的」——gate/信号分离观正确，与探针 2 ②一致。附注：其「如果合一那就是 auc，大规模验证排序模型打分能力……性能越好完成 auc 验证的时间越快」存在 gate/信号混同（把 AUC 验证 wall-clock 当性能信号），修正⑤（AUC 达标与否=gate、跑完验证的 wall-clock=信号）已交付视为已见，无复述。
- ②在线量不可直接用｜**对（机制级）**：「在线指标是端到端的但噪声太大，无法形成明确的反馈路径」方向正确；机制来源在探针 4 作答中补齐（见探针 4 ② 排队论/到达分布），一并计入此题证据。「比如 过于考虑精度误差对性能的影响，使用过高的精度标准错失优化机会」为混杂权衡的正例。
- ③reward-hacking 暴露推演｜**边缘**：第二轮追问 4「缓存高频 query 这种情况，应该需要通过设计证的 benchmark 将其规避，这本身是 benchmark 的测试问题」——识别缓存输出为 benchmark 测试缺陷（reward hacking 形态之一）✓ 方向级；但暴露手段（多 shape 输入/源码审计/独立计时任一）三轮零命中，修正④（新鲜输入/冷缓存/多 shape 方向级线索）已交付，无复述。
- 容差意识｜**边缘→由探针 4 ③ 补齐**：第一轮「没有容差会导致无效进化，无效进化的表现就是，多轮迭代下不会取得明显的性能收益，无法将 token 转换为实际的性能收益」——初答未及累积机制，第二轮起补齐（见探针 4 ③）。

档位理由：会线三要素中候选 verifier ✓、噪声来源机制化 ✓（借道探针 4 作答）、reward-hacking 暴露手段 ✗——2/3，方向正确但关键推演无机制细节，判边缘。

## 探针 4｜性能测量统计可信度 — 建议状态：边缘（四题最弱，①子问近「不会」档）

最终对错条目（按子问）：

- ①+3% 判真协议｜**错（不会档）**：三轮均无统计协议要素（重复测量/方差与显著性/环境控制——锁频、预热、隔离任一，零命中）。第一轮「我会在大规模的 auc 上离线验证他的正确性，然后在部署到线上，以实际流量开实验观察全链路耗时的变化」——是部署验证流程非判真协议；第二轮「可能需要引入 LLM 进行评估，充分的多维度评估」——答非所问（LLM 多维评估不构成吞吐判真的统计依据）；第三轮「系统中先验的假设了，小于 3% 的是噪声，大于 等于 3% 的会通过一个 review agent 专门评估优化过程，确认符合预期，让 LLM判断是否合并」——有噪声阈值意识（边缘信号），但以「阈值+LLM review」代替统计协议。
- ②在线灰度与离线差异｜**对（机制级，本轮亮点）**：「会有不同离线压测和真实流量会受排队论的影响，即单卡 GPU 对于请求的消费能力存在上限，即如果在线请求和离线测试 请求到达时间的分布不遵循相同的分布，那么测试的差异会比较大」——排队论/到达分布/服务能力上限，是题面「流量波动、时段效应、混杂因素」的具体机制化，超出边缘档「只说有噪声」。
- ③0.5% 逐轮接受长期后果｜**对**：第二轮追问 7b「我认为 benchmark 奖励了坏的优化，且这个坏优化被传播出去，造成系统性错判」——命中「噪声在逐轮接受下累积成系统性假阳性（loop 优化噪声而非目标）」；第三轮最简呈现 B 收口一致。
- 价值裁决｜**接受无错**：5 条待裁决均表态接受，无错误价值判断残留；第三轮「错误传播的风险远高于错失最优解的风险」的风险不对称裁决正确。

档位理由：会线两要素中③ ✓、① ✗（零要素）；正中边缘档「说不出协议要素」半句，但累积后果已说出——边缘偏弱，①子问单独看为不会。

## 最简呈现评价

- **呈现 A（AlphaEvolve 闭环）**：「通过进化搜索的方式，产生优化候选，再评估候选是否有所改进，并将有效策略传播出去，逐步增强整个精英池的优化下限，不断探索优化上限的过程。」
  - 命中：闭环骨架（生成→评估→保留→传播）✓；「增强优化下限 / 探索优化上限」是 exploration/exploitation 张力的合格通俗转写 ✓（补上了正文未显式命名的张力，在最简层难得）。
  - 缺差：**定义性部件 LLM proposer 缺席**——不提 LLM 则该句适用于任何进化搜索，而非 AlphaEvolve（其差异化恰在 LLM 产 diff + 程序数据库回浮）；「传播出去」方向对但机制（回注数据库→回浮 prompt）被抽象到不可辨认。判定：**未达「用最简单话语讲清核心机制」水平，差一档**——是「进化搜索通用最简呈现」而非「AlphaEvolve 最简呈现」。
- **呈现 B（0.5% 噪声不接受）**：「噪声范围内的优化，接受的风险是大于收益的，在大规模多轮次迭代的过程中，错误传播的风险远高于错失最优解的风险」
  - 命中：核心价值判断=风险不对称（错误传播累积 vs 错失最优一次性），且点明「大规模多轮次」这一放大条件 ✓。
  - 缺差：轻微——「系统性假阳性/loop 优化噪声而非目标」的机制词未出现，但风险不对称已承载该含义。判定：**达标**。
