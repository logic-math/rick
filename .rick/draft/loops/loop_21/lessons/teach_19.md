## 0｜从你的「只能重跑呗」接入——重跑是整体动作，作废可以是局部判定

昨天的场景（认知强制原话，2026-11-07 01:27）：横评 12 方法×30 基准，跑到第 8 个基准发现前 7 个结果因同一 bug 作废，你答「想不到，如果 bug 影响了实验结论，那只能重跑呗」。

这句直觉里藏着一个假设：**bug 的影响是无边界的**——它污染「实验结论」这个整体，所以补救只能是「重跑」这个整体动作。还原一下：bug 是一段代码，代码有位置。它长在**方法侧**（某个被横评的方法实现错了）、**harness 侧**（执行候选的运行时错了）还是**基准侧**（第 8 个基准的判分代码错了），决定了它污染的是矩阵的哪一片、污染多大一片。把「哪些结果作废」从直觉问题变成**可判定问题**——按影响面精确作废，不是全部作废也不是全部保留——这正是本课主角的第一个机制价值，也是你的 superopt 已经半路走到的位置（events.jsonl 的 append-only+fsync 就是「作废判定有据可依」的证据底座）。§3 展开这条线。

## 1｜定位：元层——前四条路线造方法，它造「比较方法的东西」

回看第 5 课谱系图：路线 1 造代码进化搜索系统，路线 2 造 harness 自进化方法，路线 3 造 serving 优化闭环，路线 4 造训练基建——**每条路线都在产出方法**。FlashRSI（RUC-NLPIR，人大 NLPIR 实验室）站在第五列：它不提新算法，做的是**统一实验基础设施**——官方自述「one experiment interface」：改变 agent 资源（prompt/skill/工具/运行时代码）、跑完整候选、跨任务可比对〔R §①，A〕。一句话：前四条路线是运动员，它是标准化的赛场。

为什么这个定位承重（mission 综述的判据就在这）：R Gaps ③ 指出**路线 2 各方法（Harness²/RRSI/SoL-Pi/Self-Harness/EvolveNet/HarnessDev/Meta-Harness/Dream-RSI）彼此的 head-to-head 对比缺失**——每篇论文各自选基准、各自报分，横向不可比（批评层 Rethinking Harness Evolution 2607.12227 正是打这一点：用单测搜索再用同一公开基准报分，与简单 test-time scaling 不可比）。**FlashRSI 矩阵是路线 2 唯一的统一横评入口**〔R Gaps，A〕——但「入口」不等于「已完成核对」，§5 回来兑现这句限定。

信源纪律（综述引用前必读）：FlashRSI **无同行评审论文**，primary source = 官方文档站 + GitHub 仓库 + HF datasets（R 定 A 级——官方一手且开源可复现，但未经同行评审）。它自己的定位声明也配合这个等级：「横评证据源，而非单一 SOTA 声明」〔R §①，A〕。

## 2｜三元组实验设计：一个实验 = 方法 × harness × benchmark

机制五步（R §①，A）：

```
一个实验（矩阵里的一个 cell）= 方法 × harness × benchmark

  AgentSnapshot（基线快照）
    → 方法在【声明的编辑范围内】提出候选（Worker 编辑 / Target 反馈）
    → 原生 harness（MiniAgent / Claude Code / Codex 之一）执行完整候选
    → benchmark 打分
    → 保留 / 拒绝该 Snapshot
    → 全部证据（配置 / 资源谱系 / 轨迹 / 用量）落一个 run 目录
```

三个维度各自装什么：

- **方法（12 个）**：OPRO／GEPA／EvoPrompt／SkillOpt／ACE／Evo-Harness／AHE／ADAS／DarwinX／Meta-Harness／ModularRSI／RRSI——被横评的改进机制，每个方法带着**声明的编辑范围**（declared scope：它只许改它声明的部件，越界即实验无效）
- **harness（3 个）**：MiniAgent／Claude Code／Codex——执行候选的原生运行时
- **benchmark（30 个套件）**：SearchQA／HotpotQA／Terminal-Bench 等——打分的分布

三个维度叉成三维矩阵（code-fence 缩进表示，行=方法、列=基准、层=harness）：

```
harness = MiniAgent（第 1 层）
  方法 1   ｜基准1 ｜基准2 ｜……｜基准30
  方法 2   ｜……
  ……        （共 12 行 × 30 列）
harness = Claude Code（第 2 层）
  （同构 12 × 30）
harness = Codex（第 3 层）
  （同构 12 × 30）
```

**最反直觉的一手：harness 不是配置，是实验变量。**常规横评的默认做法是固定一个执行环境跑所有方法——harness 是背景。FlashRSI 把它升为维度，理由是机制性的：**同一方法换 harness，结果不同**——一个方法优化的 prompt/工具编排可能恰好吃在某个 harness 的特性上，换个 harness 红利就变（这直接接你第 16 课的推论：harness 表现与执行环境强相关、存在匹配性）。不把 harness 拉进实验设计，「方法 A 优于方法 B」的结论就混着 harness 的单独效应，拆不出来。

这一手你有两件现成的对应物：

- **#18 四元组**（第 14 课你自己定义的）：任务不变性 = 目标/信号/方法/环境。三元组 = 把其中「方法」与「环境（harness）」拆出来当两个独立实验变量，benchmark 承载「目标＋信号」——**FlashRSI 事实上是你四元组的矩阵化**。
- **#21 配对矩阵**（第 16 课你自己的协议）：harness 版本×模型版本二维联合测评——单独效应不可比、必须联合设计。FlashRSI 是同一个思想的放大：方法×harness×benchmark 三维（它把你的「模型」维冻结了，多乘了一个「方法」维）。你加模型维的理由和它加 harness 维的理由是同一个：跨维度的单独效应不可比，除非联合设计。

## 3｜bug 作废的解：bug 有位置，影响面可判定

回到切入锚。三元组设计下，那个在第 8 个基准上现形的 bug 有三个可能的家，各有各的作废面：

- bug 在**基准侧**（第 8 个基准判分代码错）→ 作废 1 列：该基准下所有 方法×harness 的 cell；其余 29 列不受影响
- bug 在**harness 侧**（比如 Claude Code 适配器执行候选时出错）→ 作废 1 层：该 harness 下所有 方法×benchmark 的 cell
- bug 在**方法侧**（某个被横评的方法实现错）→ 作废 1 行：该方法的全部 cell——但要警惕：这个方法在各 cell 里的相对位次影响了你对**其他方法排名**的解读，作废面会顺着排名外溢

「只能重跑」对应 bug 无位置的世界；「按影响面作废」需要两个前提，两个都是工程件：

1. **证据按 cell 独立落盘**。FlashRSI 的 run 目录（配置/资源谱系/轨迹/用量）是 per-cell 证据，不是混在一起的大日志。这是你 events.jsonl 的同族纪律：append-only＋fsync 让事件不可篡改、落盘即持久——**证据的粒度决定作废的粒度**。混装日志里 bug 检出时，你能说的只有「第 8 个基准之前的结果都可能脏」；按 cell 落盘，你能枚举的是「恰好这 N 个 cell 脏」。
2. **每个 cell 的证据可回溯到它的输入**。配置＋资源谱系（这次运行是哪个方法、哪个 harness、哪个基准、哪份快照）让「哪些 cell 被这个 bug 污染」可枚举——第 2 课判真协议的「回溯可答」用在矩阵上就是污染面的边界。

推导留白（费曼件①的预演，你来推）：12×3×30 全矩阵共多少个 cell？三种 bug 各作废多少 cell？哪种最贵？——再进一步：如果你的 events.jsonl 要支撑这种作废判定，每个事件至少要挂上哪几个维度的坐标？缺一个维度会怎样？

（诚实边界：FlashRSI 的 run 目录是它的证据承诺；「bug 检出→按维度作废」是我把它的 cell 化设计与你的作废判定问题接起来的推演，不是它文档里写的操作流程。结构上它给得起，操作手册它没写。）

## 4｜far-OOD 迁移列：把 E1-E5 做成矩阵的一列

第 1 课预告过：RRSI 的存在理由、**FlashRSI 的 far-OOD 迁移列**、批评层的过拟合指控——三处反复踩同一条承重概念。今天兑现中间那处。

你已会的语言（E1-E5）：进化 loop 的选择压力只站在 verifier 所测的分布上——选择器是个体择优器，得不到全局择优器（E3），所以涨分可以是真实的、但绑定训练分布不迁移（E1/E2）。第 1 课结束时这还是「方法各自的病」：每个方法论文自己选 verifier 分布、自己决定测不测 OOD。

FlashRSI 把它基建化：结果矩阵在 near-domain（近域：与进化所用基准同分布的近邻任务）之外**固定加一列 far-OOD**——专门测「方法在训练域外的迁移」〔R §①，A〕。

far-OOD 列防的正是 **E3 选择压力**：只有近域列时，选择压力站在各方法的训练侧，方法可以在自己的分布上各自涨分、各自报喜；far-OOD 列强制 12 个方法被**同一道未见分布的筛子**筛一遍——第 1 课的判别问题「这个增益在未见分布上还存在吗」（E4）从方法论文的自由裁量变成矩阵的固定结构。对比：RRSI 自己报 5 个 OOD 基准最高 +4.3 分，是方法侧自选动作（OOD 集由它选）；FlashRSI far-OOD 列是基建侧固定动作（同一 far 定义下 12 方法可比）。

（R7 边界：R 只核了「含 near-domain 与 far-OOD 迁移列」的结构与 30 基准的域举例，未抄录逐方法分数、也未抄录 30 基准逐个的 near/far 划分——本课不臆造任何具体分数；综述引用须回指官方矩阵。）

## 5｜元层的元问题：横评基建自己也要过判真

给评测基建本身过一遍第 2 课判真协议，三条留痕：

1. **具体分数未抄录**（R7）。官方结果矩阵的结构与域已核，12 方法的逐表分数未下钻。本课全文没给一个具体分数，不是漏——是纪律：分数层引用必须回原始矩阵逐表抄录，不得转引、不得凭印象补。
2. **「合入」≠「已跑」**。项目页自述「此样本跑通设置，分数非研究结论」；30 基准中 Codex 适配器注明「合入不表示 30 项均已真实运行」〔R §①，A〕。矩阵是**结构承诺**，不是**结果承诺**——R Gaps ③ 说它是路线 2 head-to-head 唯一统一入口「但需逐表核对」，兑现的就是这个限定。
3. **口径不互通**。第 8 课你已见过同型问题：fastinfer-bench 的 leaderboard 站点 rolling 现值（660-workloads 口径）与论文 frozen 快照（1,600-workloads 口径）不互通、不可混算。FlashRSI 同样：项目页快照与仓库后续演进是两个口径，引用须锁版本——评测基建自己产出的数字，一样有判真问题。

元层结论（mission 综述的引用姿势）：横评入口的可信度不是天赋的——**评测基建本身也是被评测对象**。它比单篇论文强在可复现性（开源仓库＋HF datasets＋证据落 run 目录），弱在未经社区检验（无同行评审）；A 级（官方一手）≠ 结论已验证。综述里引它的正确姿势：结构可引（三元组设计、far-OOD 列、12 方法覆盖），分数须逐表核对后再引。

## 6｜原创视角（判断权在你）：superopt 的 events.jsonl → 横评矩阵的路径

**a) 从留痕到矩阵，差的一步是什么。**你的 events.jsonl（append-only＋fsync）已经有「不可篡改的事件流」；FlashRSI 的 run 目录有「按 cell 组织的证据」。差的一步是**维度化索引**：每个事件挂上方法×harness×benchmark 的坐标，日志就从流变成可查询矩阵——「方法 M 在 harness H 下的 far-OOD 表现」从一次重跑变成一次查询。你来推：这条路径上，fsync 的保证（落盘即持久）在 bug 检出时刻具体保护了什么？没有它，append-only 日志在什么故障下会骗你？

**b) 美团版 FlashRSI 骨架盘点**（缺口图，判断权在你）：

```
已在件：
  判真协议（第 2 课）——每个数字回溯可答
  五步管线——snapshot→范围内提候选→原生 harness 执行→打分→保留/拒绝＋证据落盘
  #21 配对矩阵——harness×model 联合测评
缺什么（你来列，先自己填再往下对）：
  benchmark 维度——30 基准的美团对应物（自家 workload 库？FIB 式 trace 四件套？）
  方法维度——横评对象集（路线 2 方法？路线 1/3？自家候选与它们的对比？）
  far-OOD 列的「far」——美团场景的未见分布是什么（新时段？新业务线？新硬件？）
  声明的编辑范围——每方法只改声明部件，越界判无效
```

其中「far」的定义是美团版最承重的一格：你的已会锚「按单一时段流量调优的 serving 策略换时段失效」（第 1 课的类比）就是 far-OOD 的美团形态——新时段＝你训练分布之外的 far 列。这一格定了，矩阵其余各格才有方向。
