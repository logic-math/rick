## 0｜从你的配对矩阵切入（认知强制·留答后填）

课前两问，先答再往下读：

- a) 要大规模验证——多环境 × 多数量 roll，每个 cell 都真跑——你先问什么成本？瓶颈落在哪一项？
- b) 两台筛子：评估分数筛选（分数高者留）vs 选择压力筛选（跨环境活下来者留）——直觉上你信哪台？为什么？

（留答后填：a)______ b)______——b 问是本课费曼件②，§4 展开。）

切入锚——你自己的设计（第 16 课设计推演，原创点 #21）：

> 「superopt 要强调 dream 的能力——这个能力必须能够适配模型……如何更好的测评，要将 harness+model 一起考虑进去才行。」

你把 harness 版本 × 模型版本摆成**配对矩阵**。SoL-Pi 做的事，字面上就是这张矩阵的工程化：跨环境（你的环境维度）× 多数量（每个 cell 里的重复 roll）。但矩阵一铺开就撞上 a 问的那个数：**每个 cell 都要真跑，跑就是钱**。乘法爆炸下，瓶颈先不是「测得准不准」（那是第 16 课批评层管的），是「跑不跑得起」。SoL-Pi 的立场一句话：**先让 harness 跑得便宜，矩阵才铺得开**。

## 1｜原创者的原始问题：成本是 scaling 的分母

还原作者当时的思考（R §⑥，A）：

- **原始问题**：不是「harness 怎么变强」，是「**该不该先让 AI 把 AI 变便宜，再谈 scaling RSI**」。注意这是一句规范性问句（价值判断，不是测量结果）——它是整篇工作的地基立场，判断权在读者，§6 归你。
- **事实调研后看见的主要矛盾**：RSI loop 每转一轮，烧的都是 AI 生成的 AI 研究——构造实验要 token，rollout 要 token，读结果要 token。scaling 想要的搜索量与每次实验的单位成本咬死在一起：**单位成本不降，搜索预算加不动**。这正是第 16 课批评层开出的每张处方（预算对照、跨环境验证 benefit）隐含的前提——那些对照实验本身也要花预算。
- **辩证逆转**：把「成本是阻碍」翻成「成本是先决投入对象」——不先优化能力，先优化**做优化的开销**。优化对象不是 harness 的「聪明」，是 harness 每次执行的 **token 流量**。

挂图定位（判语，§5 收拢）：第 16 课三批评递进是能力 → 测量 → 预算；SoL-Pi 补上第四面——**效率**。四面齐：能力（HUINHB：增益在写侧还是读侧）／测量（Rethinking：归因可比）／预算（Value Live：净值账）／效率（SoL-Pi：单位实验成本）。前三面都站在 judge 侧（第 5 课：批评层 judge 进化、自己不进化任何东西）；SoL-Pi 是 evolve 侧把批评层的隐含前提接过来干——**批评层开的每张处方都是实验，便宜是处方可执行的前提**。

## 2｜机制：可扩展 RSI pipeline——构造 → rollout → 压力 → 幸存 → 打包

事实层给满（R §⑥，A）：

```
agent 构造可执行实验
→ 跨环境 harness rollout（多环境 × 多数量）
→ 选择压力筛选
→ 四机制幸存（"Four mechanisms survive selection"）
→ 打包 SoL-Pi（Pi 的 standalone 扩展）
```

五环节各一句：**构造**——agent 自己把「验证什么」写成可执行实验（不是人设计、AI 执行）；**rollout**——多环境 × 多数量的大规模真跑，核心方法论即在此：**没有量就没有筛选压力**；**压力**——筛的标准不是某个 verifier 的分数，是「在多少个环境、多少次 roll 里活下来」；**幸存**——四机制（下表，A，原文命名照抄；机制内部怎么改——材料未载，Gaps）：

| 幸存机制 | 字面读（＝ agent loop 的 token 流道） |
|---|---|
| 动作执行 | 发出去的：动作怎么发 |
| 上下文压缩 | 带着走的：上下文怎么压 |
| observation 处理 | 收回来的：工具输出怎么处理 |
| 委托阅读 | 要读的：长材料怎么委托读 |

（右列是**字面读法、非 R 载明**——四个名字恰好覆盖 agent 一圈的 token 流量来源；机制内部实现需 parent 补调研，本课不臆造。）

**打包**：幸存机制打成一个 standalone 的 Pi 扩展——**可分发的工程产物**，也是下一轮实验的执行环境。

**留存家族一句连（第七次挂位）**：前谱（第 3/7/9/10/11/14 课）留存物四形态——工件（程序数据库种群／Booster Pack）、知识文档（骨架库／GEAK KB）、参照工件（ForgeKernel 密封件）、harness 部件（Harness² 外环）；SoL-Pi 添**第五种留存形态——行为机制**：留存的不是任何「物」，是被环境反复筛掉对手之后稳定幸存的行为方式。工件是「做出来的」，机制是「活下来的」。

## 3｜数字：性能持平、流量近半、成本 1/3（51 任务 EdgeBench）

事实层给满（R §⑥，A）：

| 对比锚（51 任务 EdgeBench） | 性能 | token 流量 | API 成本 | 每小时省钱 |
|---|---|---|---|---|
| SoL-Pi vs Pi | 持平（原文：GPT-5.6 Sol、Opus 5 下） | −44.7~49.0% | ≈ −1/3 | $4.36-5.71 |
| vs 原生 Codex/Claude Code harness | — | — | — | $8.75-13.50 |

读法（解读非 R 原文）：「性能持平」不是免责声明，是成本主张的另一半——**省的必须是从冗余里省的，不是从能力里省的**。用第 16 课的链语言读：四机制写进 harness 是 updating；EdgeBench 上分数不掉、token 掉近半是 benefit——它把 benefit 的度量从分数换成**成本**，能力持平正是「红利没有从能力侧漏出」的证据。

三个留白（你来推）：

- **流道账**：token 流量降 44.7~49.0%，API 成本只降约 1/3——为什么不按比例？候选：价格结构非均匀（缓存价／长上下文阶梯价／输入输出差价）；或成本里有不随 token 线性的固定项。你押哪个？
- **区间不重叠**：对比原生 Codex/Claude Code 省 $8.75-13.50/小时，对比 Pi 只省 $4.36-5.71——两个区间不搭界。这说明 Pi 本身相对原生 harness 已经处在什么位置？
- **乘法题**：SoL-Pi 便宜约 1/3 之后，同样预算下你的 #21 配对矩阵能多铺多少个 cell？（提示：省下来的每一美元直接换搜索量——rollout 的数量维度是乘得动的那一维。）

## 4｜两种筛选哲学：分数筛 vs 存活筛（费曼件②核心）

对照你自己的两块地基——MAP-Elites 分数驱动（第 3 课）与 E3 选择压力（第 1 课）：

| | 评估分数筛选 | 选择压力筛选 |
|---|---|---|
| 你已见过的形态 | 程序数据库回浮（第 3 课）；RRSI critic | SoL-Pi 大规模 roll |
| 谁决定留谁 | verifier 打的分 | 跨环境 × 数量的存活 |
| 依赖什么 | verifier 的设计质量 | 环境谱的多样性 |
| 病灶（你的已会锚） | OOD 缩水（E3：压力只来自 verifier 所测分布；任务特有模式与通用改进在分数眼里无差别） | 压力只来自**所 roll 环境的分布**——E3 换了压力源，没换结构 |
| 产物可解释性 | 分数可归因（哪个编辑抬了几分） | 幸存者式——只知道活了，说不太清为什么活 |

核心差别一句话：**分数筛把「好」交给 verifier 的定义，存活筛把「好」交给环境的多样性**——前者先要一个可信的判分器（第 6 课危机三篇管的就是这个），后者先要一张够宽的环境谱。

但你的 E3 不要放过它（本课的反例位）：选择压力筛选**没有逃出 E3，只是换了压力源**——如果 roll 的环境谱窄（都在同一族任务上），筛出的「幸存机制」可能只是那族环境的特有模式。EdgeBench 51 任务是它的检查集，但 51 个任务是宽是窄、有没有 far-OOD 检查——材料未载。你来推防御：要卡死 E3 的环境版，roll 的环境谱该满足什么条件？（提示：第 19 课 FlashRSI 的 near/far-OOD 迁移列就是这类检查的标准件。）

**可解释性代价**（局限三条之首，§5 展开）：四机制是「筛出来的幸存者」，不是「设计出来的方案」——你能复现它活下来了，讲不清它为什么活。与第 3 课程序数据库正相反：分数筛的产物每个都带归因标签（哪个 diff 抬了几分），存活筛的产物只带存活记录。**便宜、皮实、难解释**——一套取舍，不是免费午餐。

## 5｜局限、四面定位与你的四个原创点接口

局限三条，事实层如实给（R §⑥，A）：

1. **机制是「幸存者」式经验产物**——可解释性有限（§4 已拆）；
2. **评测限 EdgeBench 51 任务**——基准域未知（材料未载），泛化半径不可外推；
3. **目标是效率不是能力上限**——它不回答「harness 能多强」，只回答「同样强能多便宜」。

四面定位＋judgment 接口（判语）：能力／测量／预算／效率四面里，SoL-Pi 是唯一正面做效率的；它把批评层的隐含前提（对照实验要花钱）变成优化对象——**judge 侧开的处方，evolve 侧先把药钱降下来**。dense feedback 三性质（第 7 课）里「廉价及时」原是反馈的性质，SoL-Pi 把**廉价从反馈性质升级为 loop 本身的优化对象**。

你的四个原创点，各一句接口（不替你展开，素材归第 21 课提案）：

- **#13 采样器自改进**：你的「估计质量该是自改进维度」与 SoL-Pi 同构对偶——你让采样器更**准**，它让执行更**便宜**，都是对「改进机制本身」再改进；
- **#16 三分类**：SoL-Pi 的搜索落在你的「退火进化」支，但存活证据不是适应度分数，是跨环境存活率——分数与存活是两种证据观；
- **#18 四元组**：目标/信号/方法/环境——SoL-Pi 把「信号」从分数换成成本、把「环境」从单一基准换成多环境谱，你的四元组换两个分量就得到本课；
- **#21 配对矩阵**：大规模 roll 是配对矩阵的执行引擎——cell 数乘法爆炸时，便宜是矩阵铺得开的先决条件（§3 乘法题）。

## 6｜原创视角（判断权在你）：美团 RSI 的成本-收益核算表

SoL-Pi 的账本单位是 API $（实验室账）；美团在线推理的账本单位是**卡时**——你的主场。把你第 10 课的 Amdahl 优先分（`pct_gpu_time × achievable_speedup`）升一层，给 RSI loop 每轮记账：

| 成本项（单位：卡时/轮） | 对应什么 |
|---|---|
| proposer 推理 | 构造实验／提候选的模型侧开销 |
| rollout 执行 | 环境 × 数量的真跑——乘法爆炸的主项 |
| 评测/对照 | 第 16 课处方——预算对照、跨环境验证，都要真跑 |

（表是空架——每个 cell 的数和权重归你填；填完先吃哪个 cell，就是你自己的优先分公式。）

**判断题（规范层，无标准答案）**：SoL-Pi 押「先便宜再 scaling」。正方：便宜是矩阵、对照组、多环境验证的共同前提，卡时省下的每一分都直接换搜索量。反方：能力窗口期优先——对手在 scaling 时你先磨便宜，磨完窗口没了。美团的 RSI 该先投哪头？注意一个域差：你账本里的「让 AI 便宜」对应物不是 API 打折，是量化／小模型分工／缓存／蒸馏到自家模型——**便宜化在你的域里另有实现面**，判断顺序前先把它列出来。
