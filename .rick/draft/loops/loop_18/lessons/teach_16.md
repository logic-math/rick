## 1｜解耦手术：拆掉的那条箭头

被批评的默认假设只有一条箭头：

```
基座任务能力强 → harness 自进化效果好（一条箭头，两种能力被焊在一起）
```

路线 2 的预算决策全骑在这条箭头上：evolver 要不要上旗舰、执行侧要不要为 harness 演进让路，默认的都是「基座越强，自进化越赚」。HUINHB〔A：arXiv 2605.30621，EMNLP 2026 main（aclanthology 2026.emnlp-main.2326，Minhua Lin 等，Penn State/UCSC/Amazon 等；代码 A-EVO-Lab/a-evolve）〕的手术：把一条箭头拆成两条独立的链——

```
updating 链（写侧）：执行证据 → evolver 产出 → 持久 harness 更新（写进部件）
benefit  链（读侧）：下次执行 → 唤起相关 harness 件 → 忠实遵循 → 吃到红利
```

两个能力各自独立测量、各有失败面。benefit 链不是开关，是三道串联的门：**更新落盘／相关件被唤起／唤起了被忠实遵循**——任何一道断，红利为零。

现在看两刀的关系——本课核心对撞，spark_1 差异 1 的正面展开：

| | 兑现链通 | 兑现链断 |
|---|---|---|
| **判断对** | 理想格：进化真有效 | **HUINHB 隔离的格**：更新真好、红利为零 |
| **判断错** | 你的第 1 课主格：OOD 缩水（特化候选分数真涨、被传播） | 坏候选选了也没兑现（快速死掉，无人抱怨） |

你的框架切**行**（判断对错——选择器结构性误差），HUINHB 切**列**（兑现通断）——正交。你的防御清单（独立任务集、正则化、因果隔离）全在修判断行；而判断对×兑现断那一格——更新是真的好的、灰度是真过的——任何判断侧修复都照不到，你自己说破了：「失败发生在选择之后，任何独立验证集都照不到」。spark_1 说你的框架覆盖其中两格；本课要做的是把第三格（判断对×兑现断）从 infra 类比升格为 agent 域实证。

## 2｜发现一：updating 对基座能力是「平」的

事实层给满〔A：2605.30621〕：不同能力档位的模型产出的 harness 更新，带来惊人相似的增益——**Qwen3.5-9B 的更新 ≈ Claude Opus 4.6 的更新收益**；跨档 gap ≤3.1 分（二手注：数字为 R 转述层级，未回指原文核对，引用时须标二手）。

这条「平」砍默认假设的前半截：9B 和顶配旗舰写出的更新一样值钱，写侧就没有「基座更强→自进化越好」——**harness-updating 不吃基座能力**。

实用读法是一张采购表：evolver 端「要不要上旗舰」，论文域答案倾向「不用」。为什么平？论文给的是现象，机制留给你推。两个候选（非论文结论）：

- **候选 a（瓶颈在陈述）**：harness 更新的瓶颈不在模型智力，在「经验可陈述性」——把一次执行里的教训写成下轮可复用的规则，这一步对 9B 和旗舰难度差不多。
- **候选 b（瓶颈在测量）**：不是世界平，是**测量平**——基准对更新质量的分辨力有限，好更新和坏更新在分数上拉不开。

你来推：你押哪个？有没有第三个候选？（记住你的选择——§5 那篇批评正是冲着候选 b 这类「测量平」来的。）

## 3｜发现二：benefit 非单调——弱吃不到、中最多、强反低

读侧的形态完全不同，既不平也不单调〔A：2605.30621〕：

| 基座能力档 | benefit（执行侧吃到的红利） |
|---|---|
| 弱 | 几乎吃不到——两种失败模式 |
| 中 | 吃得最多 |
| 强 | 反低于中档 |

弱档的两种失败模式，正好对应 benefit 链的后两道门〔A〕：

1. **唤不起**：更新落了盘，下次执行根本没把相关 harness 件（skill/memory/工具规则）拉进上下文；
2. **唤起了但不忠实遵循**：件进了上下文，执行照样不照它办。

防一处误认（「两失败模式」你已有一套，别焊错）：第 1 课那套（快但错→gate 拦截；正确但慢→停滞）切的是**候选质量**，verifier 有信号可测；本课这套切的是**兑现链路的断点位置**，verifier 一片绿灯、失败发生在绿灯之后。名字同、切面对象不同。

你的映射正面验一遍（spark_1 已给）：失败模式 1 的 infra 翻译正是你那句「线上流量根本不激活那条路径」——落盘、灰度全过，线上没有请求走到，红利为零。失败模式 2 的 superopt 对应物是什么？§7 留给你配。

填空（benefit 链收口）：一个更新落盘了、下次执行也唤起了——benefit 链的最后一环是______？（一个词，弱档掉进的第二个坑就坑在它。）

强档为什么**反低于**中档——机制同样留白，两个候选（非论文结论）：其一，baseline 已高、更新的边际空间小；其二，强档倾向绕过 harness 自己现推，件唤起了也当参考不当指令。你来推，或给第三个。

两个发现叠成矩阵，就是本课证据的主心骨：

| 基座能力档 | updating（写侧） | benefit（读侧） |
|---|---|---|
| 弱 | 平（≈强档产出） | 几乎为零（两失败模式） |
| 中 | 平 | 最多 |
| 强 | 平 | 反低于中档 |

写侧平＋读侧非单调＝默认假设**两头都断**。费曼硬标准：两轴各举一证据、不许混——举证举错轴等于没学会。

## 4｜建议与自述局限：立场层与事实层分开读

论文自己的规范性建议〔A：2605.30621，但为规范性推论非实证〕：能力预算应投给 task-solving agent 而非 evolver；agent 训练应瞄准 harness 调用与长程指令遵循。

**立场层引用**（这是 values 待裁决 3，你 2026-11-02 已裁决接受）：从两条实证到「该投给谁」隔着一个规范性跳跃——你接受的是这个推论作为立场，不是把它当测量结果背。推论链值得自己走一遍：写侧平 → evolver 端不需要贵模型（9B 级够用）；读侧非单调且中档最多 → 预算该花在把执行侧推到「吃得下红利」的档位与能力上（harness 调用、长程指令遵循——正好是两失败模式的靶点）。两头合起来，才有「投 agent 不投 evolver」。

论文自述局限四条，事实层如实给〔A〕：

- 只覆盖 harness 自进化——权重微调／RL／混合路线不在其内；
- 7 个模型有代表性但非穷举；
- 收益集中在 verifier 友好的 agentic 基准——verifier 不友好的域（开放世界、无 ground-truth）读侧形态未知；
- **持久 harness 有安全问题**：坏经验、危险工具规则、泄漏的数据都可能被写进 harness 持久复用。

最后一条直接接你第 14 课的 guardrails 两层分工（一句连）：superopt 的 guardrails 散在框架层、人写死——恰是对这类风险的防御姿态；Harness² 把 8 类部件全放可编辑面（含 guardrails）是被这条局限点名的极端答案。你的 #9 自指性边界在 harness 域的坐标在此拿到外部背书：**持久复用面越大，坏件的复用半径越大**——被论文点名的安全面，不是设计品味问题。

## 5｜关联批评一：Rethinking Harness Evolution——拆测量

〔A：arXiv 2607.12227〕指控：harness 进化类工作在（单一）测试上搜索，再在**同一公开基准**上报分——这跟简单的 test-time scaling 不可比。

机制展开：搜索预算本身就能在熟悉的基准上买到分数。同一基准既当训练场又当考场，「学到选择器特殊性规律」就会发生（你第 1 课的原创语，这里正好是它在 harness 域的形态）——你分不清报出的增益是「进化产出了更好的 harness」还是「只是把更多预算花在了它身上」。分数是真的、分布也测对了，但**增益的来源认错了**——归因混淆。

放进你的判真语言排序（第 1/2/6 课）：噪声累积＝分数假；OOD 缩水＝分数真、分布错；本篇＝分数真、分布对、**归因错**——第三种测量病。防御不是重跑也不是换分布，是**预算对照**：同样预算花在无进化基线上比一比。用你第 10 课的判真四档（零记载／半配／满配／噪声带）给这类报分定档——没做预算对照的进化增益落在哪档，你定。

回接 §2 的留白：押了候选 b（测量平）的，这里拿到加持——「平」可能不是模型写不出更好的更新，而是基准把好坏差距抹平了。

## 6｜关联批评二：Where Does Harness-Optimization Value Live——拆预算

〔A：arXiv 2609.02889〕两个指控：**收益局部化**（增益集中在局部任务/环境，不是普涨）＋**预算切分陷阱**（WebShop 上各方法打平）。

刀刃在切分陷阱：同一份总预算，切一块给「进化 harness」、余下执行，对比全部直接花在执行/采样上——WebShop 打平意味着进化的**净值**可能是零：你观察到的增益，不过是把预算从执行侧挪走、再以 harness 的形式还回来的循环。所以判断一个 harness 进化方案值不值，分母不是「它涨了多少分」，而是「同样的预算直接执行能涨多少」。

三篇递进收拢（模块 5 批评弧的形状）：

| 批评 | 拆什么 | 一句话 |
|---|---|---|
| HUINHB（2605.30621） | 拆能力 | updating ≠ benefit——两个独立能力 |
| Rethinking（2607.12227） | 拆评测 | 进化增益 vs test-time scaling——归因可比性 |
| Value Live（2609.02889） | 拆预算 | 净值 = 增益 − 同预算无进化基线 |

层次递进：概念 → 测量 → 成本；问题递进：什么在起作用 → 测得对不对 → 值不值。

谱系总判断的坐标〔R §谱系，A/B 综合标注〕：路线 2 的 verifier 是 benchmark 分数，过拟合与评测可信度问题集中于此——批评层三篇全打路线 2，本课是唯一拆到「能力结构」层的。综述一个 harness 自进化工作，「有效/无效+为什么」必须**三关全过**：能力解耦（增益在写侧还是读侧）、测量可比（做了预算对照吗）、预算净值（扣掉基线还剩多少）——只过一关不算数。这就是 mission 考核在本模块要你装上的骨架。

第 17 课接点埋一句不展开：SoL-Pi 的多环境×多数量大规模 rollout，是「跨环境验证 benefit」的一个工程答案——读侧的非单调与局部化都要求便宜的大规模验证。

## 7｜原创视角（判断权在你）：分工、档位与失败模式对应物

三个设计判断，不替你收敛，产出直接进第 21 课提案素材：

**判断一｜evolver 配什么档**：写侧平（9B≈旗舰）是 agent harness 域的事实；迁移到 superopt/kernel 域是类比不是事实。类比题：若 kernel 域写侧同样平，evolver 模型预算该省还是该花？省下来的投哪？

**判断二｜主力执行模型在哪一格**：读侧中档吃红利最多是论文域事实。美团主力模型（吃 harness 红利的一方）在自己域里更接近弱／中／强哪一格？若偏强档，「强反低于中档」对你的 harness 投入预期意味着收紧还是加码？若偏弱档，两失败模式哪个更可能是你的主敌？

**判断三｜失败模式 2 的 superopt 对应物**：失败模式 1 你已配好（线上流量不激活那条路径）。失败模式 2（唤起了但不遵循）的对应物是什么——候选：agent 检索到了 exploit/skill 但执行走样？灰度命中了路径但没走到受益分支？你来配，并且补一刀：**怎么遥测出这个失败**（spark_1 更优替代 B 的「兑现率遥测」正好在这里落地——判定拆两栏：增益栏＋实际激活覆盖率栏）。
