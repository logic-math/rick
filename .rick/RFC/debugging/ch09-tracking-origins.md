# Chapter 9: Tracking Origins — 事实总结

## 核心概念

- **Omniscient debugging（全知调试）**：记录程序完整执行历史，允许在任意时间点查询任意变量的值
- **ODB（Omniscient Debugger）**：Bill Lewis 开发的 Java 全知调试器（2003）
- **Dynamic slicing（动态切片）**：在特定输入的实际执行中，追踪影响某变量的实际执行语句（比静态切片精确）
- **WHYLINE**：支持"Why did X happen?"和"Why didn't X happen?"两类问题的调试工具
- **Execution history（执行历史）**：程序运行过程中所有变量值变化的完整记录
- **Origin tracking（来源追踪）**：给定一个感染值，追溯其来源的过程

## 主要内容

### 9.1 向后推理的困难
给定失败点的一个感染变量，向后找其来源面临的挑战：
- 感染链可能很长（数千步）
- 中间值可能被覆盖
- 控制流分支使追踪复杂化

**静态切片的局限**：切片太大（平均 30% 的代码），需要更精确的动态方法。

### 9.2 Omniscient Debugging / ODB 工具

**核心思想**：录制程序完整执行历史，然后离线分析。
**ODB 工具操作方式**：
- 以"慢速模式"运行程序，记录所有对象字段和局部变量的每次变化
- 录制完成后，可以"时间旅行"到任意执行点
- 支持向后单步、向前单步
- 支持"谁最后写了这个变量？"的查询

**性能代价**：
- 录制时 10x-100x 速度降低
- 内存使用：每百万条指令约 100MB 执行历史
- 三种缓解策略：
  1. 只记录感兴趣的类/方法
  2. 分层录制（先粗粒度，再细粒度重跑）
  3. 离线压缩执行历史

### 9.3 Dynamic Slicing 算法

**与静态切片的精确度对比**（书中数据）：
- 静态切片：平均保留 30% 的程序语句
- 动态切片：平均保留 **5%** 的程序语句（精确 6 倍）

**DynSlice 公式**（书中 Example 9.2）：
- 只包含实际执行路径中的语句
- 只包含对目标变量实际产生影响的赋值（而非所有可能赋值）
- 递归追踪每个影响语句的来源

**计算步骤**（Example 9.2）：
1. 从切片准则出发，找到最后一次对目标变量的实际赋值
2. 将该赋值语句加入切片
3. 对该赋值右侧的每个变量，递归执行步骤1-3
4. 对影响控制流的条件语句，也加入切片

### 9.4 WHYLINE 系统

**两类问题**：
- **"Why did X happen?"**（为什么 X 发生了）：使用**动态切片**，分析实际执行路径
- **"Why didn't X happen?"**（为什么 X 没有发生）：使用**静态切片**，分析所有可能路径

**工作方式**：
- 自动识别程序中所有可问的问题（"程序状态 S 在哪里被设置？"）
- 以问题列表方式呈现给用户
- 用户选择感兴趣的问题
- 工具自动高亮相关代码

### 9.5 追踪感染的通用六步策略
1. 在失败点识别感染变量
2. 找到感染变量的最后一次赋值
3. 判断赋值语句是否正确
4. 若正确：追踪赋值右侧每个变量的来源（递归）
5. 若错误：这里是 defect 位置
6. 若无法判断：设计实验（见 Chapter 6）

## 对四个追问的回答

**1. 「实验报告」vs「解决问题」**
Chapter 9 侧重自动化追踪，无明确"实验报告"概念。执行历史本身是一种极详细的"记录"，服务于问题定位。

**2. 「探针不影响系统状态」**
ODB 的录制模式引入 10x-100x 性能降低，这是显著的干扰。但书中指出 ODB 的录制不改变程序的**逻辑行为**（只影响性能）——对于非时序相关的 bug，录制结果是可信的。对于 Heisenbug，ODB 录制本身可能消除 bug（因为性能变化改变了时序）。

**3. 「学习、设计、验证正交」**
动态切片是"学习"工具（缩小需要检查的范围），设计和验证在 Chapter 6 框架中完成。三者仍是顺序依赖，非正交。

**4. 「理解状态转移是否足以覆盖所有bug」**
全知调试的前提是"可以录制完整执行历史"，但对于：
- 非确定性程序（随机、并发）：录制的历史不一定能在调试时重现
- 超大状态空间：内存不足以存储完整历史
书中承认这些局限，但未声称状态转移理解足以覆盖所有 bug。

## 关键引用

- "Omniscient debugging: the ability to ask any question about the execution history at any point in time."
- "Dynamic slices are on average 5% of the program, compared to 30% for static slices."
- "WHYLINE: Why did this happen? / Why didn't that happen?"
- ODB 性能代价："10x to 100x slowdown during recording"

## 与AI Agent调试的关联

- **AI 版全知调试**：记录 AI Agent 每次工具调用的完整输入/输出序列，相当于 AI 版的执行历史——rick 可以实现此功能
- **"Why did X happen?"**：对 AI Agent 失败，可以问"为什么这一步选择了工具 Y？"——需要 AI 的思考过程被记录
- **动态切片对应**：在 AI Agent 的执行历史中，识别哪些步骤对最终失败"实际产生了影响"——这是 AI 版的动态切片
- **性能代价**：详细记录 AI Agent 执行历史会增加存储和处理开销，对应 ODB 的录制开销
