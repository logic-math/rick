# skill:multi-phase-protocol(多阶段协议设计方法论)

## When to Use

当需要设计 AI agent 的多阶段协作协议(如人机协作思考、复杂任务流程)时使用。具体信号:
- 协议需要 3+ 阶段且阶段间有依赖
- 线性流程无法处理"后续发现颠覆前序判断"的场景
- 需要"批判层"嵌入各阶段(而非独立步骤)
- 需要用系统论描述符分析复杂系统

不适用于:线性流程明确的任务(如 build→test→deploy)、单步决策、无批判需求的执行任务。

## Procedure

### 1. 5 阶段框架设计

```
S ⇄ E ⇄ N ⇄ S-R ⇄ EC
↑                    ↑
└── 跃迁/反向回流 ──┘
```

| 阶段 | 名称 | 核心动作 |
|---|---|---|
| S | 问题确认 | 调研现状+对 human 假设追问,完成现状/期望/差距 |
| E | 视角生成 | 跨领域调研→多视角候选→human 给原创视角 |
| N | 矛盾判断 | N1 矛盾生成(系统描述符)+ N2 主要矛盾判断(三维打分) |
| S-R | 辩证逆转 | "若 X 必然,实现 Y 应当如何?" |
| EC | 良知批判 | human 自判,降维/升维/维持 |

### 2. 关键设计原则

1. **合并优于拆分**:相关阶段合并(S1+S2→S, E1+E2→E),减少阶段数,聚焦深度
2. **批判门禁嵌入**:批判层不作为独立步骤,嵌入各阶段(human 实质性回答后触发)
3. **反向回流机制**:后续阶段发现关键事实可重启前序阶段,携带修改意见,上限可配置
4. **强制约束最重要步骤**:N 必须双追问(N1+N2),N2 无主要矛盾⇒必须 S-R(硬约束)
5. **human 自判最终决策**:EC 阶段无 subagent,AI 只呈现回顾,human 自判跃迁方向
6. **系统论描述符**:5 要素(node/input/output/inner/edge)替代模糊的概念地图
7. **配置化所有阈值**:重试/回流/top-N/min/权重都可配置,适应不同场景

### 3. 反向回流触发条件

1. EC 阶段 human 选择升维/降维 → 回到 S 或 E
2. N/S-R 阶段发现关键事实颠覆前序判断 → 回到 S 或 E
3. human 明确要求重做某阶段

回流规则:携带修改意见重新派发该阶段,该阶段之后判断标记"已失效",上限 N 次(可配置)。

### 4. 系统论描述符(N1 阶段)

| 要素 | 含义 |
|---|---|
| node | 系统组件 |
| input | 系统输入(符号,物质/信息/能量) |
| output | 系统输出(同上) |
| inner | 系统内部协作的 input/output |
| edge | node 之间的协作关系,承载 inner_input/inner_output |

用于推演系统稳态迁移:当前 A → 目标 B 所需控制手段。

### 5. 启发性提问设计

每阶段核心问题必须是启发性,禁止确认性句式:

| 类型 | 示例 |
|---|---|
| 启发性(推荐) | "你内心最确信的是什么?最不确定的是什么?" "什么证据会让你改变判断?" |
| 确认性(禁止) | "是否成立?" "对吗?" "选 A 还是 B?" |

### 6. 配置项设计

所有阈值都应可配置,默认值提供合理起点:
- `max_retries`:批判门禁未通过最大重试(默认 5)
- `sense_max_backflows`:反向回流上限(默认 3)
- `think_top_n`:top-N 假设数(默认 3)
- `think_min_assumptions`:假设最低数量(默认 5)
- 权重 map(信源/打分维度)

## Pitfalls

- **避免线性思维**:5 阶段不是必须按序,允许反向回流
- **避免批判层独立化**:批判门禁嵌入各阶段,不作为独立步骤
- **避免 AI 替 human 决策**:EC 阶段 AI 只呈现回顾,human 自判
- **避免确认性提问**:提问必须启发性,引导 human 深度思考
- **避免阈值硬编码**:所有阈值写入 config,不写死在模板
- **避免测试断言过细**:断言核心关键字,不强约束具体表述(允许 LLM 自由发挥)
- **避免强制 ASCII 绘图**:简报中已有详细描述时,提示词不应强制格式,让 LLM 自由发挥
