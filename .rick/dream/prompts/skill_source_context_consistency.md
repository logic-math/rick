# skill:source-context-consistency（源码与上下文一致性检查）

深度对照项目源码，发现并修正 `.rick/` 上下文中与源码事实不符的内容，确保上下文永远如实反映代码现状。

---

## 触发场景

在 dream 阶段执行一致性审核时使用：源码已重构、函数签名已改、模块已删除，但 `.rick/SPEC.md` 或 `wiki/` 仍描述旧实现。

---

## 执行 SOP

### 1. 加载当前上下文

读取以下文件，提取所有陈述性事实：
- `.rick/SPEC.md`：架构设计、编译与运行方法、控制方法、技能列表等章节
- `.rick/wiki/*.md`：各模块文档中的实现描述、函数签名、流程说明

### 2. 逐条源码验证

对每一条上下文陈述，使用 Read / Grep / Glob 对照实际源码（`internal/`、`cmd/`、`pkg/`）验证：

| 陈述类型 | 验证方法 |
|----------|----------|
| 函数/方法签名 | Grep 对应函数名，Read 实际定义 |
| 模块/目录结构 | Glob 验证路径是否存在 |
| 流程描述 | Read 关键文件，对比流程步骤 |
| 配置项/常量 | Grep 确认定义位置和当前值 |
| 接口/依赖关系 | Grep 调用方，确认依赖仍存在 |

### 3. 分类不一致项

将发现的不一致分为三类：
- **已删除**：上下文描述的函数/模块在源码中已不存在
- **已变更**：签名、行为、路径已改变，描述过时
- **已新增**：源码中有重要实现，上下文完全未提及

### 4. 输出不一致清单

对每项不一致输出：
```
- 文件: .rick/SPEC.md 第 N 行
  描述: "xxx 函数接受两个参数 A 和 B"
  实际: internal/cmd/xxx.go:42 函数已改为接受三个参数 A、B、C
  类型: 已变更
```

### 5. 修复

直接更新 `.rick/SPEC.md` 和 `.rick/wiki/` 中不实的内容：
- **已删除项**：删除对应描述，或标注"已移除"
- **已变更项**：用源码事实替换旧描述
- **已新增项**：在合适位置补充简要说明

## 约束

⚠️ **允许**：Read、Grep、Glob 查阅任意源码；写入 `.rick/SPEC.md`、`.rick/wiki/`
⚠️ **禁止**：修改任何业务源代码（`internal/`、`cmd/`、`pkg/` 等）
