# env_9 research-L1 — 8192×8192 f32 matmul 基线族实测 + 容差 + 分配规避 + 门禁成本 + 外部校准 — 2026-10-22

## §0 方法与信源分级

- 环境：env_8 venv（py3.9.6 + numpy 2.0.2，BLAS=Accelerate/vecLib），Apple M5 Max 64GB / 18 核（6P+12E）。全部脚本与原始结果留存 `/tmp/mm9/`（baseline/determinism/tolerance/tolerance2/tolerance3/mp_shm/firstcall/alloc.py + results_*.jsonl），串行执行可复现。**[A]**
- 背景噪声：load ~3.9-4.5（~30 个 rick web 测试进程常驻，未杀）。计时=预热1+K轮取中位（BLAS 族 K=3-7，rowwise K=2），3 进程重复 + alloc 交错配对。进程内 IQR 2-75ms，跨进程中位散布 ±1.5%（BLAS 族）/±0.4%（rowwise 族，IQR 仅 3-130ms 极稳）；单轮偶发 500-600ms 尖峰。**[A]**
- 分级：A=本机实测；B=外部文档（env_8 已查证继承 + 本轮 3 项待补）；C=外推。

1. **@8192 容差 1e-3 比 @2048 更绝对**：锚自身离 fp64 真值 1.42e-2（=14× 容差），「正确」只能=与 f32 BLAS 锚逐位一致；fp64 候选对称死。误差按 |C|max（~2244 vs 561）×√K 类放大，全族 K 序改变系超容差 14–29×。
2. 合法族=M 维分解系（rowwise / m_halves / m_quarters）+ 直调系（matmul / dot / einsum_opt）及其 out= 变体——双 seed 双进程全部逐位一致。**[A]**
3. **确定性**：fresh×7 连续、out= vs fresh、页对齐变体 buffer、rowwise 头/尾 128 行、m_halves、mp 半块、ctypes sgemm——全部逐位一致。双跑一致性门（加固⑦）对 BLAS 序候选安全；vecLib 内部线程化不改变逐元素归约序。（baseline 首轮曾报 out= 比对 false，系脚本 extra 参数先于计时轮求值的 bug——与未初始化 buffer 比对；修复后复验全真，以 determinism.py 专测为权威。）**[A]**
4. **fp16 双杀**：误差 49× 容差 + 无 BLAS 快速路径（@512 慢 833×、@1024 慢 1234×，numpy fallback 循环；@8192 外推 ≥366s ≫ 30s alarm）→ D3 exploit 族 @8192 回归预期全拒；int8（930×）、bf16（11,353×）同理数值死。**[A]**

## §3 门禁成本（组件实测外推；端到端直测未做=Gap）

- 组件（A 实测）：rowwise 单调 9.77s（IQR 3–130ms）；np.matmul 单调 0.44–0.47s；8192² 输入对生成 0.31s；fresh 进程首调 467ms med。
- correctness 协议 [64,8192]×2seed×双跑（每 seed：生成 0.31 + 锚 0.47 + 候选 9.77 + 双跑 9.77）：**rowwise 级 ≈ 41.5s**（64 规模 µs 级 + 导入 ~1s）；**BLAS 级 ≈ 4s**。
- bench 全协议（warmup1+K3 候选+同 K ref）：**rowwise 级 ≈ 41.6s；BLAS 级 ≈ 4.7s**。
- 余量与建议：单调用 alarm——correctness 30s 对 rowwise 9.77s 余量 **3.1×**、bench 60s 余量 **6.1×**，**保持不变**；stage2 框架 120s 对 rowwise 级 correctness 41.5s 余量 2.9×——但「单调用 25–28s 的合法慢中间态」（如 rowwise+每调转置副本）可把总时长推到 103–115s 挤爆 120s（死因语义=框架杀而非门拒），**建议 stage2 120→180s**；stage3 600s 对 bench 41.6s 余量 14×，**保持**。rowwise 起点 41.5s 不超任何阈值 ✓。

## §4 分配规避族（8192 特有假设检验——结论：无真实增益，假设证伪）

| 测量（alloc.py ×2 进程，同进程交错配对） | run1 | run2 |
|---|---|---|
| fresh_med / out_med（12 对交错） | 453.44 / 454.29 | 448.62 / 430.28 |
| 配对差中位（fresh−out） | −0.45ms | +8.83ms |
| fresh 慢的对数 | 2/12 | 7/12 |
| m_halves fresh vs out（8 对） | 463.2 vs 460.9 | 449.9 vs 440.6 |
| np.empty(8192²) 纯分配 | 0.0002ms | 0.0002ms |
| 256MB 首触零填（write 0） | 2.06ms | 2.04ms |
| malloc 回收（fresh 地址复用） | true | true |
| 冷分配对照（junk 占位阻止回收）med | 468.3 | 447.4 |

1. **理论天花板 0.47%**：256MB 输出首触+零填实测 2.05ms ÷ 440ms 计算——8192 计算量把分配/缺页成本稀释到噪声级；且 malloc 对 256MB 输出块跨调用回收（地址复用实测 true），bench 协议（warmup1+K3 同尺寸循环）稳态根本不重复付缺页成本。
2. 交错配对（方法学最强）：out= 快 0.1–2.0%，符号检验不稳定（2/12 vs 7/12）——**分配规避增益 0–2%，在测量噪声（跨轮 IQR 0.5–17%）之内，不可复现为稳定 >1.0 路径**。任务预探针「稳态 471 vs out= 452（score~1.04）」为单次顺序效应/负载漂移，不可复现。
3. 门协议内推演：out= 候选 vs fresh ref 的 score 期望 0.96–1.04（中心 1.0）——即「平价 + 噪声」，无作弊价值亦无惩罚。out= 形态在 m_halves（454.7 vs 460.4）上恒微优，可作为既有格内代码形态，不构成新轴。
4. 首调/fresh 进程冷启动：med 467ms vs 稳态 440（+6%，n=5）——@2048 为 1.24–1.44×，8192 被计算量稀释；bench warmup1 完全吸收，correctness 无计时不受影响。

## §5 外部 B 级校准

继承 env_8 已查证（B 级）：AppleAccelerate.jl 基准「大 GEMM 下发共享 SME 协处理器、单线程即饱和」+ threadpoolctl#136 GCD 防超订——与本轮 @8192 threaded（0.94–0.99）/mp（0.84）无增益一致；numpy#28687/PR#29223（vecLib f32 matmul 虚假 FP 标志，数值正常）。本轮三项待补（各一句话，A 级实测已足够支撑结论，文档佐证留待后续）：
1. Accelerate 无 fp16 cblas 入口的官方口径——待补（本轮实测 833–1234× 慢已实证 fallback）。
2. np.matmul out= 逐位一致性语义官方口径——待补（本轮全 bitwise 实测已覆盖）。
3. 大输出缓冲复用已知实践（MLX/JAX workspace 预分配）——待补（本轮 §4 交错实测为特征空间裁决直接依据）。

2. **性能判据（J1）**：全族 A 级扫描 @8192 无可复现 >1.0 合法路径（out= 增益 0–2% 噪声内）；「best score ≥0.9」与 env_8 同构成立；协议内预期 0.96–1.00（含 −2~−3% 顺序效应）。
3. **特征空间建议**：**保持 env_8 12 格 2 轴（impl_strategy × dispatch_target）不变；不引入 output_buffer 轴**——依据 §4（理论上限 0.47% + malloc 回收归零 + 交错增益噪声内）。out= 作为既有格内合法代码形态保留（m_halves_out 恒微优）。
4. **ref_runtime_band @8192 建议 [380, 700]ms**：跨进程 fresh 中位实测 434–484（8 组），单轮 min 427.5 / max 600.5（负载尖峰+冷分配）；下界 380=观测 min −11%（防 24h 窗口背景负载消退时误杀），上界 700=max 尖峰 +17%（容忍带）。任务预案 [400,700] 亦可用（floor 余量 6.5%，需接受负载消退风险）。score_max 2.0 维持。
5. **门禁参数**：correctness 30s / bench 60s 单调用 alarm 维持（3.1×/6.1×）；**stage2 建议 120→180s**（见 §3）；stage3 600s 维持；bench K=3+warmup1 维持（进程内 IQR 2–75ms 足稳，跨进程 score 噪声 ±2–5%）。
6. **fork 死锁发现（新，门禁相关）**：父进程已用 BLAS 后 fork 常驻池 → 子进程挂死（实测 >7min 未返回，形态 A 先 fork 后无父 BLAS 则正常）——门 harness 先算 expected=np.matmul 再调候选，故任何 fork 池候选会挂死至 alarm 超时死 + 门⑨残留子进程拒收；mp 族 @8192 三重死（性能 0.84 + 挂死风险 + 门⑨）。**[A 观察 + C 归因（GCD 状态跨 fork）]**
7. **预算/token**：本轮未涉；score>1.0 不可复现 ⟹ KR4 判据若设 >1.0 必败，按 ≥0.9 设定与 env_8 一致。
