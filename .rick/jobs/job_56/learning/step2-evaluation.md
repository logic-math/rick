# Learning Step 2：轨迹评估（parent 接手产出）

## ① 可前置预防的错误（改进检查顺序）

1. **僵死循环三层误诊（最大弯路 ~6h）**：
   - 前置预防：调度器「零事件+进程活」首次出现时（30min 内）即跑 py-spy/sample 栈 dump（而非纸面推演 2h）；「探针秒级轮转」观察应立即记录探针 etime 分布而非依赖单点采样
   - 根本预防：watchdog 采集脚本加「事件流新鲜度」确定性字段（seq 增速）——sub agent 只判读不推断（已记入待办）
2. **research --cell 缺失（214 份占位才发现）**：
   - 前置预防：新 env 资产部署时对每个 skill 薄入口跑 --help + 一次真实调用冒烟（参数协议即时验证）——gen_env 验收清单应加「skill 调用冒烟」
3. **OKR 缺位（12 项跑偏提案后才补）**：
   - 前置预防：gen_env 构建产物验收含「okr 要素非空」检查（env.json schema 校验）
4. **e2e fixture 失配（多处 pre-existing 失败占满测试收尾时间）**：
   - 前置预防：每次改动 superopt 后即时跑全量（而非攒批后遇 pre-existing 逐个溯源）；ci 层面每日全量基线

## ② 冗余工具调用

1. 僵死循环排查期间多次重复「grep 事件流 + ps 子进程」循环（~15 轮纸面推演）——应一次性写采集脚本循环观察
2. 多 wrapper 混战期间 3 次「pkill+start 撞锁」重试——restart 手柄加彻底清理前每次都要手工清理（修复前）

## ③ 最大弯路的具体改进建议

**弯路 1：僵死循环 6h** → 建议：super-watchdog skill 增补「停滞栈 dump」步骤（30min 零事件 → 自动 sample + py-spy dump 到 learning 素材），sub agent 不做纸面根因推演
**弯路 2：模型下线应急**（cache_opt 下线 → 手工探活 3 模型 + 手工切换）→ 建议：watchdog 差距③ playbook 已有（本次走通了），固化到 skill 的「模型隔离」节（备选链探活 + --switch-to 的完整命令序列——已在 skill 里，本次实战验证一遍）

## ④ 轨迹效率总评

- 四阶段总耗时 ~4 天（重构 1.5 天 + 96h 运行期[并行] + 收官/learning 0.5 天）——运行期与重构并行是 job_56 的架构收益（run 在改代码的间隙持续进化）
- 24 项提案「批准→实施→部署→验证」链平均 1-2h/批（批合并部署——#41 原子批模式有效）
- 最大教训：**观测确定性优先于推理**（三层误诊的每一层都是「数据不足时先推演」——采集脚本给确定性数据才是正道）
